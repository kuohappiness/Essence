## D-214 上線後的路線

位置照第二步 B 合併之後（[D-213](../decisions.md#d-213-任務與討論稿放進-docs外掛專用的放外掛的-docs)）。現在的路線見[文件存放規則](README.md#一件事從點子到完成的路線)。

```text
點子
 │ 記下來
 ▼
backlog〈待處理〉 ……………… 短點子、待決問題、技術債
 │ 需要展開；backlog 這一項搬到〈已轉出〉，加一行「→ plans/A」
 ▼
docs/plans/A.md ……………… 還在規畫的細節；開頭寫「來自 backlog」
 │ 要做決定
 ▼
討論 ………………………………… 一次問一題、附建議、和「不做」比較
 │ 重大的：docs/Claude Codex Discussion/ 的討論稿，Claude 與 Codex 輪流，一致才交給使用者
 │ 使用者明確同意
 ▼
decisions.md（D-ID）……… 寫「來自」「修改 D-xxx」，一句話與主題寫在條目裡；plans/A 加一行「→ D-xxx」
 │ 同步規範文件（現行規則所在）；索引、往前的鏈、「現行寫在哪」由工具算
 │ 可以交付實作
 ▼
docs/tasks/<任務>.md ……… 規格與驗收；開頭寫「來自 D-xxx」
 │ 實作 → L1 自查 → 高風險的 L2（獨立查核）→ 合併
 ▼
入口的狀態行改「已合併｜完成：一句話」→ 工具把狀態板那一列移到〈已完成〉；progress-map 改符號
（狀態板的狀態、下一步、等誰也由工具從入口讀出來；白板的「最近定案」由工具從決策索引產生）
```

每一站只寫兩種連結：自己的「來自」、上一站的「→ 下一站」，都只寫一次。可以拆分、合併、跳站、退回。讀入口文件只讀上面那一節：backlog 的〈待處理〉、roadmap 的狀態板。

## 已談定

使用者 2026-11-19 同意，已寫成 [D-214](../decisions.md#d-214-工作流程一件事一個現在位置反方向由工具算)。

1. **建一份「工作流程」規範文件**，當這條路線唯一的現行版本：每類文件一段，寫用途、什麼時候進來、狀態值、終點。architecture §9 只留放在哪個資料夾，plans/README 改成連過去，決定只記為什麼。
2. **每件事同一時間只有一個現在的位置**：它走到的最下游那一份。一件事可以拆分、合併、跳站、退回，像 git 的分支。
3. **連結只寫一次**：新的一站寫「來自 X」，上一站加一行「→ 下一站（日期）」；之後不再改。往更下游走時，上游不用同步更新，沿著箭頭一站站找。往前的「後續見」由工具從「來自」反推，不手寫。
4. **入口文件分上下兩部分**：backlog 上面是「待處理」，轉出的搬到下面的「已轉出」，不刪（舊連結不壞、原意與來源留著；backlog 原本的〈已定案對照〉併進來）。roadmap 的順序是狀態板 → 等觸發點 → 已完成。工作流程規範寫明 AI 只讀上面那一節（先找標題的行號，只讀那一段）。等觸發點的留在 roadmap、放在狀態板後面，不退回 backlog。
5. **寫一條決定變輕**（一般從約 6 個檔降到 2～3 個）：一句話與主題寫在條目裡，索引由工具產生，不再改 `decisions-index.mjs` 的對照表；不再手改舊決定的狀態行，新條目寫「修改 D-xxx」，工具反推；決定不再列進 roadmap 的「已完成」，「已完成」只記做完的工作，也不再搬去封存。
6. **白板分兩塊**：「已完成」只列做完的工作；「最近定案」由工具從決策索引自動產生，欄位是日期、決定、現在在哪（照第 3 點的箭頭算；新規則上線前只顯示日期和一句話）。「已完成」改由工具產生，見下面〈狀態寫在兩個地方〉。
7. **舊的不改**：已有的 213 條決定、任務、討論稿照舊；工具同時認舊的狀態行和新的寫法。
8. **模型分工與查核放進給其他專案的初始架構**：寫成角色（規劃者、實作者、獨立查核者）、什麼時候查核、查核分級，高風險範圍由各專案自己填；不寫模型名稱與 Codex 指令。
9. **狀態板加文件檢查，不設字數上限**：「等誰」只收使用者、Claude、Codex、實機、「—」；填的是條件（例如「新教材」）就擋下，提示移到〈等觸發點〉；「狀態」寫已合併或做完的也擋下，提示移到〈已完成〉。檢查是 commit 時跑的程式，不花 token；只清一次不夠（10-27 清過，20 天後長回 3 倍）。狀態板改由工具產生後，這兩條改成檢查入口的狀態行格式，見〈狀態寫在兩個地方〉。
10. **查 D-ID 預設只印一層**：本條全文，直接修改它的決定只印「決定」那一段，更深的只列編號與一句話；`--deep` 保留現在全印的行為。實測 D-117 現在一次印約 3.9 萬字。
11. **「現行寫在哪」由工具從規範文件反推，決定不加這一行**：規範文件寫規則時本來就註明 D-ID，213 條裡 192 條（90%）已被 AGENTS.md、product、architecture、syntax、question-types、`docs/agents`、card-rules、ai-models、skill、外掛的 AGENTS.md 引用（2026-11-19 實測）。查詢工具輸出「現行寫在：檔案〈標題〉」；沒被引用的顯示「沒有規範文件引用」（多是一次性的動作，或決定本身就是規則）。新舊決定同一種方式，不會錯亂；規則搬家時出處跟著搬。比較過的做法：每條新決定手寫一行「現行：」，舊的沒有、新舊不一致，規則搬家時會過時。
12. **新舊寫法用編號劃界**：新規則上線後寫的第一條決定起，用「來自」「修改 D-xxx」的寫法；之前的看狀態行。工作流程規範寫明分界的編號；查詢工具兩種都認、輸出同一種格式，AI 讀工具的輸出，不自己分辨。
