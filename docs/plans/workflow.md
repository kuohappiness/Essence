## 已談定

使用者 2026-11-19 同意；全部談完再寫成 D-ID。

1. **建一份「工作流程」規範文件**，當這條路線唯一的現行版本：每類文件一段，寫用途、什麼時候進來、狀態值、終點。architecture §9 只留放在哪個資料夾，plans/README 改成連過去，決定只記為什麼。
2. **每件事同一時間只有一個現在的位置**：它走到的最下游那一份。一件事可以拆分、合併、跳站、退回，像 git 的分支。
3. **連結只寫一次**：新的一站寫「來自 X」，上一站加一行「→ 下一站（日期）」；之後不再改。往更下游走時，上游不用同步更新，沿著箭頭一站站找。往前的「後續見」由工具從「來自」反推，不手寫。
4. **入口文件分上下兩部分**：backlog 上面是「待處理」，轉出的搬到下面的「已轉出」，不刪（舊連結不壞、原意與來源留著；backlog 原本的〈已定案對照〉併進來）。roadmap 的順序是狀態板 → 等觸發點 → 已完成。工作流程規範寫明 AI 只讀上面那一節（先找標題的行號，只讀那一段）。等觸發點的留在 roadmap、放在狀態板後面，不退回 backlog。
5. **寫一條決定變輕**（一般從約 6 個檔降到 2～3 個）：一句話與主題寫在條目裡，索引由工具產生，不再改 `decisions-index.mjs` 的對照表；不再手改舊決定的狀態行，新條目寫「修改 D-xxx」，工具反推；決定不再列進 roadmap 的「已完成」，「已完成」只記做完的工作，也不再搬去封存。
6. **白板分兩塊**：「已完成」只列做完的工作；「最近定案」由工具從決策索引自動產生，欄位是日期、決定、現在在哪（照第 3 點的箭頭算；新規則上線前只顯示日期和一句話）。
7. **舊的不改**：已有的 213 條決定、任務、討論稿照舊；工具同時認舊的狀態行和新的寫法。
8. **模型分工與查核放進給其他專案的初始架構**：寫成角色（規劃者、實作者、獨立查核者）、什麼時候查核、查核分級，高風險範圍由各專案自己填；不寫模型名稱與 Codex 指令。
9. **狀態板加文件檢查，不設字數上限**：「等誰」只收使用者、Claude、Codex、實機、「—」；填的是條件（例如「新教材」）就擋下，提示移到〈等觸發點〉；「狀態」寫已合併或做完的也擋下，提示移到〈已完成〉。檢查是 commit 時跑的程式，不花 token；只清一次不夠（10-27 清過，20 天後長回 3 倍）。
10. **查 D-ID 預設只印一層**：本條全文，直接修改它的決定只印「決定」那一段，更深的只列編號與一句話；`--deep` 保留現在全印的行為。實測 D-117 現在一次印約 3.9 萬字。
