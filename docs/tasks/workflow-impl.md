### 2. 入口的狀態行

格式（D-217 第 2 點）：標題下第一個非空行，一般段落（不在引用框裡）：

```text
狀態：<狀態值>｜下一步：<一句>｜等誰：<值>
狀態：已合併｜完成：<一句>｜等誰：—
```

- 狀態值：規劃中、討論中、實作中、待審、待實機、等觸發點、已合併、已結案（可以接「 → 」與 D-ID 或連結）、暫停（原因）。暫停一定要有全形括號的原因。
- 等誰：使用者、Claude、Codex、實機、—；可以用「、」接好幾個（例如「Claude、Codex」），「—」只能單獨用。
- 已合併、已結案：第二欄是「完成：」、等誰是「—」。其他狀態第二欄是「下一步：」；等觸發點的等誰是「—」，觸發點寫在下一步。
- 一行剛好三欄，用全形「｜」分；欄裡不能再有「｜」（改用「，」）。第二欄不能空。
- 經過寫在內文（例如〈結果〉、〈進度〉），不寫在狀態行。

解析放在 `tools/status-line.ts`，文件檢查與產生狀態板的工具共用。文件檢查（`check-docs.ts`）：

- 任何追蹤的 Markdown，狀態行以「狀態：」開頭又含「｜下一步：」「｜完成：」或「｜等誰：」其中之一，就當成新格式嚴格檢查；錯了報「檔案:行號  狀態：  原因」。
- 狀態板與〈等觸發點〉的入口一定要是新格式（由〈5〉的工具查）。
- 舊的自由寫法照舊（D-217 第 6 點）：舊任務、討論稿、plans 不改；原本的「標題下第一行要有狀態」與 D-195 的〈結果〉檢查照舊，「狀態：已合併｜完成：…」仍算結束。

### 3. 「來自」與「→ 下一站」

- **來自**：新的一站在第一個二級標題之前寫一行 `來自：<連結或文字>`，一份只有一行；新決定寫在狀態行的一段「來自 …」。
- **→ 下一站**：上一站加一行 `→ <連結>（YYYY-MM-DD）`（段落或清單項目的開頭；backlog 的項目寫在項目的下一行）。之後不再改。
- 文件檢查：
  - 「→」那一行一定要有連結與日期。
  - 「→」指到的檔（或決定）要有「來自」連回這一份；指到決定時看那條決定狀態行的「來自」。
  - 「來自」連到的是一站（任務、討論稿、plans、backlog）時，那一站要有「→」連回來；連到決定的不用（決定的「現在在哪」由工具算，D-214 第 5 點不改舊決定）。
  - backlog〈待處理〉裡不能有「→」：轉出的項目搬到〈已轉出〉（D-214 第 4 點）。
- 往前的「後續見」與「現在在哪」由工具算：「→」與反過來的「來自」都算一條邊，沿邊走到最下游。

### 4. 入口文件分區（D-214 第 4 點）

- **backlog**（最上層、Cards、Capture、Mindboard 四份）：二級標題只有 `## 待處理`、`## 已轉出` 兩個，依這個順序；原本的二級標題降成三級（更深的跟著降一級），GitHub 的錨點只看文字，舊連結不壞。〈已定案對照〉〈歷史索引〉、只剩一行轉往別處的節、「和 Cards 有關、留在 Cards 的項目」放〈已轉出〉；其餘放〈待處理〉。
- **roadmap**（最上層與每個外掛的）：`## 現在在哪裡`、`## 等觸發點`、`## 已完成` 三節依這個順序，中間可以有別的節（Cards 的〈路線圖〉〈未來準備開發〉）。〈已完成〉不設列數上限、不再搬去封存（D-214 第 5 點、D-215 第 3 點）：拿掉文件檢查的 10 列上限。
- 文件檢查擋：少了節、順序不對、backlog 多了別的二級標題。

### 5. 狀態板、〈等觸發點〉與〈已完成〉由工具產生：`tools/roadmap-sync.ts`

每份 roadmap 自己處理（〈等觸發點〉〈已完成〉放哪一份見 Q1，下面照建議的 A 寫）：

- **狀態板**（〈現在在哪裡〉的表，欄照舊 `工作｜狀態｜下一步｜等誰｜入口`，白板照舊讀得到）：手寫的只有工作與入口；入口一格剛好一個連到 Markdown 檔的連結，那份檔的狀態行要是新格式。工具把狀態、下一步、等誰寫進去；下一步裡的相對連結改成以 roadmap 為基準。
- **〈等觸發點〉**（表：`工作｜觸發點｜入口`）：入口的狀態是等觸發點的列，工具從狀態板搬過來，觸發點取「下一步」。入口沒有新格式狀態行的（只有 D-ID、試用紀錄）手寫，工具不動。入口的狀態改成別的，工具搬回狀態板。
- **〈已完成〉**（表：`日期｜工作`）：入口的狀態是已合併或已結案的列，工具從狀態板（或〈等觸發點〉）移到〈已完成〉表的最上面，寫成 `<工作>：<完成>（<狀態值>，[入口](…)）`；日期取收尾的 commit：入口檔在工作樹或暫存區有沒 commit 的修改就是今天（台北時間），否則是最後一個改到它的 commit 的日期。已有的列不動。
- **執行**：`node tools/roadmap-sync.ts` 改寫 roadmap；`--check` 只比對、不寫，不一致就印「檔案:行號  原因  執行 node tools/roadmap-sync.ts」並 exit 1；`--staged` 讀暫存區；`--root` 給測試。冪等：跑兩次第二次不改任何字。
- **接線**：`tools/hooks.ts` 的 `SHARED_CHECKS` 加 `roadmap-sync.ts --check --staged`；`tools` 的 `npm run check` 加 `npm run roadmap-sync -- --check`（CI 的 shared job 跑這個）。

### 7. 決策查詢工具：`tools/decisions.ts`、`tools/decisions-index.ts`

- 搬進 `tools/`（有型別、lint、測試）；`experiments/tools/decisions-index.mjs` 留一行轉呼叫，舊文件與 AGENTS.md 寫的指令照樣能用。
- **新決定的寫法**（從分界編號起，D-214 第 10 點；暫定 D-218，合併前再看 `origin/main` 的最大號加一）：

  ```markdown
  ## D-xxx 名稱

  ✅ YYYY-MM-DD｜來自 [plans/A](plans/A.md)｜修改 [D-yyy](#…)（第 n 點）、補充 [D-zzz](#…)｜取代 [D-www](#…)

  主題：<索引的主題之一>｜一句話：<一句>

  適用：全部
  ```

  狀態行用「｜」分段，「來自」「修改」「補充」「取代」開頭的段裡的 D-ID 是這條的上游。
- **索引由工具產生**（D-214 第 5 點）：分界之後的主題與一句話讀條目；之前的主題讀凍結的對照表（不再新增）、一句話照舊從現有索引保留。主題不是既有的 8 個之一、少了一句話就報錯、不寫檔。
- **後續見與已取代**：舊決定照舊從自己的狀態行往後找；再加上分界之後的決定在「修改／補充／來自」提到它（→ 後續見）、在「取代」提到它（→ 已取代）。舊決定的狀態行不用再手改。
- **查詢預設只印一層**（D-214 第 8 點）：
  - 查的那條：全文，加一行「現行寫在：…」。
  - 直接修改或取代它的：標題、狀態行與〈決定〉那一段。
  - 更深的：`D-xxx 名稱：一句話` 一行。
  - `--deep`：照現在的行為全印。
- **現行寫在哪**（D-214 第 9 點）：掃規範文件裡提到這個 D-ID 的地方，列「檔案〈最近的標題〉」，同一份檔的標題接在一起；沒有就印「沒有規範文件引用」。規範文件：`AGENTS.md` 與外掛的 `AGENTS.md`；最上層與外掛的 `docs/product.md`、`docs/architecture.md`；`docs/transcript.md`；外掛的 `docs/syntax.md`、`docs/question-types.md`、`docs/card-rules/*.md`（`trials.md` 是紀錄，不算）；`docs/agents/*.md`（不含 `token-usage` 的紀錄）；`docs/ai-models.md`；`.claude/skills/` 底下的 `.md`（`.agents/skills` 是副本，不重複算）。
- 「現在在哪」（白板用）：從決定沿〈3〉的邊走到最下游。

### 8. `section` 工具：`tools/section.ts`

- `node tools/section.ts <檔案> <標題>`：印那一節（到下一個同級或更高的標題為止），開頭一行 `<檔案>:<起>-<迄>`。標題先比完全相同的純文字，沒有再比包含；對到好幾個時列出候選與行號、exit 1；沒對到列出全部標題。
- `node tools/section.ts <檔案>`：列出每個標題的行號、層級與字數，給 AI 挑。
- 程式碼區塊裡的 `#` 不算標題。
