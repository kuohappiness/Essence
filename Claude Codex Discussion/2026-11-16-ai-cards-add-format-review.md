「加一段」可以沿用寫回及重讀保護，但沒有涵蓋所有合法筆記。實測兩處 `出處` 或欄位有接續行會被擋，單獨的標題或否定段也會被拒絕。合併行 `出處：p.8｜類型：例` 可安全加一段，三段以上拆行後仍保留 `類型`。再呼叫一次加 `p.8` 會真的寫出 `p.8、p.8`，所以呼叫端還要去重。去重不能只比原字，已寫的 `p.15` 可能接在別的單元後面。加到同單元時，`own: true` 可把本篇段排到既有的外單元段之前。

**修法。** 先依來源篇屬性讀整欄及相依段，再按已解析的歸屬轉寫。來源本地的頁、圖或 `本單元` 轉成來源絕對單元，相依的位置與學期一起處理，完整的外單元照原義，直接連結保持直接連結。若 D-027 要補上本課歸屬，獨立補單元一段，避免順帶把連結或無法辨認的文字改成有效歸屬。否定、看不懂、來源屬性不足又有本地位置、小表單拒寫時，規格應明定保留該項並告知原因。只有來源沒有可搬的出處且屬於可辨識的同科教材，才適用「異單元補來源單元」的空欄分支。

同單元須比**科目、年級學期與單元編號**，沿用有效屬性及 `termKey`／`codeKey`。探針中 `２－１`、`2–1`、`2之1` 相同，`L01`、`L1` 不同。`第2章第1節` 是出處讀法的別名，由 `chapterAlias` 處理，不能拿未切分的屬性字串代替編號。syntax §2-5 的短寫出處只找同科，跨科不能用這種短寫表示來源。即使同科同單元，若兩篇的「材料」不同，本地 `p.15` 也可能打開另一本書。沒有相同材料可佐證時，保留來源或改用已核對的教材連結。

**真實路徑。** 正常的跨課加題就會走到。頁碼列表是合法手寫格式。跨科、材料不同及否定段須碰到各自的輸入條件。影響是教材連錯、漏連，或把題目算進錯誤考試範圍。[任務 §3-3](../tasks/ai-cards-add.md#3-3-出處跨學期補年級學期與單元)、[syntax §2-5](../docs/syntax.md#2-5-出處)、`sources.ts:38–66, 327–518`、`source-edit.ts:70–79, 281–333, 375–389`。

### F2｜「目的地已有每一題」不足以刪除來源

**規格，解析已重現，寫入時序為推斷。** `問 :: 答` 搭配 `詳解：甲` 或 `詳解：乙` 都是 `e537d76e`；把答案改成 `改答` 變成 `bc6b6ea7`。依 §3-2、§4，前者會跳過有不同詳解的題，再刪掉待加入項，後者若發生在目的地寫成後、來源尚在時，重按會再加回原題。只有記憶錨點、圖片或備註的項目是 syntax §2-9 允許的，沒有題目時「每一題已存在」無條件成立。現行 `confirmed` 探針也接受了只有相同 ID 與名稱、缺了新題的檔案，回 `0`，即成功核對且新增 ID 數為零。

**修法。** 指紋照 syntax §2-8 用於辨認出題內容。刪除前須核對搬移的完整預期，包括題型、題幹、答案、背面補充、共用補充的完整子樹、合併後的備註／錯題補強及出處歸屬。撞到同指紋但有不同內容時，規格先指定如何保留雙方或留項提示。若無任何完成紀錄，重試無法分辨上次沒寫成和上次寫成後被家長改掉。可選擇保留來源、回報衝突，或沿用最小版「先保存足以核對的資料」的做法，記錄來源身分與原文、目的地 ID 及採用內容，重開後依實際狀況接續。單靠指紋不得承諾重按一定完成且不重複。

**真實路徑。** 補詳解或只補錨點是正常用法。重開前需曾寫成目的地、沒清掉來源，家長又在這段期間編輯，才會觸發加回舊題。[任務 §3-2、§4](../tasks/ai-cards-add.md#4-多檔寫入的順序與中斷要格式查核)、[syntax §2-8](../docs/syntax.md#2-8-題目指紋)、`parse.ts:112–118, 310–336`、`state/ids.ts:67–81`。

### F3｜補齊跨檔的核對、續作與兩台裝置的界線

**規範與設計，依現行 API 與規格推斷。** `saved` 表示已寫進磁碟、目前無法核對，停用時也會回這個結果。無改字的 `unchanged` 同樣沒有證明該項已採用。目的地在第 2、3 步之間刪除或改名，依原路徑找不到須保留來源。若按 ID 找到新路徑，也須重查唯一、版本及完整內容。讀取與來源寫入之間仍有空隙。現行 `edit`／`fillFile` 計畫回呼同步，只能核對回呼拿到的來源與先前讀到的目的地版本，不能在裡面等另一篇的讀取。同一篇同時是來源與目的地時，有條件用單篇交易一起完成，應明定且只用一次最新文字。

**修法。** 同一次加入經 state 協調成一份工作，實際寫入前各自重查門檻，對同機並行、pending、開著且尚未落盤的編輯器及 close 明定行為。第 2 步要有符合 F2 的核對結果，`saved`、讀不到、逾時或結果不明都留項並如實回報。第 3 步在可行的最晚時點核對目的地，來源回呼再確認來源原文及沒有已知的目的地變更。即使現有檔案當下都讀到，本機佇列也沒有跨裝置保障。例如 A、B 對同一目的地各加不同題，A 讀回並清來源後，iCloud 若採用 B 的版本，A 的題和待搬項都可能消失。舊來源版本回流時，目的地完整保留才可安全再清一次，目的地也回流或被改過時須保留並給出可辨識狀態。規格需明訂跨機衝突時如何保有可恢復的來源或搬移紀錄，或收窄保證並經確認接受限制。最小版 §5 以恢復資料與實檔核對續作，遇到「可能曾寫出、現在找不到」會停下。現提案不能沿用其安全結論。

**批次重排。** §4 最後一點與環節 4 結論第 5 條的「批次結束才統一重建、重排」直接相反。現行 `adopt` 會立即重排並通知。每次採用可以維持內部索引及核對所需的最新資料，批次中的畫面、今日份與當前卡何時更新仍須照結論實作，或先確認允許中途可見、寫明原因與可觀察行為。來源清除成功、部分寫成、停用的批次終點都要明定。

**真實路徑。** 重開、已開啟的目的地、改名或讀不回來是可達路徑。同步造成內容丟失須同一批或不同批次在兩台同時改、再遇到版本覆蓋，頻率待實機驗證。[任務 §4](../tasks/ai-cards-add.md#4-多檔寫入的順序與中斷要格式查核)、[最小版 §5](../tasks/ai-cards-mvp.md#5-存草稿與快照要格式查核)、[環節 4 結論第 5 條](<2026-10-26-plugin-architecture.md#環節-4-的結論待-codex-確認下面四點>)、`writes.ts:152–174, 333–407, 433–455`、`state/index.ts:546–558, 828–839`。

### F4｜候選應插在解析出的根項邊界，刪框也要保住區塊邊界

**規格，已重現。** 以 `parseDeck(..., { layout: true })` 的半開 `end` 且保留外部空行，探針在普通段落、表格、程式圍欄、其他引言框、一般清單、下個標題及檔尾前插入，舊題指紋不變，候選留在最後一個目標的分組。若按最後一個清單行找位置，`問 :: 答\n一般筆記` 原指紋 `9da10ea4` 會改成 `e537d76e`，普通文字改黏到候選的題尾。數字根項 `100. 舊` 的正文從第 5 欄縮排開始（0 起算），候選根項若也跟著縮排 5 欄，就成了共用補充，原本的新題沒有獨立目標。縮排應以展開 Tab 的相對欄位與清單符號寬度處理。只移除理由那一行也不夠。理由放在兩題之間且下面有子項目時，刪掉理由後，子項目在探針中變成前一題的詳解，指紋不會指出這個變更。

`blocksOf` 把連續的 `>` 行視為同一塊，沒留外部空行的第二個 `> [!note]` 不能當獨立框刪。若刪框後消掉最後一個區塊分隔，旁邊的普通段落仍可能成為新接續行。AI 檢查器能切出中斷的引言行，閱讀模式所屬的範圍須等 Obsidian 探針證實。

**修法。** 採用完整根項的解析範圍。無目標時使用完整框前的頂層區塊邊界。候選維持為根項，子項縮排以其清單符號的正文欄為基準。必要時插一個外部空行隔開前後區塊，保留未搬文字、原換行型態與檔尾有無換行。只自動移除沒有子樹的直接一層理由行。理由有附屬內容、框內外邊界有歧義時先保留該項。寫前解析整篇，確認除了要求的新增目標之外，舊目標與題目、欄位、題型及段落歸屬不變。§2 的「最後一個小標題」應寫清楚是**最後一個目標所在的小標題**，末尾若有其他小標題則位置不會在其下。

**真實路徑。** 標準 AI 草稿的典型格式可安全插入。一般筆記、數字清單與巢狀理由須有手改或非典型輸出，普通段落與框相鄰在閱讀模式的實際邊界待驗。[任務 §1、§2](../tasks/ai-cards-add.md#2-候選卡片的加入同一篇要格式查核)、`markdown.ts:104–193`、`parse.ts:380–384`、`check.ts:82–101, 413–420`。

### F5｜第一層分組須保留完整子樹，合併要按目的地的題型驗證

**規格，已重現。** 一行 `出處：p.9｜類型：例｜備註：乙` 同時寫三欄，整行搬會把來源類型帶進目的地，整行捨棄又會漏出處、備註。題目底下的 `出處：p.10` 照樣算在目標出處，記憶錨點底下的 `狀態：暫停` 也會讓目標暫停。若把原樣子樹當純題目或背面補充搬過去，會跳過前綴規則或改掉目的地狀態。第一層圖片應仍為共用補充。多行答案及單行答案的題下詳解都要跟著題的完整範圍。欄位判定優先，題目再用解析器同一規則，不能只掃 `::`／`==`，行內程式碼或公式可能含這些符號。

**已重現的題型變化。** 比較卡加一個普通問答會退成原題型並提示 `pick-mixed`，加一個答案為組內別字的比較句會出現 `pick-answer-invalid` 並停出。全詩排序加第二個填空會失去排序，英文句子排序混進普通問答也會失去排序。接句與排序的填空須保住題下與共用記憶錨點的順序和語意。整個目標若只在名稱的接續段落有 `::`，現行讀成隱含題、ID 為 null。把題加進這類根項只會成為背面補充。單一題目的合法接續行則是題的原文，插在它前面會改題。寫錯的目標有時仍有有效 ID 並計入 D-157，不能因此視為可加入的目的地。

**修法。** 版面切割與語意分類須一致。以可保真的欄位解析拆複合行、處理巢狀欄位，再移各題與補充的完整範圍。沒有可驗證的保真搬法、`ok: false`、隱含題、改掉既有題型或引入題型錯誤時留項並提示。合併前後用目的地的科目、名稱和整組題驗證，既有題與補充應保留，來源擱在框內的題型檢查沒有目的地上下文。

**真實路徑。** 複合欄、答案多行、比較句、接句與排序是合法格式。圖片、巢狀欄位和手改目的地會走到對應分支。[任務 §3-1～3-2](../tasks/ai-cards-add.md#3-1-目的地)、[syntax §2-3、§2-4](../docs/syntax.md#2-3-學習目標)、`parse.ts:209–357, 358–383`、`check.ts:406–447`。

### F6｜候選 ID 轉為排程身分，舊外掛的版本標記要同次落盤

**規格，解析已重現，現有寫入路徑為靜態核對。** 候選在框內時，`blockIds` 有收、`parseDeck` 不會列為目標。複製出與既有目標相同的 ID，在框中沒報重複，移出後出現 `duplicate-id`，D-157 會讓兩者停出。標準 MVP 草稿先配好候選 ID，正常採用沿用 ID，快照也使用同一個 ID。手貼無 ID、行中／行尾歧義、既有目標的同 ID、或同一批候選重複，都應明定採用前核對方式。歧義和已進入排程的碰撞照 D-134／D-157 保留待處理，不可自行改配後當成採用了原候選。D-042 快照維持原樣。以後做比對時要辨認採用前後的位置，原本在框內的候選仍留在框內或被搬出，都不能只用本文的 `parseDeck` 推成「家長刪掉」或「家長新增」。

比較卡另有相容性缺口。草稿 `piece.pick` 只取本文目標，只有框內有比較卡時可無 `需要版本`。一旦搬入本文須同次補最低標記（D-191，目前比較卡 `0.4.0`），無法加標記就留項，以免舊版讀成一般翻面開始排程。範例 `changeStatus` 的寫回不會補這個標記。其他題型的既有相容性照 syntax §2-3。

加進已有的項目，第一行連結的 `#^ID` 或原文開頭 ID 只供定位。題尾的 `^zzz234` 在探針中不成為目標 ID、不進題目指紋，但仍是 Obsidian 區塊 ID 且算占用。若目的地已有同名區塊 ID，搬過去可能使區塊連結歧義。規格應說明逐一檢查所有搬移行的區塊 ID。核對目的地中原有的區塊 ID、同批搬入的 ID，以及跨篇後原筆記的區塊連結是否仍能使用。發現衝突或已知引用無法保留時先留項，避免靜默改號或留下斷連結。

### F7｜原文 ID 留著可能表示 MVP 核對未通過

| 題型 | 題目與答案應如何取 |
|---|---|
| 問答、多行答案 | 用 `Prompt.question` 作題幹，包括合法的續行。答案用 `Prompt.answer`，保留多行順序與語意；已有行內答案時其子項目是 `extras`，異詳解走完整內容衝突。中翻英、文法打字可用解析後接受的答案集合辨識只改列舉順序或分隔的情況，但仍保留原文差異供人工核對。 |
| 普通填空 | 依 `Prompt.blanks` 的位置保留一格一個占位，保留整個 `Prompt.text` 的可見文字及續行，依格比答案。探針中的行內程式碼 `\`==literal==\`` 沒有被解析成空格，用正規式遮整行會誤擋有不同可見提示的正常題。 |
| 比較卡 | 用比較句的 `question`（含空格所在位置）及該目標的固定答案，仍須通過比較組驗證。相同句子在兩個不同字的目標之間不用互相比；改成同組別字的答案仍留項。 |
| 接句、全詩排序 | 接句用實際顯示的另一句、缺的是哪一半，以及解析出的詩文脈絡。全詩排序用標題、可見文脈與可選詩句，答案是正確順序；另保留既有的單題約束。探針中 `==甲==，==乙==。` 與 `==乙==，==甲==。` 都能解析，兩者選項相同、順序不同，應留項。 |
| 英文句子排序 | 以解析出的題頭、片段位置與實際選項判定題幹可識別的內容，答案比片段正確次序。**已重現**：同一 `語序 排序` 目標可同時有 `==I== ==read== ==books==.` 與 `==We== ==write== ==notes==.`，遮完都是三格加句點，但字鍵完全不同。照 §3-2 字面會誤擋正常加題。若有片段改動而無法區分重試與新題，明列為限制或留項待確認。 |

**影響與真實路徑。** 問答只改答案確實能擋，英文排序的多題、填空的續行或行內格式都是可達輸入。接句、全詩排序即使沒命中防呆，第二題仍須由題型不變的核對拒絕。§7 應逐型定下正常加題、答案改動、詳解改動及同前半句不同可見提示的預期。[任務 §3-2](../tasks/ai-cards-add.md#3-2-搬過去的東西放哪)、`parse.ts:310–369`、`markdown.ts:97–102`、`question-types.ts:118–147, 152–202, 243–293`。

### 第二輪 R4｜§2、§5 新增項目：疑似重複須能在原稿與連結化草稿辨認

**字面差異已驗，誤加入為規格推斷。** 原文 `理由：可能重複 abc234｜待看` 符合 §2 的純 ID 格式，核對成功後依 §5 會成 `理由：可能重複 [[舊卡組#^abc234|原目標]]｜待看`，用 §2 的字面規則即失配。現行 `check` 對兩種都當成理由，但仍把所有根項算進五項；目前沒有加入程式可操作。摺起時，「全部加入」若按最新 Markdown 掃描而把連結式當一般候選，就會把疑似重複整項搬出框，家長沒檢查便另立新目標。只測展開時的按鈕標籤看不出這條路。

**修正條件。** 三處共用解讀名稱下第一個直接理由節點的規則，明訂原稿 ID、已存草稿的區塊連結及未核對而保留原文三種情況；框與舊 ID 要分開辨識，連結內的 `|` 只是別名。對以「可能重複」開頭但 ID、分隔或理由不全的內容，檢查時報出格式，加入時留項待單獨檢查，不能默認為一般候選。明訂半形冒號等和既有理由容錯的關係。確認畫面與實際寫入都從最新文字取同一組一般候選；確認到套用間有項別或原文變動時重取確認，不能趁此把原先排除的項目搬入。只剩疑似重複時，框與項目原文保留。新語法載入舊版仍在引言框內，D-089 第 8 條維持不排程；相容驗收應查實際留下的文字與目標數。

**影響與真實路徑。** 一次正常的 ID 核對成功和按預設摺起框的「全部加入」就可走到，是功能主路徑。[任務 §2、§5](../tasks/ai-cards-add.md#5-送給-ai-的已有目標)、[討論稿第一輪結論第 2 點](<2026-11-16-existing-targets-for-ai.md>)、`check.ts:362–372, 413–446`、`draft.ts:163–168, 193–198`。
