分支 `claude/ai-cards-deepen-04562a`。請求基準 `efe50f04b1b9e942a16e7ef41a7697b080213b44`，實際查核 `233d1adcd4e335982528a1063590f1c3e0a1e7c7`，開工時工作樹乾淨。兩者之間只有任務說明更新，§9 四項已選定。下文的章節與行號指實際查核版本。範圍為任務 §1～§7 的決定與格式、§8 的驗收邊界、§9 的已選方案與原列對照，以及發布版讀取行為。

## 必須先改的格式與流程

### R1　快照可套到錯篇，提示基準與最新地圖也可能互相遮蔽

- **看規格推斷｜真實路徑會發生。** 分篇、同名重建、關著 Obsidian 時搬檔、從 A 剪目標到 B，都會遇到。§2-3 只要有一個 ID 交集就採用，A 的連結失效、B 收了 A 唯一記穩的目標時，B 可採到 A 的地圖與基準。同一個 ID 誤複製在兩篇也會兩邊都命中。初次製卡快照的 `對象` 本來就是多篇，本文又是整份回覆，單篇消失時無從用全篇 ID 交集還原原始歸屬。連結解析成功也可能指向替代檔，因現行快照用 basename，路徑重用時會失去身分證據。預期 A 的工作只影響 A，且找不到證據時照首輪。實際可壓掉 B 的提示、送錯地圖，甚至把另一篇的內容當家長刪除。證據見任務 §2-2、§2-3、D-190 第 3～4 點、[publish.ts](../src/core/ai/publish.ts#L74)、[draft.ts](../src/core/ai/draft.ts#L193)。
- **建議。** 舊快照只採有可確認篇關聯的連結，失效或歧義就回首輪，撤掉「任一 ID 交集」自動配對。新寫的對象先沿用 YAML 連結清單，加深固定一項，寫 vault 內明確路徑。若要跨離線搬移或同名重建自動續用，需定既有或新增的穩定篇身分、複製衝突規則與舊資料退路。對舊的分篇快照，只有單元共用的地圖可以共用。列「家長已刪除」之前要核對該篇原有的正式目標、同單元其他篇現在的 ID、仍待採用或已捨棄的項目。未採用的候選、從未屬於本篇的項目和搬去別篇的目標都不能推定是家長刪除，亦應遵守 syntax §6 保留修改原因不明的約定。
- **看規格推斷｜真實路徑常見。** 最新成功工作可能只有補題、無有效地圖，或屬不交 R3 地圖的科目。§2-3 強制兩者同份會讓仍可用的前一份地圖消失。提示用最新有效成功工作，地圖用最新有完整全貌與架構的可歸屬快照，對齊 D-136 補充第 1 點及原討論〈特別 2〉。同時明寫課外所依賴的課內目標要**全部**記穩，範圍是這些前置目標（D-136 第 4 點）。§2-2 的「至少一個」只適合一般加深的新連結，不能套成課外的充分條件。
- **現行格式已重現，選擇結果按規格推斷｜真實路徑會發生。** `時間` 要先驗 ISO 時刻含時區，再比較瞬間。Node 下 `10:00+08:00` 早於同日 `03:00Z`，和 `02:00Z` 同時。單靠 `Date.parse` 還會把 2 月 30 日正規化。現行 `stamp` 同一秒兩次輸出相同，快照同時刻、時鐘偏移與兩台各自生成都要有明確規則。可排序的同時刻用工作識別碼作穩定決勝，寫明兩個工作各自的結果都留著，決勝只決定讀哪份。保留原發布時間與工作識別碼，還原只補回更舊的快照時不會壓過仍在的較新快照或「這次不用」。若較新的快照已消失，只剩還原的舊份，現有格式無法知道曾有較新工作。需明定可恢復退路，別用修改時間、檔名、首次看到檔案的時間補猜。兩台反向完成或晚到的作答也不能拿目前的紀錄回推當初送出的集合。證據見 [prompt.ts](../src/core/ai/prompt.ts#L47)、[publish.ts](../src/core/ai/publish.ts#L219)、[history.ts](../src/core/study/history.ts#L211)、syntax §6。
- **舊值。** 現行發布器固定寫 `工作: 製卡`、`記穩目標: 無（初次製卡）`，實際 YAML 讀回對象是清單。以兩欄一起判讀。這個組合是首輪空集合，`工作: 加深` 加 `無` 是已成功的空集合，`工作: 加深` 加非空字串 ID 清單是已成功的凍結集合。舊稿只寫 `製卡`、`無` 或缺欄、無精確時間、欄位不符的，不能據此宣告已加深。可用地圖和可用提示基準分開驗欄位。識別碼重複而內容不同、同時刻不同識別碼、未來時間和本機 `at` 等於快照時間均要有測試與退路；同一工作重試維持同一識別碼和時間。

### R2　追加可以寫成功卻永遠看不見，恢復時容易重貼或誤發布

- **已重現｜真實路徑會發生，主要是手寫未關圍欄。** 一個未關閉的**頂層** `~~~text` 後空一行，再加新框和候選框，`introBoxes` 找到 0 個候選框，Markdown-it 也沒有渲染引言框。兩個發布版及現行 `parseDeck` 都只有原有的 `abc123`，原目標完整相同。這表示「未排程」成立，但核對字串和 ID 都會漏掉「看不到、加不了」。一般尾端引言、已關圍欄、表格、答案接續行、沒有末尾換行、只有屬性區，現行探針加空白實體行後原目標相同，候選框可找到。清單內未關的小圍欄在退縮排後亦可分開。證據見任務 §3-1、[check.ts](../src/core/ai/check.ts#L93)、[markdown.ts](../src/core/deck/markdown.ts#L104)。
- **建議。** 段落間用真正沒 `>` 的空白行。頂層圍欄未關時擋下寫入，說明先修檔。保留原文空白及換行風格，含 CRLF。提交前驗新批次在解析後的外層可辨認，也驗原正式目標的 ID、題目指紋、群組與欄位不變。屬性區以後要加備註時，原目標行號會合理平移，驗語意即可。引言框裡有巢狀清單或圍欄時，空白行與內容行都須保持框前綴。
- **看規格推斷｜真實路徑會發生。** §3-2 的「仍是前綴」在案例如 `原文 + 家長新段` 成立，無法保證最新檔尾仍可寫。反過來，中間有人改檔就重新組文會覆過原先的語意驗證。重開時按 ID 認已寫入，對只補舊 ID、只寫備註、沒有新內容都沒有識別力。家長在中途加入或刪除一部分時，可能把捨棄的項目重加，或看到 ID 還在就發布一份已缺批次內容的快照。另有快照已寫、只差清除恢復資料的中斷點。兩台各自 `process` 後再同步，規格無從保證兩份都留在同一檔。Obsidian 編輯器未儲存時也可能另有一份待寫舊文字。證據見任務 §3-2、§4-3、[job.ts](../src/core/ai/job.ts#L21)、[publish.ts](../src/core/ai/publish.ts#L125)、[intro-run.ts](../src/obsidian/intro-run.ts#L175)。
- **建議。** 發布前保存工作識別碼、原文雜湊、預定批次證據，以及快照的預定位置與內容雜湊。對 `process` 回呼拿到的最新文字重新驗身分、目的地、編輯器狀態、圍欄及批次完整性。用同一工作記號或可驗的批次證據認領結果，分清未寫、已寫完整、已處理部分、衝突／讀不到、快照已存在且屬自己。衝突或結果不明時保留恢復出口，別盲重貼或發布。明定備註與只補題的識別方式、真正零寫入怎麼成功，以及在已採用／捨棄後如何完成或放棄。把「兩份都留」限在第二次寫入看到第一次時。iCloud 舊版覆回或衝突副本出現時，驗證發現缺批次後的行為，勿用快照反向改寫卡組。快照只建立，同一工作已發布就驗同一內容並清恢復資料。

### R3　待審核要認工作批次，同名框與舊補題不能靠目標 ID 分辨

- **已重現及看規格推斷｜真實路徑會發生，反覆補同一個常錯目標尤常見。** §4-3 只看最新快照與舊目標 ID。舊製卡補題 A 還在，新加深也補 A，採用新補題後仍會被舊 A 擋住。兩次手動加深都只補題，較新的批次採用完而較早的還在，會提早解鎖。補題已落盤但快照未發布／已放棄時，另一台沒有相應快照，也會漏掉。只看框頭會讓空框或家長留字永久顯示待審核。候選是否算該次仍待審也要明定，初次製卡候選不能一概算。預期只算還有可處理項目的加深批次，採用或捨棄後解除，符合 D-194 第 8 點。
- **已重現。** 兩個獨立同名補題框、同目的 ID 而文字不同，`findItem` 可各找到。文字與 ID 都相同就回 `duplicate`。兩框沒有外部空行時，`introBoxes` 只列第一框並標成 `merged`。同檔兩個候選框被生成稿 `check` 報 `candidate-position`，新標題被報 `callout-unknown`。這些是把現有入口直接套到已發布卡組時的落差。證據見 [intro.ts](../src/core/ai/intro.ts#L42)、[check.ts](../src/core/ai/check.ts#L424)、任務 §3-1、§4-3。
- **建議。** 加深框及補題框要能認出所屬工作，且在快照未到、被還原或有多個待審批次時照樣可辨。以可驗的批次身分加框內項目作為加入與待審的依據，並用相同證據支援 R2。明定舊製卡框、加深候選、只有備註、保留文字、全部捨棄的轉移。生成回覆仍先照回覆格式檢查，寫入後用筆記布局的驗證，避免把單份 AI 回覆只能一個候選框的限制套到成品。§3-1 要補「檔尾已經有舊候選」時的布局，否則只追加會違反「候選最後」。可以按批定序並在 syntax 寫明多批可並存，或另定全檔的插入錨點。

### R4　課外出處的舊版讀法及補題合併須先定契約

- **已重現｜真實路徑很常見，因來源得附可查位置。** 現行與 `v0.5.0`、`v0.3.0` 的 `parseDeck` 都保留 `課外：高中課本 p.44`，但 `sourceLinks` 讀成 `block/p44` 加 `before`，`課外：[[教材]]` 讀成筆記連結加 `before`。若在明寫的跨單元後面，`課外：高中課本 p.18` 跟到前一個單元。單寫 `課外：國三上 2-1` 在探針裡是標題，現行和 0.5.0 還標上 `missed`。現行有轉錄稿比對時，`check` 對這些寫法報 `source-unknown`。所以 §6 的舊版「只是文字」不能成立。舊版仍可讀題、但可能連到錯的教材頁或提示寫錯，且課外題在舊排程仍會當原單元。證據見 [sources.ts](../src/core/deck/sources.ts#L323)、[check.ts](../src/core/ai/check.ts#L278)、syntax §2-5、§2-10。只用 `[AI 補充]` 掩蓋課外會失去這次選定的區分，syntax 已定的初製補底層語意也會混掉。
- **建議。** 保留 §9 選定的 `課外：<來源>`，在位置、單元和否定判讀前辨認，定出前綴空白、全半形、空來源、分隔符及引號／網址寫法。前綴內原樣顯示，不產生教材位置，不改寫前後出處既有的單元或連續頁碼語意。與生成檢查、存檔提示、來源按鈕及補題的出處合併一起驗，避免現有合併器補本單元或裁掉課外來源（[existing-sources.ts](../src/core/ai/existing-sources.ts#L111)）。舊版兼容可先驗一種現存解析器能當不透明文字的引用寫法是否夠用。若不能保證，讓 Claude 明列過渡時舊版的實際行為與支援的部署順序，勿把行為寫成相同。
- **看規格推斷｜正常會遇到未同步／改名的連結。** `[[教材#段落|名稱]]` 先以出處筆記解析，連結缺檔、歧義、內容或 cache 未就緒時屬未知。只有確實找到筆記且確定沒有 `來源類型` 才能算補充筆記。空或非標準值但鍵存在，仍算教材，與 [parse.ts](../src/core/deck/parse.ts#L98) 的鍵存在判準一致。每一項都確定是課外才降權，保留明寫的跨單元、教材頁碼、混合來源、先備、AI 補充及無出處原語意。驗材料或 metadata 晚到後重新分類，並重新算範圍與佇列。§7 建議名稱可進 syntax §1，D-152 第 4 點另要求「課本跟學校講義衝突時列備註並請家長確認」，§2-2 要補這句。

### R5　只改 contains 會漏掉課外重學，範圍檔本來以單元為鍵

- **已重現｜真實路徑是考前答錯已採用的課外題。** 即使替身讓 `contains(def456)` 為 false，昨天答錯的課外 `def456` 仍以 `relearn`、80% 排在考試新卡 `abc123` 的 `exam-new`、90% 前面。D-142 第 5 點明定生效時連課外重學也排在範圍內的課本新卡後。正常重學在無生效範圍時仍先出。測試須涵蓋有生效範圍但沒有日期（會排序、不升保持率）、有日期、範圍結束後，以及同組比較卡、每日時間上限和追加練習是否會把課外項目又提到考試卡前。證據見 [plan.ts](../src/core/study/plan.ts#L8)、[plan.ts](../src/core/study/plan.ts#L129)、[state/index.ts](../src/state/index.ts#L655)。

## 其他要補清楚的邊界

### R6　逐篇偏好遇到換檔、時間及多 vault

**看規格推斷｜正常改名可走事件，離線更名與同名重建較少但可發生。** 路徑鍵配 rename 可照規格接受離線改名多提醒一次。A 刪除、同步後 B 先在同一路徑出現、讀時才清理的話，B 會繼承 A 的偏好。等讀不到就清又會把暫時未同步或佔位誤當刪除。對已知 delete 和 rename 要處理鍵及目的地舊值，路徑被重用或身分不明時優先讓新檔照首輪。和快照用同一時間驗證與比較規則。凍結集合較晚時，即使快照被刪仍要尊重；之後成功與本機時間同秒、時鐘被調快、壞 `at` 過濾一筆還是整表、相同鍵同時改名要有明確結果。定出首輪按「這次不用」後下一次用第幾輪最小值以及提示是否寫「又」。現行試作當後續輪，§4-1 與 §4-2 的字面未定一致。讀取驗外層是記錄、每筆 `at` 有效、`ids` 是格式正確且去重的字串 ID，較窄的忽略粒度是壞一篇只忽略那篇。開關沿用 `=== true` 的明確判斷，缺值或壞值預設開。依 vault 儲存是目前慣例，請 Windows 實測兩個 vault 同路徑與重開；基於 [prefs.ts](../src/ui/prefs.ts#L3) 的呼叫無法驗證宿主的隔離行為。

### R7　加入的位置、補題的目的地與備註

- **已重現與規格推斷｜正常手寫的重名小標會發生。** `## A / ### 同名 / ## B / ### 同名` 的兩組正式目標，`parseDeck` 有相同 `section`、不同 `sectionIndex`。§9 選定放同名小標符合 D-100 和 syntax §2-9，但需要保留標題階層或可重驗的插入錨。多個相符且無法區分時先留待審，別挑第一個；已有空標題、祖先標題下只有子節、目的節沒有目標、最後沒標題、§1 讀得懂的目標存在但檔尾僅備註都應明定。新建標題要驗相鄰目標的節與指紋。候選一律檔尾雖較容易實作，會丟掉組別且和這次已選方案相反。證據見 [markdown.ts](../src/core/deck/markdown.ts#L104)、[move.ts](../src/core/ai/move.ts#L84)。

### 四項延後或限制

1. **舊版讀 `課外：`，可記相容限制，前提是逐台更新及重開後才採用新卡。** 核對第一輪對 `v0.5.0` 和 `v0.3.0` 的探針，風險包含錯頁連結、誤提示、提前出課外題，不是純顯示。換版窗口是可預期的路徑，外掛檔已同步也不能證明載入的是新版。現行發布已有逐台重開與驗版本做法，可用於新功能的過渡，不必為此改選格式。若打算支援長期混版，交使用者選相容語法或接受差異，不能以極低機率結案。§6 的「0.5.0 以前」應明列包含 0.5.0。[0.5.0 換版紀錄](../tasks/release-0.5.0.md#結果)
2. **跨裝置的等待貼回可以記，待審不能整項記掉。** D-194 已選本機工作，另一台等待中的狀態天然不可見，只在兩台同時發起才有影響。快照只晚到時，可把已同步卡組的等待窗口列為限制並實測。分開處理同機放棄、快照永不建立、舊批未處理、快照落盤但卡組被同步覆回舊版本等情境，這些會漏待審或遺失結果，見 R2、R3，並非等待幾秒即可解除。
3. **只連非教材筆記，交使用者選是否延至第 3 批。** 第 2 批生成規則要求課外每項用前綴，通常不走純連結。但是手寫 `出處：[[補充筆記]]` 目前已能寫，正常可被選入考試；即使補充筆記不存在於這個使用者的正式 vault，格式仍是 D-152 與 syntax §2-9 已定的 v1 行為。延至第 3 批有依賴上的理由，屬實作範圍選擇。若同意延後，同步寫明暫時仍照課內排，完成條件為已解析且無 `來源類型` 的筆記才算，來源未知與混合來源保守留課內，並重驗考試資格。
4. **額外模擬可記技術債，正確性驗收現在做。** 漏天、積欠、作答率差異、時間上限的分布會改模擬結果，正常使用可遇到，影響的是提示體感與試作結論。既然 1/2 已選、首輪樣本限制也已寫明，試用一個月後補看頻率合理。第 90 百分位的考試首輪時間仍宜補進表（1/2 到第 9 天），避免「所以第 2 天就到」讀成保證。首輪只有一兩個、部分刪除／暫停、較晚的「這次不用」、無內容成功、全部待審解除等有明確預期，仍要在接線時用固定案例驗，不能跟補模擬一起延。
