## 和「不做」比較（D-153）

- **不做會怎樣**：最小版的草稿裡，候選卡片與加進已有的學習目標只能手動處理：候選要自己剪出引言框、拿掉每一行的 `> ` 與「理由」；加進已有的要打開舊卡組、找到那個目標、把題目照縮排貼過去、在出處自己補 `小五上 2-1 p.15`，再回草稿刪掉。一項約 1～2 分鐘、容易錯（縮排錯一層意思就變，`> ` 沒拿乾淨整段不算卡），家長多半就不做：D-027 的「同一個知識再出現就加題」與候選卡片等於沒有。之後的第 2～5 批（加深、錯題補強、補記憶錨點）也都靠這個搬移把結果寫進已有的卡組，不做就全部卡住。
- **做的代價**：閱讀模式的引言框多幾顆按鈕；一個「跨檔寫入」的流程（先寫目的地、再從草稿拿掉），中斷時要靠重按一次接起來；L2。
- **更小的做法**：
  - 只做候選、不做加進已有：同一篇搬移很簡單，但加進已有才是手動最容易錯、也是第 2～5 批都要用的那一條。不夠。
  - 不做按鈕、只做命令「加入這一篇引言框的全部項目」：省了按鈕的掛法，但家長沒辦法只挑幾項，候選卡片本來就是要挑的（D-091）。按鈕的代價小，做。
  - 加進已有不做跨檔，改成把題目複製到剪貼簿、請家長自己貼：還是要找目標、對縮排、補出處，省下的不到一半。不夠。

**第 2 類（延後，記進技術債表）**：見 §7 的表。開放的入口都能走完一條安全的路徑：中斷時重按一次「加入」就接著做完，不會重複、不會丟。

## 1. 按鈕在哪、按的是哪一項

- **哪些引言框**：卡組筆記（`isDeckPath`，轉錄稿不算）裡，標題是「候選卡片」「加進已有的學習目標」的引言框（`[!note]` 與預設摺起的 `[!note]-` 都算；標題的認法和 `src/core/ai/check.ts` 相同，照用不另寫）。對象表（標題 → 怎麼加入）寫成一張表，第 2 批加「加深的學習目標」一列。
- **按鈕**：閱讀模式裡，框裡每一個最上層的項目旁一個「加入」，框的標題列一個「全部加入」；按「全部加入」不會展開或摺起引言框。只在電腦、外掛讀完之後；這一篇需要新版（D-149）或屬性區讀不懂時不放按鈕。
- **找項目**：畫按鈕時記下那一項在那時的原文（每一行去掉引言框的 `> ` 之後的字）與它的身分：候選是名稱行行尾的 ID；加進已有是第一行連結（或原文開頭）的 ID 加上同一個框裡同 ID 的第幾項。按下去時，在這一篇**最新的文字**裡用身分與原文重新找；找不到或原文變了，提示「這一項剛改過，請再按一次」，不寫。
- **平台事實**（code-quality〈寫規格〉；送 L2 前用開發命令在 Windows 版 Obsidian 跑完，iPhone 不用）：

## 2. 候選卡片的加入（同一篇，要格式查核）

- **搬到哪**：卡組本文（引言框外）最後一個學習目標那一整項（含它的子項目）的下一行；本文沒有學習目標時，放在這個引言框的前面。所以候選會在最後一個小標題底下，家長要換位置自己搬。
- **怎麼改**：每一行拿掉引言框的前綴（行首最多 3 個空白、`>`、後面一個空白）；拿掉名稱底下直接一層、以「理由：」或「理由:」開頭的那一行（只拿一行，它底下的子項目照舊留著並往上接）；其他字（名稱、行尾 ID、出處、題目、縮排）不動。縮排的字元照這一篇（引言框外的學習目標用 Tab 就換成 Tab），換法和出處小表單相同（`src/core/deck/source-edit.ts`）。
- **框空了**：最後一項搬走後，連標題那一行整個框拿掉，框前後多出來的空行只留一個。
- **全部加入**：同一個框的每一項照順序搬，接在一起；一次寫入。
- **確認**：「加入」一項不問；「全部加入」先問一句「把 3 個候選卡片加進這一篇的學習目標？」。
- **驗收**（能用程式判斷）：
  - syntax §2-9 例子的候選框加入後，`parseDeck` 多一個目標、ID 是原本行尾的那個、題目指紋和搬之前相同、`理由` 不在任何一行；引言框不見了。
  - 往返與冪等：同一項按兩次（第二次在新文字裡找不到）不改任何字；登錄進 `tests/deck.test.ts` 的 `deckCases`。
  - 邊界：理由不在第一個子項目、沒有理由、理由底下有子項目、項目有圖片與多行答案、框裡夾一行不是 `> ` 開頭的、框後面緊接另一個框、檔尾沒有換行、本文用 Tab 縮排、本文沒有目標。

## 3. 加進已有的學習目標的加入（跨檔，要格式查核）

### 3-1 目的地

- 用那一項的 ID 找目標（不靠連結的檔名，卡組可能改過名）：整個 vault 剛好一個讀得懂的目標用這個 ID、那一篇不需要新版、讀得到，才加入；否則那一項不動，提示原因（找不到、重複〔D-157〕、需要新版、讀不到）。
- 存草稿時沒轉成連結的（最小版 §5：原文留著的 `ID 名稱`）照同樣的規則再找一次；找得到就照常加入。
- 目的地可以是草稿、啟用或暫停的卡組；也可以是這一篇自己（家長自己搬過）。

### 3-2 搬過去的東西放哪

那一項的子項目（第一層）一行一行分成三種，各自的子項目跟著走：

| 種類 | 認法 | 放到目的地的 |
|---|---|---|
| 資料欄位 | `出處`、`類型`、`重要性`、`狀態`、`備註`、`錯題補強`（和 `parseDeck` 同一組，`｜` 分隔的同一行算一行） | 出處見 §3-3；`備註`、`錯題補強` 在目的地的資料欄位後面加一行（同欄位寫兩次會合併，[syntax §2-4](../docs/syntax.md#2-4-資料欄位)）；`類型`、`重要性`、`狀態` 不搬（目的地的照舊） |
| 題目 | 有 `::` 或 `==…==`（`parseDeck` 認得是題目的） | 目的地最後一題（含它的子項目）的下一行；目的地沒有題目時，接在資料欄位後面 |
| 其他（記憶錨點這類共用補充、圖片） | 其餘 | 目的地那一項整個的最後 |

- **不重複**：題目照 [syntax §2-8](../docs/syntax.md#2-8-題目指紋) 的指紋，目的地已經有同一題就不加；共用補充與 `備註`、`錯題補強` 的那一行整理空白後和目的地已有的相同就不加。所以同一項加兩次、或中斷後重按，目的地不會多一份（§4）。
- **縮排**：搬過去的行，第一層對齊目的地子項目的那一層，更深的照原本的相對深度；縮排字元照目的地那一篇。
- 目的地的名稱、ID、其他題目一個字都不改。

### 3-3 出處（跨學期補年級學期與單元）

這一篇（來源）屬性區的年級學期與單元編號，寫成 `<年級學期> <單元編號>`，例如 `小五上 2-1`：

- 那一項的出處每一段：已經寫了年級學期與單元的照原文；沒寫的前面加上 `小五上 2-1 `，例如 `p.15` → `小五上 2-1 p.15`（syntax §2-5 的跨單元寫法：別的單元一定要寫年級學期，同一學期也一樣）。
- 那一項沒有出處那一行：加一段 `小五上 2-1`（D-027「在出處加上新的課」）。
- 來源和目的地是同一個年級學期、同一個單元（例如英文同一課的單字篇和文法篇）：不加前綴，照原文；沒有出處那一行時不加。
- 目的地已經有完全相同的一段（整理空白後）就不加。
- **寫法**：用出處小表單「加一段」的同一套寫法（`src/core/deck/source-edit.ts`，D-170）：接在同一行或分行照目的地現在的樣子、三段以上或有連結時分行（syntax §2-5）、`本單元` 的規則都由它決定，不另寫一份。
- 來源沒有年級學期或單元（一般知識）：出處照原文搬，沒有出處就不加。

### 3-4 全部加入與確認

- 「加入」一項不問；「全部加入」先問：「把 5 項加進已有的學習目標（3 篇卡組）？加入前可以把滑鼠移到連結上，看原本的題目。」
- 做完一則通知：加入了幾項、到哪幾篇；沒加入的每一項一句原因（照 §3-1），留在框裡。

## 4. 多檔寫入的順序與中斷（要格式查核）

環節 4 結論第 5 條：每篇寫成才算完成，失敗時照實回報已成功的部分；**先寫目的地再刪來源，刪除前在最新文字裡重新確認**。

1. **讀**：來源最新的文字裡找到要加入的項目（§1），記下每一項的原文。
2. **寫目的地**：照目的地分組，一篇一次寫入，經過 `state` 的寫入佇列與門檻（電腦、讀完、備份成功、沒有讀不到的、目的地不需要新版）。寫入回呼裡用那一篇**最新的文字**再找一次目標（§3-1）、算要加的（§3-2 的不重複）；沒有要加的就不改字。寫入後照現有的核對讀取確認寫成。
3. **從來源拿掉**：一次寫入。回呼裡在來源最新的文字裡，只拿掉**原文和第 1 步記下的相同**、而且**目的地最新的文字裡已經有它的每一題**（指紋）的項目；其他的留著。框空了照 §2 拿掉。
4. **回報**：照實寫哪幾項加入了、哪幾項沒有與原因。

- **中斷**（重開、寫不進去、門檻沒過）：不另存恢復資料。第 2 步寫成、第 3 步沒做時，項目還在框裡、目的地已經有題目；家長再按一次「加入」，第 2 步因為不重複所以不改字，第 3 步照常拿掉。第 2 步沒寫成時什麼都沒變。
- **只拿掉自己搬的**：第 3 步只拿第 1 步記下、原文沒變的那幾行；家長在中間改了那一項，就留著不拿，提示「這一項剛改過，題目已經加進去了，框裡的請自己看要不要刪」。
- 同一篇的候選（§2）只有一次寫入，沒有中間狀態。
- 重排：每一次寫成照現有的採用（`state` 的 adopt）；不另做批次結束才重排的機制（一次加入最多幾篇，今天的份照現在的規則重算）。💬 格式查核請看這樣夠不夠。

## 6. R8：刪除收成一個入口（等使用者決定範圍）

技術債的觸發點寫「下一次新增會刪 vault 裡的檔或資料夾的產品程式（例如……引言框的加入與搬移）」。但照 §2～§4，加入**不刪任何檔或資料夾**，只改兩篇卡組的字；拿掉來源的那幾行由 §4 第 3 步的「只拿掉自己搬的」保護。所以觸發點其實沒到。使用者要決定：
