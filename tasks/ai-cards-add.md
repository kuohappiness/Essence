## 和「不做」比較（D-153）

- **不做會怎樣**：最小版的草稿裡，候選卡片與加進已有的學習目標只能手動處理：候選要自己剪出引言框、拿掉每一行的 `> ` 與「理由」；加進已有的要打開舊卡組、找到那個目標、把題目照縮排貼過去、在出處自己補 `小五上 2-1 p.15`，再回草稿刪掉。一項約 1～2 分鐘、容易錯（縮排錯一層意思就變，`> ` 沒拿乾淨整段不算卡），家長多半就不做：D-027 的「同一個知識再出現就加題」與候選卡片等於沒有。之後的第 2～5 批（加深、錯題補強、補記憶錨點）也都靠這個搬移把結果寫進已有的卡組，不做就全部卡住。
- **做的代價**：閱讀模式的引言框多幾顆按鈕；一個「跨檔寫入」的流程（先寫目的地、再從草稿拿掉），中斷時要靠重按一次接起來；L2。
- **更小的做法**：
  - 只做候選、不做加進已有：同一篇搬移很簡單，但加進已有才是手動最容易錯、也是第 2～5 批都要用的那一條。不夠。
  - 不做按鈕、只做命令「加入這一篇引言框的全部項目」：省了按鈕的掛法，但家長沒辦法只挑幾項，候選卡片本來就是要挑的（D-091）。按鈕的代價小，做。
  - 加進已有不做跨檔，改成把題目複製到剪貼簿、請家長自己貼：還是要找目標、對縮排、補出處，省下的不到一半。不夠。

**第 2 類（延後，記進技術債表）**：見 §7 的表。開放的入口都能走完一條安全的路徑：中斷時重按一次「加入」就接著做完，不會重複、不會丟。

## 1. 按鈕在哪、按的是哪一項

- **哪些引言框**：卡組筆記（`isDeckPath`，轉錄稿不算）裡，標題是「候選卡片」「加進已有的學習目標」的引言框（`[!note]` 與預設摺起的 `[!note]-` 都算；標題的認法和 `src/core/ai/check.ts` 相同，照用不另寫）。對象表（標題 → 怎麼加入）寫成一張表，第 2 批加「加深的學習目標」一列。
- **按鈕**：閱讀模式裡，框裡每一個最上層的項目旁一個「加入」，框的標題列一個「全部加入」；按「全部加入」不會展開或摺起引言框。只在電腦、外掛讀完之後；這一篇需要新版（D-149）或屬性區讀不懂時不放按鈕。
- **找項目**：畫按鈕時記下那一項在那時的原文（每一行去掉引言框的 `> ` 之後的字）與它的身分：候選是名稱行行尾的 ID；加進已有是第一行連結（或原文開頭）的 ID 加上同一個框裡同 ID 的第幾項。按下去時，在這一篇**最新的文字**裡用身分與原文重新找；找不到或原文變了，提示「這一項剛改過，請再按一次」，不寫。
- **平台事實**（code-quality〈寫規格〉；送 L2 前用開發命令在 Windows 版 Obsidian 跑完，iPhone 不用）：

## 2. 候選卡片的加入（同一篇，要格式查核）

格式查核（[報告](<../Claude Codex Discussion/2026-11-16-ai-cards-add-format-review.md>)）的 F4、F6 已照改。

- **兩種候選**（§5）：一般候選；**疑似重複**（理由那一行是 `理由：可能重複 <ID>｜<哪裡拿不準>`）。疑似重複的按鈕寫「加入為新目標」，不進「全部加入」。
- **搬到哪**（F4）：用 `parseDeck(…, { layout: true })` 找本文最後一個學習目標**完整根項**的結束位置，插在那裡；和前後的區塊之間要有一個外部空行（沒有就補一個）。本文沒有學習目標時，插在這個引言框前面的頂層區塊邊界。所以候選會在最後一個目標所在的小標題底下（不是檔案最後一個小標題），家長要換位置自己搬。
- **縮排**（F4）：候選維持根項，清單符號對齊最後一個目標的根項；子項目先把 Tab 展開，照它和候選清單符號正文欄的相對欄位換算（數字清單 `100. ` 的正文欄比 `- ` 寬，不能照抄欄數）；縮排字元照這一篇。
- **怎麼改**：每一行拿掉引言框的前綴（行首最多 3 個空白、`>`、後面一個空白）。理由行只在「名稱底下直接一層、底下沒有子項目」時自動拿掉；理由底下有內容的，這一項留著，提示「理由底下有內容，請手動搬」（拿掉理由會讓它的子項目變成前一題的詳解）。其他字（名稱、行尾 ID、出處、題目）不動。
- **框空了**：最後一項搬走後，整個框（標題行到最後一個 `>` 行）拿掉，保留前後區塊的分隔：剩一個空行，框在檔頭或檔尾時不多留；檔尾原本有沒有換行照舊、換行字元照這一篇。這個框和下一個框之間沒有外部空行（`blocksOf` 讀成同一塊）時，只拿項目、不拿框。
- **ID**（F6）：搬之前核對名稱行的 ID：在行尾、和本文的目標、同一批的候選、vault 裡其他卡組的目標都不重複。不符合（沒有 ID、在行中、重複）就留項並說原因，不自己改配。快照不改（D-042）。
- **比較卡**（F6）：候選有比較卡時，同一次寫入在屬性區補 `需要版本`（取現在的值和比較卡最低版本的較高者，D-191）；補不了就留項。
- **寫之前核對**（F4）：計畫裡解析寫前、寫後兩份文字，寫後 = 寫前的每個目標（ID、名稱、分組、題型、題目指紋、欄位、補充歸屬）不變，加上恰好這幾個新目標，它們的題目指紋和在框裡時相同。不成立就不寫，那幾項留著並提示。
- **全部加入**：同一個框的一般候選照順序搬，接在一起；一次寫入。
- **確認**：單項「加入」不問；「全部加入」先問一句「把 3 個候選卡片加進這一篇的學習目標？可能重複的 2 項請逐項看。」（沒有疑似重複時不寫後半句）。
- **驗收**（能用程式判斷）：
  - 存草稿後的 syntax §2-9 例子（候選已配好 ID）加入後，`parseDeck` 多一個目標、ID 是原本行尾的那個、題目指紋和搬之前相同、`理由` 不在任何一行；引言框不見了。
  - 往返與冪等：同一項按兩次（第二次在新文字裡找不到）不改任何字；登錄進 `tests/deck.test.ts` 的 `deckCases`。
  - 邊界照格式查核〈驗收與相容性〉表的前兩列與第四列（段落緊鄰或空行、表格、程式圍欄、兩框有無外部分隔、只剩空的框、沒有本文目標、`###` 後無目標、數字根項、Tab 與不等寬縮排、CRLF、無檔尾換行；理由在中間且有子項、項目有圖片與多行答案；候選和本文或另一候選重 ID、僅候選含比較卡）。

## 3. 加進已有的學習目標的加入（跨檔，要格式查核）

### 3-1 目的地

- **有連結的項目**（存草稿時核對過）：用那一項的 ID 找目標（不靠連結的檔名，卡組可能改過名）：整個 vault 剛好一個**正式的**目標用這個 ID（讀得懂、不是隱含題、沒有讓它停出的寫法問題）、那一篇不需要新版、讀得到，才加入；否則那一項不動，提示原因（找不到、重複〔D-157〕、寫法有問題、需要新版、讀不到）。
- **沒轉成連結的原文 `ID 名稱`**（F7；最小版 §5：可能是 AI 引用了沒送出的 ID）：不進「全部加入」，通知裡報出原因。單項「加入」先開確認：目的地的卡組、目標名稱與第一題，家長按確定才照上一點加入。
- 目的地可以是草稿、啟用或暫停的卡組；也可以是這一篇自己（家長自己搬過）。
- 加入只加題與補充，不退役、不合併任何正式目標（D-167 第 9 點不適用）。

### 3-2 搬過去的東西放哪

格式查核的 F2、F5、F6 已照改。那一項的第一層子項目用 `parseDeck` 的同一套規則（版面切割與語意分類一致，不自己掃 `::`／`==`）分成三種，各自的**完整範圍**跟著走（多行答案、題下的背面補充、子項目）：

| 種類 | 認法 | 放到目的地的 |
|---|---|---|
| 資料欄位 | `出處`、`類型`、`重要性`、`狀態`、`備註`、`錯題補強`（`fieldStart`）；`｜` 分隔的複合行用欄位解析拆開，各欄位各自處理 | 出處見 §3-3；`備註`、`錯題補強` 在目的地的資料欄位後面加一行（同欄位寫兩次會合併，[syntax §2-4](../docs/syntax.md#2-4-資料欄位)）；`類型`、`重要性`、`狀態` 不搬（目的地的照舊） |
| 題目 | `parseDeck` 認得是題目的 | 目的地最後一題**完整範圍**的結束位置（不插進它的接續行或子項目）；目的地沒有題目時，接在資料欄位後面 |
| 其他（記憶錨點這類共用補充、第一層圖片） | 其餘 | 目的地那一項整個的最後 |

- **留項不搬**（F5）：欄位出現在題目或補充底下（例如記憶錨點底下的 `狀態：暫停`、題目底下的 `出處：`）；目的地是隱含題（題目只在名稱的接續段落、ID 是 null）；`parseDeck` 讀那一項有 `ok: false`。都提示原因。
- **已經在目的地**（F2）：每一個要搬的單位（一題連同它的完整範圍、一行補充、一行備註或錯題補強）整理空白後和目的地已有的**逐字相同**，就當已經加過、不再加。題目指紋相同但完整內容不同（例如詳解不同）：這一項留著，提示「目的地已經有同一題，但補充不一樣，請自己看」。不只比指紋：指紋不算詳解與補充（[syntax §2-8](../docs/syntax.md#2-8-題目指紋)）。
- **題目相同、答案不同**（防 §4 限制 1；使用者 2026-11-16 同意）：目的地這個目標裡已經有一題，題目那一側整理空白後和要加的相同、答案不同（填空題把 `==…==` 遮掉後比整行），就不自動加，那一項留著，提示「舊卡組已經有同一個題目、答案不同，可能是上次加過又改了，請自己看」。同一個目標裡題目相同、答案不同本來就讓孩子不知道答哪個，攔下來不算誤擋。不比答案：答案相同、題目不同在同一個目標裡很常見。
- **區塊 ID**（F6）：搬的行裡帶著區塊 ID（`^xxx`，題尾的不當目標 ID，D-089 第 9 條）時，目的地或同一批已經有同一個就留項；不改號。
- **縮排**：搬過去的行，第一層對齊目的地子項目的那一層，更深的照相對欄位（Tab 展開）換算；縮排字元照目的地那一篇。
- **寫之前核對**（F5）：用目的地的科目解析寫前、寫後兩份文字：目的地每個目標的 ID、名稱、題型、既有題目與補充、欄位不變；這個目標多出預期的題，題型不變、沒有新的寫法問題（例如比較卡混進普通問答的 `pick-mixed`、答案不在組裡的 `pick-answer-invalid`、全詩排序或英文排序因為多一題而退化）。不成立就不寫，那一項留著並提示。比較卡多一句要補的 `需要版本` 照 §2 同一次補。
- 目的地的名稱、ID、其他題目一個字都不改。

### 3-3 出處（跨學期補年級學期與單元）

格式查核的 F1 已照改：**不逐段加前綴**（`p.44、46` 逐段加會把 `46` 讀成標題、`國二上 1-3 p.20、p.21` 的後段會換單元、否定段會恢復成有效單元），改成先讀懂、再按讀出的歸屬轉寫，寫後重讀核對。

1. **讀**：用來源這一篇的屬性（科目、年級學期、單元、材料）讀那一項的整個出處欄（`readSourceParts`），得到每一段的歸屬：這一篇（沒寫單元或寫 `本單元`）、寫明的別的單元、直接連到筆記的連結。讀出看不懂、否定、`leftover`、只寫年級學期這類問題的，或來源屬性不足卻有本地位置（`p.15` 但來源沒有單元）的，這一項留著，提示原因。
2. **同一個單元**：來源和目的地的科目、年級學期（`termKey`）、單元編號（`codeKey`；`第2章第1節` 這類別名先經 `chapterAlias`）都相同，**而且材料相同**。例如英文同一課的單字篇和文法篇。
3. **轉寫**（以讀出的「同一歸屬、連續的段」為一組）：
   - 歸屬是這一篇的組：同一個單元 → 照原文；不同單元 → 整組前面加一次 `<年級學期> <單元編號> `、拿掉 `本單元`，例如 `p.44、46` → `小五上 2-1 p.44、46`（syntax §2-5：別的單元一定寫年級學期，同一學期也一樣）。同單元但材料不同 → 留項。
   - 歸屬是寫明的別的單元（含接在後面、靠它承接的段）、直接連結：照原文。
4. **沒有出處那一行**：來源有單元、和目的地不同單元時，加一段 `<年級學期> <單元編號>`（D-027「在出處加上新的課」）；同單元、或來源是一般知識（沒有年級學期或單元）時不加。
5. **去重**：轉好的組，歸屬（科目、年級學期、單元、位置）在目的地已經讀得到同一個就不加；比歸屬，不比字面（目的地的 `p.15` 可能接在別的單元後面）。
6. **寫法**：每一組用出處小表單「加一段」的同一套寫法（`src/core/deck/source-edit.ts`，D-170），接在同一行或分行、三段以上或有連結時分行都由它決定；同單元的段用 `own: true`。目的地有兩處 `出處`、出處有接續行這類小表單拒寫的情況 → 留項。
7. **寫後核對**：用目的地的屬性重讀出處，原有每一段的歸屬不變，新加的每一段讀出的歸屬和第 1 步在來源讀到的相同；不同就不寫、留項。

### 3-4 全部加入與確認

- 展開的框裡、第一個項目上方提示一行「點連結可以打開原本的學習目標」（§5 第 4 點；按鈕畫出來時才有，不寫進檔案）。
- 單項「加入」不問（沒轉成連結的照 §3-1 先確認）；「全部加入」先問：「把 5 項加進已有的學習目標（3 篇卡組）？」沒轉成連結的有幾項時加一句「2 項沒有核對過，請逐項加入」。
- 做完一則通知：加入了幾項、到哪幾篇；沒加入的每一項一句原因，留在框裡。

## 4. 多檔寫入的順序與中斷（要格式查核）

環節 4 結論第 5 條：每篇寫成才算完成，失敗時照實回報已成功的部分；**先寫目的地再刪來源，刪除前在最新文字裡重新確認**。

格式查核的 F2、F3 已照改。

1. **讀**：來源最新的文字裡找到要加入的項目（§1），記下每一項的原文與要搬的單位（§3-2）。
2. **寫目的地**：照目的地分組，一篇一次寫入，經過 `state` 的寫入佇列與門檻（電腦、讀完、備份成功、沒有讀不到的、目的地不需要新版）。寫入回呼裡用那一篇**最新的文字**再找一次目標（§3-1）、算要加的（§3-2 的「已經在目的地」）、做寫前寫後核對（§3-2、§3-3）。**算完成**只有一種：核對讀取確認目的地寫成（`written`），或沒有要加的（全部已經在目的地）而且最新的文字讀得到。`saved`（寫進磁碟但讀不回來，停用時也會回這個）、讀不到、逾時、結果不明：這幾項留在框裡，通知「目的地可能已經寫了，重開後再按一次」。
3. **從來源拿掉**：一次寫入。回呼裡在來源最新的文字裡，只拿掉同時符合三件事的項目：原文和第 1 步記下的相同；目的地在第 2 步算完成；`state` 記著的目的地最新文字（回呼是同步的，不在裡面讀另一篇）仍然含它的每一個單位。其他的留著。框空了照 §2 拿掉。
4. **回報**：照實寫哪幾項加入了、哪幾項沒有與原因。

- **同一篇同時是來源與目的地**：一次寫入完成，只用一次最新文字。
- **同一篇同時只跑一個加入**：工作進行中這一篇的按鈕停用；雙擊不會跑兩次。
- **目的地在第 2、3 步之間被刪或改名**：照原路徑找不到，來源留著；重按時照 ID 找到新位置，再查一次唯一、版本與完整內容。
- **中斷**（重開、停用、寫不進去、門檻沒過）：**不另存恢復資料**。第 2 步寫成、第 3 步沒做時，項目還在框裡、目的地已經有那些單位；家長再按一次，第 2 步沒有要加的、不改字，第 3 步照常拿掉。第 2 步沒寫成時什麼都沒變。
- **iCloud 把來源的舊版同步回來**（項目又出現在框裡）：目的地完整就只再拿掉一次；目的地也回到舊版，就照常再加。
- **只拿掉自己搬的**：家長在中間改了那一項，就留著不拿，提示「這一項剛改過，題目已經加進去了，框裡的請自己看要不要刪」。這一條是 R8「只刪自己建的」在文字層的版本（§6），L2 要查。
- **限制**（💬 等使用者接受，見下方）：
  1. 第 2 步寫成、第 3 步沒做（中斷），家長在重按之前改了目的地剛加的那一題**題目的字**，重按會再加一份原本的。看得到、可以刪，不會丟。只改答案的由 §3-2「題目相同、答案不同」攔下（使用者 2026-11-16 同意加這道防呆）。
  2. 兩台電腦同時對同一篇加入，iCloud 只留其中一份時，另一台加的題可能不見。AI 原本交回的整份留在快照（D-042），可以從那裡找回。
  - 為什麼不另存恢復資料：要防第 1 點，得在外掛資料記「哪一項已經寫到哪裡」，重開時比對；它本身也靠 iCloud 同步，防不了第 2 點，卻多一份跨重啟的狀態要測。兩種情況都要「中斷＋手改」或「兩台同時」，影響是多一題或可從快照找回。
- **重排**（環節 4 結論第 5 條）：一次「加入」或「全部加入」是一個批次。批次中每篇寫成照常採用、更新索引，但只標記要重排；批次結束（全部成功、部分成功、停用都算結束）才重建、重排、通知一次。中途有人要今天的份或卡組清單時，先用已成功的部分重建，不給舊清單配新文字。`Files.watch` 的回聲不另外重排。
