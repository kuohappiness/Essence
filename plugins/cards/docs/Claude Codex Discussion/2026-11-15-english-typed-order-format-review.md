## F1｜通用結尾會把別科目標變成英文打字卡

**觸發／預期與實際。** 數學的 `能化簡 複數` 底下寫 `i² 等於 ＿＿。 :: -1`，應維持翻面。`typedAnswer('-1')` 完全合法，`42`、`B`、`...` 也一樣。國語的 `能辨認句子的 文法` 答 `A`、語言比較的 `能從句子辨認 比較級` 答 `more` 會走同一條路。`語法結構 文法` 答中文、或 `複數` 用公式時才會碰到 §1-3 的翻面提示，因此降級無法防止型別誤認。反過來，真英文的 `go 過去式` 交出 `went | `、含連結的答案或高亮填空時，無條件翻面會讓家長以為已在驗拼字，卻只寫下自評。一律停整個目標則會停掉同名的別科卡與同池有效題。

**影響／真實路徑。** 手寫卡可直接觸發，數字、代號與單詞答案都常見。英文草稿也可能生出無法比對的答案。把全部異常一律設成錯誤或一律設成提示，都會把作者意圖相反的卡混在一起。

**判斷。** 用已有的 `科目: 英文` 或一個明確的英文題型標記確立意圖。最小方案是以英文科目為新結尾的範圍，手寫無科目卡沿用原題型並在格式文件寫清楚。AI 草稿以製卡選定科目判斷，因 §2-9 本來就由外掛補屬性。若無科目的手寫卡也須支援，先定明確標記。意圖成立後，不能當打字答案的 QA 建議報錯，延續中翻英的壞答案處理。尚未有明確意圖的卡照原題型，無需告警。中翻英本身已有兩種行為：非法 QA 會停目標，真的 `==…==` 填空只有 `cloze-not-typed` 提示，仍可翻面。新目標若也採這個填空例外，就明文列為手寫相容行為，英文 AI 草稿必須擋；單一目標混合打字／翻面時也要寫清楚是否接受共用排程。

**證據。** 已重現。三個版本的 `typedAnswer` 都收數字與符號；上述數學目標在 `dd808c1` 和 `v0.5.0` 是 `flip`、在 `5a4ca30` 是 `typed` 且無診斷。三版的 `go 中翻英` 下 `I ==go== there.` 都是有效的翻面卡，只有提示。位置見任務 §1-1～3、§5、基準 `question-types.ts:18`、`parse.ts:313–322`。

## F2｜先定名稱的拆法與題型優先序

**觸發／預期與實際。** `go 過去式`、`go　過去式` 的原形均應為 `go`；`lie（躺） 過去式` 應提示 `lie`、配指定義項。`lie(躺)過去式` 的右括號可作分隔，§1-4 卻只去全形括號，所以會保留 `(躺)`，而配對已經把半形折成相同的義項。應同時定下提示與配對接受的括號，建議正式寫全形、讀法兩者一致；多組、空組、巢狀與未配對括號各有明確結果。單寫 `過去式` 或 `go過去式` 照常；`能說出 go 的 過去式` 不應讓這一整段充當英文原形，保留翻面或提示重寫。

| 輸入 | 預期與現況 |
|---|---|
| `lie（躺） ^x3q9m2 過去式` | 共用解析先找回 ID，再比後綴。基準已取出 `x3q9m2` 與乾淨名稱，留 `misplaced-id`；實作版打字且原形是 `lie`。兩個不同 ID 照原規則停止。 |
| `**go** 過去式`、`go **過去式**`、`**go 過去式**` | 契約要說格式能否包住後綴。建議只在語意判定前去成對粗體，保留原名、ID、題目指紋。實作版整名加粗會漏認。不可任意去 `==` 讓原本的 implicit 填空變成新型別。 |
| `go 過去式 中翻英`、`go 過去式　中翻英` | 方向優先。後一例的方向已認得，但 `baseForm` 現有只去半形空格的後綴，提示會顯示 `go 過去式　中翻英`。沿用方向確立後的 `pairKey` 可共享拆法。 |
| `borrow（borrow、lend） 文法` 或 `… 排序`，底下是 `Can I ＿＿ it? :: borrow` | 維持 D-182 的有效點選填空；答案換成 `lend` 保留 `pick-answer-invalid`，不能吞成一般打字。 |
| 同一組形狀，底下只有 `He ==can== ==borrow== it.` | 名稱讀得出括號組，但整個目標沒有比較句。§4-1「沒有組」需指定是已認成的比較目標，還是僅有組形狀。基準把它讀成全詩；實作版是句子排序。建議有組形狀而沒有有效比較句時維持原題並給歧義提示，除非作者用明確的排序標記消歧。 |

**影響／證據。** 已重現上表的中置 ID、整名粗體、全形空白方向、兩種組與答案的基準讀法。其餘是依 §1-1、§1-4～5、D-125、D-134、D-182 第 4 點推斷；手寫格式和複製編輯會遇到，正常 AI 預設用正式寫法。位置見基準 `parse.ts:145–176`、`question-types.ts:56–99,125–156`、`base-form.ts:7–11`。優先序應明寫為先判 implicit／ID 與方向，再確認比較組含診斷，然後按明確意圖讀新題型。三個後綴不會在同一名稱同時命中，真正重疊的是括號組、最終後綴與題目形狀。

## F3｜文法提示需要可定位的格式

**觸發／預期與實際。** 現有取第一個括號適用於 `被動語態（現在式） 文法`、`比較級（兩者比較） 文法` 和無括號的 `被動語態 文法`。`（現在式）被動語態 文法` 得到空提示；`be 動詞（含縮寫）（現在式） 文法` 若前一組是文法點名稱的一部分，會只剩 `be 動詞`。題幹的 `不要用「比較級」這個詞。He is ＿＿ than I.` 含同字串卻沒給使用比較級的提示，會跳過；連結目的地、註解中有同名文字也可能誤跳。`現在完成`、`present perfect` 又可能已明示、但字串找不到。

**判斷。** 用名稱最後一組平衡括號當用法，只移除該組；早先的括號保留，前置括號、空文法點或不成對者提示作者改名。`被動語態（現在式） 文法` 這種只有一組括號的情形按格式約定當用法，若文法點本身以括號收尾就再寫一組用法。題目前置明示標籤如 `（現在完成式）` 才觸發跳過，完整等值比對，支援全半形和成對格式；`(know)` 是題中原形，不是標籤。別名若日後真的要收，列明對應或讓作者改寫同名標籤。一般內文不作語意猜測。AI 題仍按 D-193 第 6 點不給文法名稱；手寫已明示才用這個例外。

**影響／證據。** 只改第二次作答的機會與 `retry` 證據，第一步的分數仍照 D-121。真實路徑主要是家長手寫或採用錯題，常規英文草稿不該給名稱。已在 `5a4ca30` 的 `typedHint` 重現否定句和前置括號都回傳 null；別名與隱藏文字是依規格推斷。位置見任務 §1-4、§2-2、英文預設 §5 A、基準 `review/typed.ts:46–51`。

## F4｜「找不到原形」與「有原形但今天不能出」要分清楚

**觸發／預期與實際。** D-193 第 5 點正文寫同字同義；同決定第 13 點把細節交給英文預設。英文預設 §3 明定，無括號是任一義，有括號只配同義，因此任務 §3 的 `go`／`go（走）`／`go（去）` 例子成立。若同篇有兩個匹配義項，無括號取任何一個 `remembered` 也成立。配對建議明定先按 F2 拆出義項，再分別正規化詞與義項，釘住 `Light　(輕的)` 與 `light（輕的）` 是否等值。連續空白壓成一個不會去掉括號前的可選空白。`go（走）` 找不到同義時不宜退回 `go`。配對仍限同篇，片語的變化留在原中翻英池（D-193 第 5 點）。

| 條件 | 查核判斷 |
|---|---|
| 英翻中在段考範圍外，仍符合今天的份濾網 | `exam.contains` 只改類別／保留率，並非候選條件。仍把它當配對，可能讓考試範圍內的變化晚出；寫成明確例子。 |
| 英翻中暫停、無 ID、錯誤或排除在濾網外 | §3-3 選擇照常出，與目前中翻英找不到有效候選時一致。對家長主動暫停／過濾是合理取捨；新格式不要寫成「原形不存在」。 |
| 英翻中被未知版本紀錄停掉，或 ID 重複而被 state 移除 | §3-3 也會放行。這時程式知道判斷不了原形是否記得。建議停等至資料可判定，或由規劃者明定接受放行。若要停等，必須從 state 保留被移除的同篇匹配資訊；重複 ID 既不採它的分數也不選一筆代表。整份紀錄 `incomplete` 時所有候選都停，無須另做例外。 |
| 同配對鍵兩個英翻中，第一個暫停，第二個可出 | 舊中翻英先按原字串、每方向取行號最小，再查候選；第一個不是候選時不改找第二個。§3 的所有候選／任一記得是另一個配對規則。可共用候選、`remembered`；別在這次一起改 D-069 的配對或同日到期二選一。 |
| 當天才答對原形、變化只有今日紀錄或只有 `src: mistake` | `planToday` 只重播 4 點換日前的紀錄；這次的「記得」隔天才生效，且好評但今日到期仍不算。`§3「有紀錄」` 要明定同日作答由哪條流程承接、錯題造成的排程紀錄是否解除首次門檻。建議明寫今天的份是日初判斷，已完成同日作答不因重算被當成沒開始；只有錯題的事件要由產品定是否算已開始，別用 `memory !== null` 隱含決定。 |

**影響／證據。** 基準 `plan.ts:76–165`、`study/fsrs.ts:9–31`。合成筆記已在基準與 `5a4ca30` 驗證濾網、`need` 停一個原形、重複 ID、第一個同鍵暫停、段考範圍外。實作版在原形被濾網、`held` 或重複 ID 排除時都出變化；原形在考試外仍會擋。另驗了實作版同日 `easy` 沒在 `planToday` 放行、前日只有變化的 `src: mistake` 已解除門檻。段考和過濾是可預期的日常路徑；壞紀錄與重複 ID 取決於混版或複製筆記，頻率較低。真實複習中的同日恢復需另驗 session，這裡只跑今天的份規劃。

## F5｜句子與全詩沿用同一後綴時，Latin 無法確定題型

**觸發／預期與實際。** 一題 `短詩 全詩 排序` 的 `==Here we go==，==There we stay==。` 在基準是全詩，提案會改判為句子。含 `A`、`COVID-19` 的中文現代詩也會命中。反過來，英文題幹下的 `==3== ==7==`、全靠人名譯字或數字的詞序，會按題數讀成全詩或翻面；有一格英語、有一格中文的題則仍可能進句子模式。光是 `[甲](foo)` 的網址就含 Latin，不能代表可排序的可見文字。句子題池一題沒有 Latin、多一題只有一格、或把 `==.==` 去標點後成空，依 §4-1 應整個目標翻面；§5 卻可能因完全沒 Latin 而把明顯寫錯的英文排序草稿放過。用英文科目呼叫實作版共用 checker，兩題空格只有數字時沒有英文排序錯誤，換成含 go 與僅有句點的兩格才報 `english-order-invalid`。也應寫清是每一題至少一格含 Latin，還是每格都要有，兩者對 `==the== ==7==` 結果不同。

**判斷。** 用既有的 `全詩 排序` 明示全詩；新句子可限定在明確英文範圍，或給一個明確句子標記。非英文的既有簡寫 `… 排序` 保持先前的一題多格讀法。若英文筆記也允許既有全詩簡寫，必須明定歧義時保留原樣或由作者補標記。先定意圖，再用題目的可見文字／格式檢查形狀。AI 檢查對明示的英文排序做完整題池檢查，對全詩不套英文規則。共用點選流程、單目標多格、最差格決定評分都符合 D-193 第 8 點與 D-187；依 D-028 選一題，勿混用比較卡的輪替例外。

**影響／證據。** 英文詩或數字／混合詞塊須手寫，低於正常文法句的頻率；英文預設本來一次出三句，刪題剩一題也是合理編輯。已重現 `短詩 全詩 排序` 在 `dd808c1` 的 order 變成 `5a4ca30` 的 sentence，`v0.5.0` 都翻面。一題英文多格在 `dd808c1` 其實進全詩，三題才照翻面。位置見任務 §4-1～2、§5，基準 `question-types.ts:154–166`、`docs/syntax.md` §2-3 的全詩段。「英文的排序寫成問答題」應刪，英文預設 §5 B、§8 已用 `==…==` 填空。

## F6｜詞鍵的正規化不能改寫拼法或讓標點跟錯詞

**觸發／預期與實際。** §4-5 會把 `Mr.`、`U.S.` 的末點移到格位上，交換兩顆鍵時縮寫的點留在原格，甚至在 `==Mr.== ==Alex==` 中把下一格視為句首。引號內的 `==Go!==` 可把 `!` 挪出，`==“Go!”==` 尾端是引號卻會整組留在鍵上。裸 `don't` 不會受尾端規則影響，撇號須保留；`A:`、`B:` 若被挖空，冒號是說話者標記，也不是句尾點。`My choices: ==TV== ==USA==` 或 `key: ==Alex==` 的冒號不一定是句首。規則把早先的中文／全形標點一律當作句界也會誤判。句首 `I'm`、`I’m`、`I`、`NASA`、`TV` 保留可測，但 `Alex`、`May` 與普通句首詞的單字形狀相同，無法只靠第一個字母判斷。英文預設 §5 B 已明說真要挖句首時人名照原樣，光登錄已知限制不能讓這兩個規格都成立。

**判斷。** 延續英文預設把句尾標點與對話標籤寫在格外，格內標點視為詞的一部分；當明確判出獨立句尾標點才移出，無法分辨時保留或請作者改寫。句首需有可測的句界，最小做法是只支援第一個英文句子的開頭，內文有縮寫、引號、冒號或多句時用既有的句首留格外。對必須挖的句首，讓作者直接用鍵應有的小寫或原大小寫，並寫清畫面何時補句首大寫。評分用經指定轉換後的鍵等值，`The`（因句首才大寫）與 `the` 化為同鍵，互換對；人名 `May` 與動詞 `may` 是不同詞，不能把全部詞一律折小寫。顯示、位置與等值都要有測試，包含去標點後兩顆變同鍵。全同鍵沒有排序能力可測；僅兩種可見排列時也無法同時要求「與正解及上次都不同」，應優先保證可作答且不直接給正解，允許兩次相同或拒收全同鍵。

**影響／證據。** 手寫的稱謂、引號、人名很常見，正常草稿把句首句尾留外可避掉較多。已重現 `5a4ca30` 的 `He asks ==Mr.== ==Alex==: "==Where== is ==the== ==exit?=="` 產出鍵 `Mr`、`alex` 與後綴 `. `，以及 `==The== ==the== dog.` 只剩相同鍵；基準 `review/pick.ts:185–196` 確實比字串，鍵索引只用於交換。其餘為 §4-3～6 的推斷，未在 Obsidian 驗實際畫面。

## F7｜紀錄能相容重播，混版仍會提前開卡

**觸發／預期與實際。** 兩台同步同一新卡組，一台仍在 `0.5.0`。舊版變化、文法、英文句子排序都翻面。舊版 `planToday` 在 `go 英翻中` 仍未作答時也排 `go 過去式`，如果孩子翻面自評並同步，等新版隔日重播時，這個變化目標已有 `r`／記憶狀態，§3-4 不再等原形。新版也會用普通自評推進原來想用打字或排序驗證的目標。現有正式 vault 沒有這批卡，因此已發布資料的搬移無須擋開工；這個路徑發生在啟用新卡後，條件是一台未升級或退版且作答，操作足夠普通，不宜當作極低機率。全部卡、單篇、小考在新版也能提早練變化，須在規格說清楚這些入口的紀錄是否也視為已開始。

**判斷。** D-204 第 6 點的免標記決定針對全詩，理由是當時會把所有裝置更新；它沒有涵蓋增加先備門檻的變化目標。依 D-149 第 3 點選擇發布前先升、核驗所有仍使用的裝置已重開，再啟用英文新卡並定退版下限；若要支援混版啟用且仍保證新作答語意，給受影響卡組 `需要版本`，舊版便不寫這些目標。若產品明確接受舊版自評可推進相同進度、舊版能跳過門檻，就把例外寫進決定與說明。已寫進去的舊自評保留，不把缺欄位補成打字／排序成功。

**證據與欄位建議。** 已用 `v0.5.0` 的排程重現同日可出原形和變化，並把只有 `r`、`v` 的合成翻面行交給 `5a4ca30` 重播，變化不再是未開始的目標。也用舊版 `parseLine` 確認能讀 `typed: "wrong"` 與 `retry: "not-needed"`，以及帶 `cell`／`pick`／`also` 的句子排序行：會保留 `r`、`v`、`typed` 和 `also` 的指紋，`cell`、`pick`、`retry` 仍是原檔證據。相同 `v` 的格經 `addShown` 去重，只算同一題一次。沒有新枚舉值要舊版理解，單靠證據欄位不需要 `need`。

- D-115 的作答方式與回頭定位一題可以沿用。打字 `typed` 是第一步，`retry` 為原形或文法點提示後的結果；說明無提示、提示等於一種答案或題首明示時的 `not-needed`。同字數是 D-193 第 6 點對英文製卡的硬條件，舊的 `typed-answer-words` 只是提示，英文 AI §5 要補查。實作版共用 checker 對 `went | did go` 沒報打字格式錯誤。
- 排序 `pick` 記第一次按「對答案」時真正所選的**鍵文字**，也就是去自動大小寫／標點後所見的鍵，而非目標格原文或再選內容；第一次跳過寫 `null`，`retry` 另外記。兩個同鍵互換等值，無需再記鍵索引。用 `lt`、原始題目指紋 `v`、從 1 起算的 `cell` 回查。最差格放最上層，同分取前者，`also` 放其餘格，全部沿用同一 `v`。用 `pick`／`typed` 判有無作答證據；碰到沒有版本行的舊自評無法確定是哪一版，不推定它通過新題型。位置見基準 `review/pick.ts:234–247`、`study/entries.ts`、`study/shown.ts` 與 syntax §5。

## F8｜文件和驗收必須描述相同的入口

**預期／實際與影響。** 程式可查格式、結構與具體字面值，無法從名稱證明文法點語意、出題只有一種合法排法，或教材是否正在教這個用法。這部分出現在正常草稿，應用製卡規則的試填反例驗收。任務現有例子大多能測，`==lives.==` 單獨只有一格應當翻面，要補整句兩格以上才可測標點移除。`用 typedAnswer 讀得成` 單靠答案 validator 會讓 `When did he leave? :: went` 進打字，實作版已重現。文法／變化須明定題幹恰一個可見 `＿＿`，並定義 QA 的第二行子項目只有一行時是否允許打字；`typedAnswer` 看組合後的值，實作版對 `::` 後下一行單列 `have been` 仍可打字。題幹零格、兩格、Markdown 隱藏的格、不同字數的替代答案都要有不同的驗收值。

- **syntax §2-3** 更新名稱總則、後綴和有效題目的優先序、原形的括號與提示、今天的份的關卡、全詩與英文句子的消歧、失敗行為與舊版界線。維持 D-182 組優先、D-125 舊義項保留及 D-134 的 ID 修復；英文預設用 ID 回原目標，不用新後綴重命名既有錯題。D-193 第 5、6、8 點的正式例子可原樣保留。
- **syntax §2-6／§2-7** 補 `＿＿ :: 答案` 的打字形狀與 `==詞塊==` 的排序形狀，註明詞塊排序照一般輪替，調整排序畫面和名稱顯示的說法；題目指紋沿 §2-8 用原始題目，不能用轉過的鍵重算。
- **syntax §2-9／§2-10** 寫明英文製卡的科目如何帶進共用 checker、錯誤與提示的界線、候選和依 ID 加題的檢查點。若此輪尚不處理加題引用內容，應寫明在哪個入口補查，避免草稿新目標有檢查、加題到既有英文排序卻讓整池降級。CLI 與產品共用 `src/core/ai/check.ts`；用相同輸入驗兩個入口。AI 的「每目標先三句」是製卡驗收，手寫可一題；D-193 第 8 點要求另留新句驗收、家長沒勾點選就不生成，這是英文預設／製卡路徑責任。
- **syntax §5 和最低版本段** 同步 `typed`、`retry`、`cell`、`pick`、`also` 的適用題型，修正「非打字不寫 retry」與比較卡重試的表面矛盾，再加句子排序的完整一行範例。依 F7 的發布選擇補上 §0-1／§2-1 的適用範圍。

## Claude 的回應

全部採納，F7 由使用者決定（不加 `需要版本`）。規則寫進[任務說明](../tasks/english-typed-order.md) §1～§5，實作與測試在同一分支。

- **F1**：文法、變化與句子排序只在科目是英文的卡組（屬性的 `科目`；沒寫時用 `parseDeck(text, { subject })`，AI 檢查傳這次的科目）。英文卡組裡讀不成打字照中翻英是錯誤；填空題照翻面、只提示。別科、沒寫科目的照舊。
- **F2**：認結尾前先去掉成對的 `**`；變化的意思是最後一組成對的括號（全半形），字裡不能有中文或其他括號；配對鍵是字與意思各自 `pickKey` 後接成 `字(意思)`。`baseForm` 改用 `pairKey`，全形空白的方向也拿得掉。有組的名稱不當句子排序。
- **F3**：文法點是去掉最後一組括號的那段，剩下空的或還有括號就沒有提示；第 2 步只在題目開頭用括號標了同一個文法點時跳過。
- **F4**：正規化同 F2；讀不懂的紀錄停掉的英翻中也算配對、讓變化等；不在考試範圍裡的英翻中照算；重複 ID 被拿掉時照常出，記成已知限制；「有紀錄」是今天以前任何紀錄，一天開始時決定。
- **F5**：句子排序只在英文卡組、名稱沒有 `全詩`；`readOrder` 拿掉拉丁字母的判斷，別科照舊；句子排序不看空格裡是不是英文。
- **F6**：不自動改小寫，鍵照原文，english.md §5 B 已要求句首的字寫小寫；只有第一格在英文句子開頭時畫面顯示大寫，句中 `. ` 之後不猜。句末標點只從最後一格拿 `.?!`，而且後面只剩空白與結束的引號、括號，拿掉後還有 `.` 的縮寫不拿。AI 草稿的句首大寫是提醒。只有標點的格不是詞塊。
- **F7**：不擋。syntax 與發布說明寫明舊版照翻面出、紀錄相容。
- **F8**：AI 檢查只在英文草稿，擋填空題、字數不同、題幹不是恰好一個 `＿＿`、認不出的排序卡；syntax 對應各節同步改。
