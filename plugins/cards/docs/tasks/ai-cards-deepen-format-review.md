## 查什麼

1. **和決定的矛盾**：§1～§7 和 D-077、D-100、D-136、D-152、D-190、D-194、syntax §2-9、§6 有沒有矛盾；syntax 要補哪幾句。
2. **基準**（§2-3，**這次最重要之一**）：用 `對象` 的連結解析、退回用 ID 交集、取 `時間` 最晚的，會不會選錯一篇（分篇的單元、兩篇共用 ID 的錯誤狀態、家長把目標從一篇剪到另一篇、還原備份補回舊快照、兩台電腦各自加深、`時間` 時區不同）；`記穩目標` 用 YAML 清單、`無`、`無（初次製卡）` 三種寫法夠不夠清楚；舊快照（`工作: 製卡` 但其實是第一次）會不會被當成加深。
3. **寫進啟用的卡組**（§3-1、§3-2，**這次最重要之一**）：檔尾加引言框會不會接錯地方（檔尾是沒關的引言框、程式碼區塊、表格、最後一個目標的接續行、沒有結尾換行、只有屬性區）；加了之後 `parseDeck` 會不會把框裡的目標讀成正式目標（被排程）、或讓上一個目標多出接續行（題目指紋改變）；第二次加深另起同名框，第 1 批的「加入」與 `check` 會不會出事；備註框前面加 `加深 <日期>：` 的併法；寫入順序與中斷（寫好卡組、沒寫快照時重開、家長在中間改了檔、iCloud 把舊版本同步回來）。
4. **待審核的認法**（§4-3）：只看框與基準快照，有沒有會一直待審核（解除不了）或該待審卻沒擋的情況；和最小版草稿留下的框分不分得開。
5. **這台電腦的偏好**（§5）：用路徑當鍵加 `rename` 事件、`at` 和快照 `時間` 比先後，有沒有漏洞（Obsidian 關著時改名、刪了又建同名、兩個 vault）；讀不懂的值的處理。
6. **課外與延伸**（§6）：`課外：` 那一段在現行 `parseDeck`／出處的讀法裡是什麼（會不會被讀成單元、位置或提示寫錯）；舊外掛讀到會不會出事；「每一項都是課外或教材以外的筆記才算延伸」有沒有反例（`課外：` 裡有頁碼、`課外：國三上 2-1`、連結到有 `來源類型` 的筆記但解析不到、跨單元）；考試範圍檔照列它的 ID 時 `contains` 傳回 false 會不會讓範圍檔與畫面數字對不上。
7. **門檻試作**（§4-1）：模擬的假設會不會讓比較失真；有沒有該加的情境。
8. **邊界能不能寫成測試**：任務說明的邊界例子有沒有寫不成測試的；少了哪些例子。
