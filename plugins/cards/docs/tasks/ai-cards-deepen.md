## 和「不做」比較（D-153）

- **不做會怎樣**：第一次製卡只做第 ① 層（D-100：一次出完做不出深層的題），之後沒有入口讓 AI 看著學生熟不熟出下一層；家長要自己複製卡組、自己寫「哪些熟了」、自己把交回的新目標貼進啟用中的卡組（貼進去就開始排程，沒有審核）。學習地圖的第 ②③ 層與課外層永遠停在快照裡。什麼時候該加深全靠家長想到（D-194 理由第 1 點）。
- **做的代價**：一個寫進啟用卡組的流程（只加引言框，不動已有的目標）、快照多兩個欄位、這台電腦多兩種偏好、考試範圍多一條「課外不算」；L2。
- **更小的做法**：
  - 只做命令、不做主動提示：D-194 已比較過，不採（入口難找、沒人看數字）。
  - 加深的結果另存一份草稿檔，不寫進卡組：新目標加入時要跨檔、加深的補題已經是同一篇，家長要開兩個檔；D-100 定了放進那一篇的引言框。不採。
  - 課外層不標、靠家長用濾網：考前會被算成課本內容、提高到 90%（技術債那一列），和北極星的學業表現相反。不夠。

## 1. 入口與流程

1. **命令「加深這一節」**：打開的是卡組筆記（`isDeckPath`，不是轉錄稿）、狀態是啟用或暫停、讀得懂、不需要新版時才可用；草稿不行（草稿還沒審完，直接改草稿就好）。從提醒一區按「加深」走同一個流程（D-194 第 1 點）。
2. **畫面**（沿用最小版的製卡畫面，第一步換成加深的內容）：
   - 一行篇名與三個數字：「記穩了 6、常錯 2、還沒記穩 4」，旁邊一句說明（依複習紀錄判斷，目錄顏色另受到期與考試影響，D-194 第 7 點）。
   - 「這次的方向」選填一行（D-136 補充，例如「這次不要課外」），寫進任務資料的「家長調整」。
   - 「教材」選填一行（同最小版）：教材在家長自己的 AI 對話裡附上（D-206）。
   - 「複製提示」→ 同最小版的貼回步驟（服務、輸入框、檢查）。
3. **防重**（D-194 第 8 點）：同一篇有還沒貼回的加深工作時，命令與提醒都打開那一份，不另開一份；複製貼上的工作可以「取消」，取消就釋放。同一篇在寫入中（§3）時按鈕停用、命令只通知。有待審核的結果（§4-3）時，命令先問「上一次加深的結果還沒審完，要先打開嗎？」，家長選「仍要加深」才繼續（手動入口不擋，D-077「家長隨時可以直接按」）。
4. **沒有地圖、沒有教材**（〈特別 2〉）：家長手寫、沒有快照的卡組照樣能加深，地圖寫「無（請先依教材補一份全貌與架構）」；教材在家長的 AI 對話裡，程式不檢查。只有這一篇沒有任何讀得懂、有 ID 的目標時不能加深（命令說明缺什麼）。

## 2. 送給 AI 的材料（要格式查核：快照兩個欄位）

### 2-1 記穩了、常錯、還沒記穩

- **啟用目標**（D-194 第 4 點）：卡組啟用、目標沒暫停、讀得懂（`ok`）、有 ID 且 ID 不重複（D-157）、有題目、不在引言框裡、紀錄沒被停用（`stopped`）的目標。暫停的卡組可以手動加深，但提醒不算它（沒有啟用目標）。
- **記穩了**（D-194 第 3 點）：從整份複習紀錄重播（`replay`，含 iPhone 同步來的與 undo 過濾後的 `history.reviews`），穩定度 ≥ 7 天，而且最後一次有效評分是記住了或太簡單；最後一筆是錯題本（`src: mistake`）的不算記穩。不看保持率與考試。提示與送給 AI 共用一個函式（`src/core/study/` 新增，純函式，有測試）。
- **常錯**：答錯 2 次以上（§9 第 3 題）：有效評分裡「沒印象」或「差一點」累計 2 次以上（同一天同一個目標連續的答錯算一次，中間答對一次就斷開；錯題本的紀錄當成連錯裡的一筆，和同一天緊接著的重學答錯合計一次，不是每筆各算），而且現在還沒記穩。同一時刻、不同檔案來的作答照 `mergeHistory` 的順序，先後還原不了（影響小，記住）。
- **還沒記穩**：其餘的啟用目標（包括沒複習過的）。

### 2-2 任務段（`加深 v1`，和製卡的 `提示 v3` 分開記版號）

規則組照這一篇的科目送（同最小版 §3，`rules.ts`）；任務段換成加深的：

- 學生、科目、單元、學習目的（考試範圍內是準備段考或小考，否則平常複習）、家長調整、教材（同最小版）。
- **這一篇的學習目標**：每一項 `ID 名稱｜記穩了／常錯／還沒記穩｜第一題`（第一題的寫法同 `提示 v3`）。
- **同單元的其他篇**（D-190 第 4 點的去重）：只列 `ID 名稱`，寫明「只用來避免重複，不要加題到這些目標，也不要放新目標到那一篇」。
- **最新的地圖**：歸屬這一篇（§2-3 的認法）、有完整 `<<<全貌>>>` 與 `<<<架構>>>` 兩段的快照裡最新的一份，兩段原文照送；和提示的基準分開選（只補題、或不交地圖的科目的那次加深不會遮掉前一份地圖；格式查核 R1）。沒有就寫「無」，並請 AI 先依教材補一份（D-136 第 3 點、補充第 1 點）。
- **以前出過、現在不在這一篇的目標**（D-136 補充第 2 點）：歸屬這一篇的快照卡組段裡、名稱行有 ID 的目標（新目標與候選），現在這一篇沒有這個 ID 的，列成一行「以前出過、現在不在這一篇（沒採用、刪掉或搬走），不要再出：ID 名稱」。不推定是刪除（第二輪：加深的新目標寫進卡組時都在引言框，程式分不出「沒採用」和「採用後刪掉」；也不靠整個 vault 的索引）。
- **加深的規則**（通用規則 F 節凍結，所以寫在任務段；D-100、D-136、D-152 第 4 點）：
  - 常錯的先補：寫在「加進已有的學習目標」，題目讓學生自己做出常錯的判斷。
  - 記穩了的往深處出：新目標把兩個以上的知識連起來，至少一個是記穩了的，換句話問不算；還沒記穩的不動；一次只往下一層；同一次課內還有下一層時先出課內。
  - 課外層（課內熟了才出）：它用到的課內目標**全部**記穩了才出（D-136 第 4 點；不是「至少一個」）、說得出讓學生多懂了什麼、附可以查的來源（例如高中課本），查不到就不出；出處照 §6 的標法寫，每一項都寫 `課外：`。家長調整說不要課外時不出。
  - 教材之間說法不一致時照學校的，差異寫在給家長的備註；課本和學校講義不一致時也寫在備註，請家長確認（D-152 第 4 點）。
  - 新的學習目標每頁最多約 3 個；沒有值得出的就不出，在給家長的備註寫一句「這一節目前沒有更深的內容」（`check` 要接受這一句，現在報 `note-kind`，R7）。
  - 修過的地圖照樣交三段（R3 的科目）；新目標只寫在卡組段，分組用這一篇已有的小標題。
- 其他照 `提示 v3`：不寫 ID 與屬性、一個程式碼區塊、`<<<完>>>`。

### 2-3 快照與基準（格式查核）

快照照 syntax §6，改四處：

- `工作`：多一個值 `加深`（原本「製卡（包括加深）」）。舊外掛不讀快照，不受影響；這一版起讀快照的只有加深流程與提示，排程與複習不依賴（syntax §6 那一句改寫，R1）。
- `記穩目標`：和 `工作` 一起讀：`製卡` 加 `無（初次製卡）` 是第一次；`加深` 加 `無` 是成功、送出時沒有記穩的；`加深` 加 YAML 清單（照 ID 排序、去重）是送出時凍結的集合（D-194 第 5 點）。其他組合（舊稿只寫 `製卡`、缺欄、清單裡有不是 ID 的字）不算加深過：只能當第一次，也不拿來擋。
- `對象`：加深寫一項，連結用 vault 內的完整路徑（`[[Essence Cards/自然/國二上 2-1.md|國二上 2-1]]`），不用檔名（R1：同名的篇會對錯）。初次製卡照舊（多篇的清單）。
- `原有目標`（L2 R7，使用者 2026-11-17 選）：加深多寫一欄，複製提示時這一篇所有目標的 ID（YAML 清單，照 ID 排序、去重；一個都沒有時不寫）。只用在下面的「同一路徑換了一篇」：連結已經解析到這一篇時幫忙認回，不拿來跨篇找。清單裡有不是 ID 的字時當成沒寫。

**一份快照歸屬哪一篇**：只看 `對象` 的連結（metadataCache 解析）解析到這一篇。解析不到、解析到別篇、或有歧義的，不歸屬任何一篇（R1：撤掉「ID 有交集」的退路）。改名、搬移時連結的處理見下面的「卡組改名」。

- **只寫檔名的舊快照**（初次製卡的多篇清單）：vault 裡同檔名的卡組剛好一篇時才算解析到；不只一篇時算有歧義（metadataCache 會挑一篇，不能直接用它的結果；第二輪）。
- **同一路徑換了一篇**（刪了再建、同步換成別的卡組，第二輪）：快照卡組段、`記穩目標` 與 `原有目標` 裡的 ID 有，但一個都不在這一篇時，這份快照不算這一篇的（照第一次算）；兩邊都沒有 ID 的（只有備註的加深）照路徑算。真的同一篇、家長把以前的目標全部刪光時也會回到第一次（接受：內容已經整個換掉）。和 §5-1 的「路徑重用」同一條規則，不另設篇的身分。加深成功、送出時沒有記穩的，家長又把這次的新目標全部捨棄時，靠 `原有目標` 仍算這一篇的（L2 R7；沒有這一欄時只剩捨棄的新 ID，會被當成換了一篇）。
- **卡組改名**（L2 R7，使用者 2026-11-17 選 D）：Obsidian 的「自動更新內部連結」預設是關的，改名時跳出詢問框；家長選不更新、或用別的方式改名時，快照的連結就失效，照第一次算：第一次至少要 3 個記穩，提示反而少出現，地圖與以前出過的也送不出去。所以外掛收到 `vault.on('rename')`（搬資料夾時裡面每一篇）時，自己把快照 `對象` 裡指向舊位置的連結改到新位置：寫完整路徑的照路徑比；只寫檔名的，現在已經沒有同檔名的卡組才改，改成完整路徑；顯示的名稱是舊檔名的跟著換。只改屬性區 `對象` 那幾行裡雙引號包著的值（外掛自己寫的樣子：一項一行的清單或同一行的值；單引號、沒有引號、flow 清單、後面有註解的不改），本文不動；新路徑有連結放不下的字（`#`、`^`、`|`、`[`、`]`）不改；改完重讀，`對象` 以外的屬性與本文要一樣、`對象` 每一項要是原本的值換過連結的樣子，否則不改（L2 R12）。「自動更新內部連結」開著時不改（Obsidian 會連本文一起改，兩邊同時寫會蓋掉對方）；寫入被擋（備份、手機、載入中、還原）、state 還沒建立或外掛停用中不改，寫入的回呼裡再看一次（L2 R11）；這些時候與外掛沒開著時的改名不補，照第一次算（接受，說明書寫怎麼把連結指回去）。連續改名照收到的順序一次做一個，讀磁碟上最新的快照（L2 R11）。

**提示的基準**＝歸屬這一篇、`工作` 與 `記穩目標` 讀得懂（上一點）、`時間` 是帶時區的合法時刻（拒絕 2 月 30 日這類會被進位的日期，`parseTime`）的快照裡最新的一份：

- 比的是時刻（換成毫秒），不是字串；時刻相同時比 `識別碼` 的字典順序，大的算新；再相同（同一次工作的同步衝突副本）比檔案路徑的字典順序（只決定讀哪一份，都留著；同一次工作送出的記穩集合相同，選哪份影響小）。
- 比現在晚超過一天的 `時間`（時鐘錯）不採用。
- 不看檔名、修改時間、首次看到的時間（〈特別 2〉）。還原只補回舊快照時，較新的那份還在就照新的；較新的那份不見了，就照剩下的（現有格式無法知道曾有較新的工作，接受：最多多提示一次）。
- 初次製卡的快照：基準是空集合，算「第一次」（門檻至少 3 個、文字不說「又」）。
- 同一次工作重試：沿用同一個 `識別碼` 與 `時間`（最小版 §5 已是這樣）。

## 3. 寫進那一篇（要格式查核）

### 3-1 交回的內容放哪（syntax §2-9〈加深的草稿〉）

整理與檢查沿用最小版（`normalizeReply`、`check`；回覆照回覆的格式檢查，寫入後照筆記的格式驗，R3）。卡組段裡的：

| 內容 | 放哪 |
|---|---|
| 新的學習目標（照小標題分組） | 「加深的學習目標」引言框（`> [!note] 加深的學習目標`，不摺起）；框裡照樣用小標題分組 |
| 加進已有的學習目標 | 「加進已有的學習目標（加深）」引言框，接在加深框後面；ID 轉成連結，**只轉這一篇現在的目標**（D-190 第 4 點）；其他 ID 留原文，加入時也不寫到別篇（§3-3） |
| 候選卡片 | 「候選卡片（加深）」引言框（摺起），接在後面 |
| 給家長的備註 | 屬性區後面剛好一個頂層的備註框（「給家長的備註」或「給學習者的備註」）時，接在框的最後，每一項前面加 `加深 <日期>：`，不動框裡原有的字；沒有、不只一個、或框的格式讀不懂時，在這一批的最前面另起一個備註框（R7） |
| 全貌、架構 | 只進快照（D-136 補充：家長不直接改地圖） |

- **一批**：上表的框（備註另起時也算）照順序接成一批，加在檔尾；每次加深是新的一批，舊的不併（舊框可能有家長的字，併了也分不出是哪一次的）。多批可以並存，syntax §2-9 寫明「候選卡片在最後」指的是每一批裡（R3：已經有舊候選框時只追加會違反「候選最後」）。
- **框名帶「加深」**（第二輪 R3）：加深那一批的三種框名都只有加深會寫（「加深的學習目標」「加進已有的學習目標（加深）」「候選卡片（加深）」），和第 1 批、最小版草稿留下的框分得開；待審核（§4-3）、「加入」的限制（§3-3）都照框名認，不靠快照比對。syntax §2-9 寫進這三個框名。
- 新目標與候選的 ID 在寫入前配好（同最小版 §5〈ID 的預留〉），放在名稱行行尾。
- **怎麼接**（R2、第二輪）：換行符照原檔（有 `\r\n` 就全用 `\r\n`）；原檔結尾的空白行（只有空白的行）全部去掉，接**一行沒有 `>` 的空行**，再接這一批；框和框之間也用沒有 `>` 的空行隔開（同一個框裡的空行照樣加 `>`）；寫完的檔以一個換行結尾。檔尾那一行本身行尾的空白不動。
- **擋下不寫**（R2）：頂層有沒關的程式碼圍欄（三個反引號或 `~~~`）時不寫，請家長先修檔（接在後面的東西會被當成程式碼，看不到也加不了）。
- **驗兩次**（R2、第二輪）：① 寫入前，在 `vault.process` 的回呼裡對組好的**候選全文**驗：`parseDeck` 與 `introBoxes` 讀得出每一個新框、項目數對；原本的正式目標的 ID、題目指紋、組別與資料欄位都不變（加備註時行號會平移，比語意不比行號）；備註併進原有的框時，那個框的最後幾項就是這次的備註。不對就傳回原文（沒寫），告訴家長沒寫的原因。② 寫入後重讀一次再驗同樣的事；不對時檔已經寫了，工作進「結果不明」（§3-2）。`introBoxes` 要認得備註框與三種加深框（第 1 批只認候選與加進已有）。
- **回覆裡沒有新內容**：加深的檢查（`check` 的加深模式）接受卡組段沒有任何目標的回覆，只要備註至少一項、或寫了「這一節目前沒有更深的內容」；全貌、架構照樣要（初製的「卡組段不能空」不套用）。

### 3-2 寫入的順序與中斷（R2）

原則（第二輪）：同一次工作最多寫進卡組一次；一旦開始寫過，程式就不再自己重寫，認不出來的交給家長選。「找不到」不等於「沒寫過」（家長可能已經加入或刪掉、iCloud 可能把舊版同步回來），所以不用證據判斷要不要重寫。

1. 複製提示時：存恢復資料（同最小版的工作，多 `deck`：卡組路徑；`ids`：那時這一篇所有目標的 ID；`baseSha`：複製時的全文 SHA-256）。
2. 貼回、檢查過：組好這一批的文字與要寫的快照（`識別碼`、`時間`、內容雜湊），存進恢復資料。
3. **先認快照**：已經有同一個 `識別碼`、內容雜湊相同的快照，就是做完了（快照已寫、恢復資料還沒清），直接到第 6 步，不動卡組。只有 `對象` 不同（改名時外掛或 Obsidian 改了連結，屬性與本文讀出來都一樣）也算同一份；同一個 `識別碼` 而有別的不同時不當成一般的撞名往後加，停下來（L2 R13）。
4. **寫卡組**：恢復資料先記 `writing: true`，再進 `vault.process`。回呼裡對拿到的**最新**全文重驗：
   - 還是這一篇（第二輪）：路徑相同、是卡組、屬性讀得懂、不需要新版；`ids` 的每一個 ID 都還在（家長在中間加了目標、改了字都沒關係，只加在檔尾）；`ids` 是空的時全文要和 `baseSha` 相同。不符合時不寫，提示「這一篇在複製提示之後換了或刪了目標，請重新複製」（改名、搬移也走這一條）。
   - 沒有沒關的頂層圍欄、編輯器沒有還沒存的字（同第 1 批 `intro-run.ts` 的 `unsaved`）。
   - 照 §3-1 組候選全文、驗第 ① 次。
   - 任何一項不過：傳回原文（沒寫），恢復資料拿掉 `writing`，說明原因；家長可以修好再按，或取消。
5. 寫入後重讀、驗第 ② 次；過了就寫快照（同最小版的發布：原文、快照）。
6. 清掉恢復資料。

**重開時恢復資料還在**：先做第 3 步。沒有 `writing` 的，從第 4 步照常做（還沒開始寫過）。有 `writing` 的（寫到一半中斷、或第 ② 次驗沒過），不再寫卡組：

- 這一批有新 ID（新目標或候選），而且全部都在這一篇的加深框裡：當作寫好了，到第 5 步的寫快照（新 ID 是這次才配的，不會和舊內容撞到）。
- 其他情況（只補題、只有備註、新 ID 只剩一部分或都不在）：停在「結果不明」，畫面說明並讓家長選「當作完成」（寫快照）或「放棄」。補題的題目指紋、備註的字可能是舊的同樣內容，不拿來當證據（第二輪）。

- **放棄**：卡組裡已經寫進去的框不拿掉（家長自己決定加入或刪掉；框還在時照 §4-3 算待審核），快照不寫，這次不算一次加深（D-194 第 5 點）。
- 沒有新目標、沒有補題、只有備註或什麼都沒有：照樣成功、寫快照（更新提示的基準）；什麼都沒有時不寫卡組，只通知「這一節目前沒有更深的內容」。
- 兩台電腦各自寫同一篇：第二台在第 4 步看得到第一台那一批時，兩批都留著；看不到時（iCloud 還沒同步）可能有一份被衝突副本蓋掉。不用快照反過來改卡組。
- **限制**（記住）：恢復資料清掉之後，iCloud 才把沒有這一批的舊版卡組同步回來，這一批就不見了，快照仍算加深過一次。程式看不出來；家長可以再按一次「加深」（手動入口不擋）。

### 3-3 「加深的學習目標」的「加入」

第 1 批的對象表多一列（`intro.ts` 的 `BOX_TITLES`）。按「加入」：照 syntax §2-9 已定的行為（§9 第 4 題使用者確認），移到同名的小標題底下：

- **同名**：框裡那一項上面最近的小標題，和本文（引言框以外）的標題比，層級與字都相同（標題字的比法照 `headingKey`）。
- 剛好一個相符：放在那個標題**直屬**的範圍（從標題到第一個子標題、或下一個同級或更高的標題，取先到的）裡最後一個學習目標整項的後面；直屬範圍沒有目標時（例如 `## A` 底下直接就是 `### B`），放在標題的下一行（第一個子標題之前）。不放到子標題那一節的後面（第二輪 R7：`## A` 的目標放在 `### B` 的最後一個目標後面，會被讀成 B 的）。
- 一個都沒有：在本文最後一個學習目標整項的後面新增這個小標題（層級照框裡的寫法），再放這一項。本文沒有目標時放在檔尾的第一批框之前。
- 不只一個相符（`## A / ### 同名 / ## B / ### 同名`）：那一項留著，提示「卡組裡有兩個同名的小標題，請手動搬」（R7：不挑第一個）。
- 搬完驗：用 `parseDeck` 讀搬好的全文，新加的目標歸在預期的標題底下（三種位置都驗：有直屬目標、沒有直屬目標、新建標題）；相鄰目標的題目指紋與組別不變（同第 1 批 §2）。不對就不搬。
- 其他（拿掉框前綴、框空了拿掉、名稱行的 ID 跟著搬、候選的「理由」）照第 1 批 §2；「全部加入」逐項照做。

「加進已有的學習目標（加深）」「候選卡片（加深）」也進對象表，「加入」照第 1 批的同名框（§2、§3）。補題的「加入」（第 1 批 §3）在「（加深）」的框裡多一個限制：目的地只能是這一篇（D-190 第 3、4 點）；ID 找到的是別篇、重複、找不到的，那一項留著，說明原因（逐項的確認框也一樣，準備與寫入時都重驗，R7）。補題的出處裡有 `課外：` 的那一項也留著，請手動搬（出處合併的規則還沒涵蓋課外，R4）。

## 4. 主動提示（D-194）

### 4-1 門檻（D-194 第 4 點）

`pool`＝現在的啟用目標裡不在基準集合（§2-3，或較晚的「這次不用」集合，§5-1）的；`新記穩`＝pool 裡現在記穩了的。條件：`新記穩 ≥ max(⌈pool × 比例⌉, 第一次 ? 3 : 1)` 而且 `新記穩 ≥ 1`。比例是 1/2（§9 第 1 題，修改 D-194 的 1/3）。基準集合裡的目標之後被刪、暫停、變成重複 ID 的，不算進 pool 也不算新記穩。

**試作**（`node experiments/tools/deepen-threshold.ts`，2026-11-17；用外掛的 FSRS，學生每天把到期的卡做完，答對機率是當下的 recall、新卡第一次六成，每個情境 400 次，家長每次提示都按「加深」並加入新目標）：

| 門檻 | 首輪 10 個、每次加 3 個（80%） | 同左、考試期間（90%） | 首輪 6 個、每次加 2 個 | 只補題、沒有新目標 | 每次都按「這次不用」 |
|---|---|---|---|---|---|
| D-194：1/3、首輪 3、之後 1 | 第 8 天；之後間隔中位數 9 天（10%：3 天）；60 天 7 次 | 第 2 天；間隔 3 天；60 天 17 次 | 第 8 天；9 天（10%：2 天）；7 次 | 60 天 3 次 | 60 天 3 次 |
| 1/2、首輪 3、之後 1 | 第 8 天；9 天（10%：9 天）；5 次 | 第 2 天；4 天；12 次 | 第 8 天；9 天（10%：4 天）；6 次 | 3 次 | 3 次 |
| 1/3、首輪 3、之後 2 | 第 8 天；9 天（10%：3 天）；7 次 | 第 2 天；3 天；17 次 | 第 8 天；9 天（10%：4 天）；5 次 | 2 次 | 2 次 |
| 穩定度 10 天、1/3 | 第 8 天；9 天（10%：9 天）；5 次 | 第 2 天；3 天；14 次 | 第 8 天（90%：23 天）；9 天；5 次 | 3 次 | 3 次 |

- 第一次幾乎一定在第 8 天：80% 時第一次答對的下一次在第 8 天，第二次答對穩定度就到 22.8 天。考試期間（90%）第 2 天就複習第二次，穩定度 11 天，中位數第 2 天就到；但這是模擬裡每天都做完、每次都答對的結果，不是保證（1/2 的第 90 百分位是第 9 天，第二輪）。
- **看得到的差別**：改成 1/2 後，一般情況的間隔中位數不變（9 天），間隔的第 10 百分位從 3 天變 9 天，60 天的提示中位數 7 → 5 次；考試期間 17 → 12 次（R8 重跑確認）。pool 只剩 1～2 個時，1/2 仍然記穩一個就問。
- 首輪只有 1～2 個啟用目標時全部記穩也到不了 3，不會提示；手動命令照常可用。
- 限制（R8）：模擬的學生每天都做完、同一批同時到期、答錯一分鐘後一定答對、提示當天就加深、沒有時間上限與積欠；兩組門檻抽到的作答不配對。只能比較門檻之間的差別，不能當成真實的頻率。

### 4-2 提醒一區的那一行（D-194 第 7 點）

- 一篇一行，篇名照 D-189 第 3 點：「L3 單字：有 6 個記穩了，要加深嗎？」，基準是加深時「又有 6 個記穩了」；按鈕「加深」「這次不用」；旁邊一句說明（同 §1 第 2 點）。
- 狀態列每篇算一項（`ReminderView.count`）。
- 開關關掉（§5-2）時不出現；手動命令照常。
- 點下去時重驗（〈特別 6〉的表最後一列）：門檻、待審核、生成中都重新算，條件已經不成立就通知並重畫。
- 只在電腦；`reminderView` 在 iPhone 不算這一項。

### 4-3 生成中與待審核（D-194 第 8 點、〈特別 3〉）

| 狀態 | 怎麼認 | 那一行 |
|---|---|---|
| 等待貼回 | 這台電腦有這一篇還沒完成的加深工作（§3-2 的恢復資料） | 「L3 單字：加深的提示已複製，等你貼回」＋「打開」「取消」 |
| 待審核 | 這一篇有任何一個加深的框（§3-1 的三種框名，哪一批都算）裡還有項目：名稱行（新目標、候選）或補題的題目行 | 「L3 單字：上一次加深的結果還沒審完」＋「打開」 |
| 可以加深 | 門檻成立、不在上面兩種 | §4-2 |

- 待審核只看卡組本身（第二輪 R3）：不看快照、不分哪一批。D-194 第 8 點的「還沒處理完的加深結果」就是加深框裡還沒加入或刪掉的項目，較早一批沒處理完也算；家長按「加入」、或刪掉框裡那幾項就解除。空框、框裡只剩家長自己的字（不是名稱行或題目行）、備註框都不算。
- 第 1 批與最小版草稿留下的框（框名沒有「加深」）不算，不擋提示。
- 另一台電腦寫好的加深框，卡組同步過來就看得到待審核，不用等快照。
- 「放棄」的工作（§3-2）留下的框照樣算待審核：結果已經在卡組裡，家長加入或刪掉才解除。
- 另一台電腦正在等待貼回的，這台看不到（v1 接受：D-194〈代價〉的兩台電腦；只在兩台同時發起才有影響）；兩邊都寫進同一篇時，第二份照 §3-1 另起一批，兩份都留著。

## 5. 這台電腦的偏好（要格式查核：讀寫契約）

沿用 `src/ui/prefs.ts`（`app.saveLocalStorage`，Obsidian 依 vault 分開存，不同步）。

### 5-1 「這次不用」（R6）

- 存 `{ [卡組路徑]: { ids: string[], at: string } }`：按下時的記穩 ID 集合（去重、照 ID 排序）與時間（帶時區，同快照的寫法）。
- 門檻用的基準：`at` 比 §2-3 的基準快照 `時間` 晚（比時刻，相同時算快照的）就用這一份；快照被刪也照樣用它。
- 按過「這次不用」不算加深過：下一次還是第一次就照第一次的門檻與文字（至少 3 個、不說「又」）。
- 卡組改名、搬移：聽 `vault.on('rename')` 把鍵換成新路徑（目的地已經有舊值時蓋掉）；刪除：聽 `vault.on('delete')` 拿掉那一鍵。Obsidian 關著時改名對不上：那一篇的這次不用失效，可能多出現一次（接受）。
- **路徑重用**：讀的時候，存下的 `ids` 和這一篇現在的目標 ID 一個都對不上，就當這一鍵不存在（刪了再建同名的新篇照第一次）；有對上的照用。同一條規則也用在快照（§2-3）。代價（第二輪，接受）：真的同一篇、家長刪光當時記穩的目標，「這次不用」就失效，門檻照快照的基準重算；離線複製重建、帶著一個舊 ID 的新篇會沿用舊值。`ids` 是空的（按下時沒有記穩的）照路徑用。
- **快照被刪、只有這一份**：門檻用它的 `ids` 當基準，但看不出以前加深過沒有，照第一次的門檻與文字（至少 3 個、不說「又」）。
- 讀的時候：外層不是物件就整份當沒有；某一篇的值壞了（`ids` 不是 ID 字串陣列、`at` 不是合法時刻）只略過那一篇。
- `localStorage` 依 vault 分開（Obsidian 的 `saveLocalStorage`）：Windows 實機驗兩個 vault 同路徑的卡組互不影響。

### 5-2 總開關

- 設定頁「這台電腦的加深提醒」，預設開（存 `essence-cards-deepen-remind-off`，只有存的是 `true` 才算關，缺值或壞值是開）；說明「關掉後仍可用命令『加深這一節』」。
- 關掉不取消正在做的、不刪引言框、不拿掉命令；再打開時保留每篇的「這次不用」（D-194 第 9 點）。

## 6. 課外層：標法與佇列（技術債「課外層的目標要算延伸」）

**已做**（`f695b5f`，第二輪 R4 的修正在其後；`tests/ai-deepen-mastery.test.ts`）：

- **標法**（§9 第 2 題）：出處裡寫 `課外：<可以查的來源>` 一項，例如 `出處：p.44、課外：高中基礎物理 熱學`。
  - **切項**：以頓號為界；`課外：` 前面是空白或逗號、分號、斜線時也切開（`p.44 課外：…`、`p.44，課外：…`），課外那一項到下一個頓號為止。連結裡的頓號不切（`課外：[[甲、乙]]` 是一項）。卡組的讀法與 `check` 用同一個切法（`splitSourceItems`）與同一個前綴判斷（`outsideSource`，第二輪）。
  - **前綴**：`課外` 與冒號之間可以有任意空白，冒號全形半形都可以。在位置、單元、否定的判讀之前認。
  - **不改前後的承接**（第二輪）：課外那一項只顯示、不連、不算單元，前後的出處照沒有它時的意思讀：`國二上 1-3、1-8、課外：高中課本、p.44` 的 p.44 仍屬 1-8，`p.44、課外：高中課本、46` 的 46 仍是頁碼。（`先備：` 照舊會斷開承接。）
  - **沒寫來源**：`課外：`、`課外：；` 這種去掉空白與標點後是空的，不算延伸（當成沒確認的出處，照課內排）；`check` 報 `source-outside-empty`。
  - 和 `[AI 補充]`、`先備：` 分得開；`check` 不報 `source-unknown`。
- **算延伸**：出處的每一項都是有寫來源的 `課外：`（`isOutside`；分行寫的每一行也一樣）。有一項是教材的位置、別的單元、`先備：`、連結就不算；沒有出處的不算。
- **佇列**（D-136 第 4 點、D-142 第 5 點）：考試範圍不算延伸的目標（`targetsInScope` 跳過；範圍的提示 `scopeCheck` 也不列它）：不提高保持率、新卡與到期的排在範圍內的後面。範圍生效時（有沒有考試日期都一樣），延伸目標的重學也不排最前面，改進一般的到期那一條（R5）。沒有生效的範圍時照常。
- **比較卡的例外**（§9 第 5 題）：同一組比較卡裡有課內也有課外的目標時，整組照現在的排法一起出，課外那張跟著課內的排在前面（佔今天的時間）；不拆組、不擋這種寫法。

**還沒做**：
