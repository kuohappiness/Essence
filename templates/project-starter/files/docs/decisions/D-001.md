# D-001 這個專案採用這套初始架構

✅ 【待填：日期，YYYY-MM-DD】｜使用者提出

一句話：這個專案從一份通用的初始架構開始：一份短的全專案規則、一頁工作流程、三類入口文件、三個 skill，以及擋得住改不回來的事的幾道防線。

## 決定

1. 規則寫在 `AGENTS.md`，工作流程寫在 [docs/workflow.md](../workflow.md)，程式品質的專案設定寫在 [docs/agents/quality.md](../agents/quality.md)。
2. 進度放【待填：repo 的檔案，或 GitHub Issues】。
3. 規劃、實作、獨立查核分別由【待填：各由誰做】擔任。
4. 第一次設定時填的答案：【待填：第一個 session 問完的重點，一題一行】

## 理由

- 每個新專案從頭建流程，每次花時間，結果每次不同；用一份做過、驗過的初始架構，第一天就有防線與固定的做法。
- 只帶小專案用得到的部分；專案長大到某些條件，才照 [workflow.md〈成長條件〉](../workflow.md#成長條件) 加。

## 曾考慮的做法

- 不做：從空的 repo 開始，邊做邊建流程；前幾週只靠口頭提醒把關，金鑰外洩、force push 這類改不回來的事沒有防線。
