# 第二個子專案

條件：同一個 repo 裡出現第二個可以各自使用的軟體或服務。

## 加什麼

- **資料夾**：每個子專案一個資料夾（例如 `apps/<名稱>/`），裡面有自己的程式、測試、套件設定，以及自己的 `AGENTS.md`（只寫這個子專案特有的規則，`CLAUDE.md` 一行 `@AGENTS.md`）。
- **文件放哪裡**：只和一個子專案有關的，放它自己的 `docs/`（roadmap、backlog、任務說明）；兩個以上或全專案的，放最上層。決定一律放最上層的 `docs/decisions/`，編號接續；每條寫一行「適用：<子專案>／全部」。
- **最上層的 roadmap 是入口**：〈現在在哪裡〉放跨子專案的工作，並連到每個子專案 roadmap 的〈現在在哪裡〉。
- **專用的品質設定**放子專案自己的 `docs/quality.md`，標題和最上層的 `docs/agents/quality.md` 對應，最上層同名標題下留一行指過去。
- **子專案之間不互相 import 程式**：共用的程式放共用的資料夾（例如 `packages/<名稱>/`），用相對路徑引入；加一項檢查擋跨子專案的 import。
- **只檢查改到的對象**：提交前與 CI 照改到的路徑決定跑哪個子專案的檢查；改到檢查本身（hook、CI、共用的工具）或判斷不了的路徑，全部都跑。CI 最後的 `gate` 要分得出「照規則跳過」和「漏跑」。這張對照表只寫一份，提交前與 CI 讀同一份。
- `AGENTS.md`〈開始工作前〉加一行：做某個子專案時，先讀它的 `AGENTS.md`，再讀它的 roadmap。
