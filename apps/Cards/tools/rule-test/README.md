# 製卡規則的比較測試工具

給操作的 Claude：怎麼跑。規格（設定的格式、指標、門檻、驗收）只寫在[任務說明](../../docs/tasks/rule-test-tool.md)，這裡不重寫。

## 底線

- **在使用者電腦跑**：要讀 vault 與教材（D-212 第 4 點）。本機 session，或雲端串開 Remote Control。
- **測試資料夾與課庫放 repo 外面**：教材、vault 快照、原稿、評分表、評分都是私人資料（D-003）。工具會擋在 repo 裡建資料夾。進 repo 的只有 `結果/摘要.md` 的數字，寫進[試用紀錄](../../docs/card-rules/trials.md)與任務〈結果〉；vault 名稱與私人路徑不寫進 repo（repo 是公開的）。
- **使用者只做三件事**：同意開跑的用量、貼 ChatGPT、答教學選擇。其他由操作的 Claude 做。
- **凍結後不改**：`測試.yaml`、凍結的提示、評分表、範本改了，之後的指令會停下並說是哪個檔。要換規則或設定就開新的測試資料夾。

## 準備

- 在 `apps/Cards` 跑 `npm ci`。指令都是 `npm run rule-test -- <指令> <測試資料夾> …`，也在 `apps/Cards` 跑。
- `claude` 與 `codex` 要裝好、登入。不在 PATH 上時，用環境變數 `CLAUDE_CLI`、`CODEX_CLI` 指向執行檔。Claude 桌面版內建的 `claude.exe` 沒有自己的登入，不能用；要另外裝 Claude Code CLI 並登入（2026-11-25 探針）。
- 新電腦或 CLI 改版後，先跑一次探針，把結果和任務說明 §9 比：

  ```
  npm run rule-test -- probe <教材.pdf> <輸出資料夾> [--pages <頁數>] [--skip-long] [--clipboard]
  ```

  輸出資料夾也放 repo 外面。結果在 `probe.md`，每個探針的原始回覆在 `raw/`。
- 剪貼簿（P9）加 `--clipboard` 才測：會暫時借用使用者的剪貼簿，先告訴使用者。剪貼簿裡有圖片或網頁格式時不借；放不回去時，原本的內容存在輸出資料夾的 `剪貼簿原本的內容.txt`，請使用者複製回去再刪掉。

## 一輪的步驟

隨時可以跑 `status <測試資料夾>`：每一步做到哪裡、下一步是什麼、背景工作的進度。每個指令重跑都安全：做過的跳過，凍結過的檔不覆蓋。

1. **建資料夾**：`init <測試資料夾>`，照 `測試.yaml` 裡的註解改。設定的寫法見任務說明 §4-2，門檻見 §6-3；重大錯誤的門檻預設「不比基準多」（D-234），要改成「零」先問使用者。
2. **課庫**：每課一個資料夾 `<課庫>/<課代號>/`，放 `教材.pdf`（只含這一課的頁）。評分表做好後也放這裡（第 4 步）。
3. **凍結**：`freeze <測試資料夾>`。凍結已有目標、各組提示、範本與設定的雜湊，印每組規則與整份提示的字數。外掛來源用到的檔有沒 commit 的修改時會停下。印出「用過的課」警告時，那一課之前解開過、規則又是之後改的，只能當回歸，不算新課；回報時照寫。
4. **評分表**（課庫還沒有這一課的評分表時）：
   1. `rubric <測試資料夾> <課>`：印要開的 3 個對話。告訴使用者，同意用量後加 `--confirmed`（在背景跑；`--foreground` 在前景）。
   2. 做完看 `評分表/<課>/` 裡的 `1-寫.md`、`2-核對.md`、`3-回應.md` 與草稿 `評分表.md`。不接受的意見、類別拿不準的列，問使用者。
   3. `rubric <測試資料夾> <課> --accept` 存進課庫。之後要改就存成新版（任務說明 §5-2），開新的測試資料夾。
5. **生成**：`generate <測試資料夾>` 印要開幾個對話、提示共幾字。使用者同意用量後加 `--confirmed`。
   - 手貼的（ChatGPT）：說明寫在 `生成/手貼/<工作>.md`（服務、模型、推理、附哪一份 PDF、照順序貼哪幾段）。請使用者照著貼，回覆複製後跑 `paste <測試資料夾> <工作> [<步>]`（讀剪貼簿；`--file <檔>` 讀檔）。多步的，貼完前一步才會產生下一步的提示。
   - 沒有 `<<<完>>>`、卡組段是空的原稿是無效原稿，工具自動補一份並記下；不要自己挑哪一份重跑。
   - 額度用完、連續 3 個失敗時佇列停下。等額度回來再跑同一個指令，做完的會跳過。
   - 同一份試滿 3 次（失敗、逾時、中斷都算一次）就放棄，`status` 列出原因；放棄的還在就不能匿名。看過原因、決定再試就加 `--retry`（再給 3 次）。不要改事件檔。
6. **格式**：`check <測試資料夾>`。用外掛的檢查記錄每份原稿的格式，不改原稿。
7. **匿名**：`blind <測試資料夾>`。這時鎖住評分表的雜湊。停下列出洩漏字樣（組名、模型名、`<<<`）時，逐條看：是誤報才加 `--accept-leaks` 重跑；真的洩漏就先告訴使用者。
8. **評分**：`judge <測試資料夾>`，同第 5 步先印計畫、同意後 `--confirmed`。兩位評審都交齊時自動鎖定（`評分/批N/鎖定.md`）。設定了 `評審重評` 的，重評的對話也在這一步跑。一個評審對話在同一個對話裡補正兩輪還不合格，算試了一次；重跑同一個指令會再試。試滿 3 次就放棄，這一批鎖不了：看 `status` 列的原因與 `評分/批N/紀錄/` 的對話紀錄，決定再試就加 `--retry`。
9. **裁定**：`disputes <測試資料夾>`，同上先印計畫、同意後 `--confirmed`。做完寫 `評分/批N/裁定.md`：
   - 只有一位評審記的重大錯誤，各開一個隔離的對話裁定。對話失敗的格子，照 `templates/裁定說明.md` 的定義判了填上。
   - 拿不準的記錄分成「照口徑」與「教學選擇」。教學選擇問使用者，答案照表上的寫法填進「使用者的選擇」（照原樣、拿掉 R5、R5 改加分、R5 改必備）。
   - 這個檔只寫一次，重跑不會蓋掉你填的。
10. **解開**：`unblind <測試資料夾> [--batch N]`。核對鎖定、裁定都填好、格式檢查做過才解開。寫 `結果/批N.json`、`明細.md`、`明細.json`、`摘要.md`，並在每課的 `使用紀錄.md` 加一行。
11. **回報**：把 `摘要.md` 的門檻結果與平均表寫進試用紀錄與任務〈結果〉，附解開的 commit。`明細.*` 有評分表與卡組的原文，只留在使用者電腦。門檻「未定」或兩批結果翻轉時，照任務說明 §5-10 補跑，不要自己下結論。
12. **追原因**（要的話）：解開後才打開原稿的全貌與架構，用下面的提示。

## 補跑

- **同一課多跑幾份**：`extend <測試資料夾> <課> <生成器> <份數> <原因>`。上一批的工作要先做完。追加的份數成為新的一批，照第 5～10 步跑（`blind` 只匿名新的一批）。報告會標出後來才補的批，和各批之間門檻結果翻轉的地方。
- **加另一課**：`init <新的測試資料夾> --from <這一輪的資料夾>`，只把「課」換掉。凍結時會核對：除了課以外的設定、範本、規則都要和那一輪相同，課也不能重複；不同就停下。
- **換規則**：開新的一輪（`init` 不加 `--from`）。

## 還沒做的

- `materials`（把教材轉成頁面圖）不做：`claude` 與 Codex 都讀得了整份 PDF（2026-11-25 探針，任務說明 §5-1、§9）。CLI 改版後探針的 P3a 或 P6 不過，才照 §5-1 做。

## 手動用的提示

不做成指令（任務說明 §10）；要用時開新的對話，貼下面的提示。

**追原因**（解開以後）：

> 這份卡組在評分時漏了下面這些必備的列，也有下面這些錯。附件是同一份原稿的全貌與架構、它的提示和教材。逐項找出漏在哪一步（全貌沒列、架構沒排、卡組沒寫，或寫了但評審判沒有），引用原稿的那一行；最後歸納成幾類，說每一類是規則沒寫、寫了沒照做，還是評分表的問題。不要提改規則的方案。

附上：`明細.md` 裡那一份的「漏的必備」與重大錯誤、`生成/原稿/` 裡那一份的原稿、`凍結/提示/` 裡它的提示、教材。

**第二道查核**（新的對話，沒看過評分；第一輪的寫法，見[第一輪任務說明](../../docs/tasks/rule-restructure-test.md) §11）：

> 逐項對照教材，只交附頁碼的修改清單：哪個目標或題目、改成什麼、為什麼（漏了、教錯、洩漏、多解、重複、ID 指錯）；加題要確認是新題、ID 指對，疑似重複逐項決定，不要重寫整份。

附上：教材、`凍結/已有目標/<課>.json`（含整個題目池）、那一份的卡組。記下用量與時間。
