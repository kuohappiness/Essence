## 行為與風險

**寫進使用者資料的（最先看）**

- 加深的快照（`src/core/ai/deepen-job.ts` 的 `deepenSnapshot`、共用的 `src/core/ai/snapshot-api.ts`）：證據在 `beginDeepen`（第 2 步）就放進 `save.api`，快照在這一步組好；欄位與位置和製卡的 API 快照相同。不可破壞：複製貼上的加深快照逐字和改之前一樣；製卡的 API 快照逐字和第 2 批一樣（`apiFields` 從 `publish.ts` 搬出來）；`v0.6.0` 讀得到新的加深快照、改名後 `retargetSnapshot` 與 `sameButTargets` 照舊。
- 恢復資料（`DeepenJob.api`、`DeepenSave.api`）：讀不懂的 `save.api` 停在 `newer`、不寫任何檔；讀不懂的 `job.api` 當成一般的待貼回。不可破壞：`v0.6.0` 存的與舊的加深工作照舊讀得到；`isDeepenJob` 不看 `api`；ID 的預留（`reserved`）不受影響。
- 原文：家長改過字時，收到的與存下的兩段都存（`runDeepen` 的原文那一步）。
- 寫進卡組：收到的回覆走和貼上的同一條路（`inspectDeepen`、`composeBatch`、`runDeepen`），寫出的卡組逐字相同。

**送出（`src/obsidian/deepen.ts`）**

- 提示和「複製提示」逐字相同；教材檔選填，選了照 §5 擋；送出前擋下時不建工作。
- 同一篇上一次直接送出還沒處理完時，「直接製作」與「複製提示」都擋下（F14 第 2 點）。
- 先存工作再送；一次只送一個；取消、停用外掛時中止；取消的不記錯誤紀錄。
- 重送用同一份提示；這次開著 Obsidian 的期間記得教材檔，上一次沒附教材的不用重選，重開過、有附的要重選。
- 按「寫進卡組」時只用存放裡和畫面手上的是同一次的證據（同製卡的 T1）。

**畫面（`src/obsidian/deepen-modal.ts`、`direct-ui.ts`、`ai-cards-modal.ts`、`main.ts`）**

- 加深的第一步多教材檔與「直接製作」（電腦才有）；送出前那一行用表單打開時讀的那一份算。
- 送出中、送不成、重送、收到的畫面和製卡的相同；重開時直接送出還沒有結果的，打開「重送／改用複製貼上／取消這次加深」。
- 製卡視窗改用共用的零件，行為不變（它的測試沒改）。
- `main.ts`：製卡與加深共用同一份連線（`directHost` 只建一次）。

**請找新的組合**，例如：收到後家長改字再按檢查、寫到一半中斷再「繼續」；加深視窗與製卡視窗同時送出；收到之後才改了卡組（目標被刪、改名）；送出中刪掉或改名那一篇；收到之後「這次不用」或總開關；重開後的重送畫面「回上一步」；改用複製貼上之後又重送；一篇的工作在寫、另一篇送出；提醒一區的加深列在直接送出的工作上顯示什麼。

## 實作者自己選的做法

請先看這些：

1. **防重擋住複製提示**：F14 第 2 點只說「不再做一份新的」；這裡連「複製提示」也擋（新的一份會把已經付過錢的那一份無聲地換掉）。一般複製的待貼回照舊被換掉。
2. **證據的凍結**：`save()` 用 `received` 參數決定要不要帶證據，並和畫面手上那一份比 JSON（同製卡的 T1），對不上當成複製貼上。
3. **一次只送一個**是每個流程各自算：加深與製卡可以同時各送一個（各自一個視窗）。
4. **送出前那一行**用表單打開時讀的 `context`（方向、教材說明、點選填空改了就重組）；按下「直接製作」時重讀一次最新的。
5. **重開後沒有結果的**打開的是重送的畫面，不是貼回的框（第 2 批的製卡是清單上的按鈕）。
6. **共用零件**：`direct-ui.ts` 只放畫的東西（教材欄、送出中、取消那一列、時間），流程仍各自一份（`ai-cards.ts`、`deepen.ts`）。
