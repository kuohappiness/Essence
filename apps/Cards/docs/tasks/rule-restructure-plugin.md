## 4. 貼回時擋同名、加題時列出原有題目

D-229 第 2 點，不等比較測試。只做第一次製卡的貼回；加深的貼回不在這份。

### 4-1 同名的新目標（開工前等格式查核）

**什麼算同名**：貼回的每一篇裡，有名稱行的新目標（不含最上層直接寫題目的、候選卡片、加進已有的那一項），和這次送出的已有目標（`sent`）比：

- 英翻中、中翻英：方向相同、字相同。字的取法和 `learnedWord` 相同（名稱去掉方向、去掉成對的粗體與螢光筆、再去掉最後一組全形括號），用 `pickKey` 比（大小寫、全半形、連續空白不分）。
- 其他（英文的文法、變化、比較，其他科的全部）：整個名稱用 `pickKey` 比。

**畫面**：檢查沒有擋住的錯誤之後，貼回的畫面另列一區「和孩子已有的學習目標同名」，每一項一列：左邊是新目標的名稱與第一題，右邊是已有的 `ID 名稱｜出處｜第一題`（`sent` 存的），兩個按鈕「併進已有的」「是不同意思」。每一項都選了才能存草稿。同一個新目標對到好幾個已有目標（已有的本來就同名）時，每一個已有的各一個「併進」按鈕，加一個「是不同意思」。重貼或改了回覆，選擇全部重來。

**選「併進已有的」**：卡組（不是快照）裡把那個新目標整項（名稱行與它底下的範圍）搬進同一篇的「加進已有的學習目標」引言框，名稱行改成 `- <ID> <已有的名稱>`，其他行原樣、每行前面加 `> `，相對縮排不變。那一篇沒有這個框就照 [syntax §2-9](../syntax.md#2-9-ai-製卡交回的草稿) 的順序建一個（學習目標之後、候選卡片之前）。之後照一般的加題處理：存草稿時轉成連結、家長按「加入」才寫進已有的卡組。R3 的全貌、架構段不改。

- 一篇搬完沒有新目標了：那一篇不建，它的加題與候選搬到最後一篇還有新目標的那一篇的最後（和英文規則〈分篇與檔名〉要 AI 做的一樣）。每一篇都沒有新目標：存不了草稿，畫面寫「這一次沒有新的學習目標，存不了草稿；要加的題目請直接到那一篇加」（現行就有的限制，[next/README](../card-rules/next/README.md#codex-契約查核2026-11-24) 第 1 項）。

**選「是不同意思」**：照原樣存成新目標。

**快照**（提案，請格式查核判斷）：快照本文照 AI 的原文，不搬；併進的那一項名稱行不配 ID。`程式改動` 多兩種寫法：`第 N 行 併進 <ID>（家長選）`、`第 N 行 和 <ID> 同名，家長選不同意思`（N 是原文的行號，和現有的「拿掉」同一套）。syntax §6 那一段跟著改。

**中斷後繼續**：選擇在做出全文之前定好；存草稿的恢復資料存的是做好的全文，中斷後按「繼續」不用再選。

### 4-2 加題時列出原有題目、英文單字核對意思

- 和那個目標已有的題完全相同的不加：現在就是這樣（syntax §2-9「已經在的不會再加」，`src/core/ai/existing.ts` 的 `missingOf`），補一個測試釘住。
- 新：引言框「加進已有的學習目標」每一項，在「加入」按鈕同一處列出那個目標現在的題目（唯讀，一題一行，寫法同 `firstLine`；超過 5 題先收起，「還有 N 題」點了展開）。第一次製卡與加深的框都有。找不到那個 ID（框裡已經寫了原因）時不列。只在電腦，和「加入」一樣。
- 為什麼：比較測試裡現行、候選、ChatGPT 都有把題目加到判準不合的已有目標（[比較測試](rule-restructure-test.md) §9 第 3 點）。使用者 2026-11-25：家長基本上不會改題目，所以並排不是防線，防線放在規則與之後的背景查核（§9 第 3 點）；並排照 D-229 留著，想看、想改的家長保留這個彈性。
- 新：**英文單字加題核對意思**（[兩段送法檢討](<../Claude Codex Discussion/2026-11-25-two-stage-sending-review.md>) 方案 1；使用者 2026-11-25 同意加題改保守、畫面保留彈性）。比較測試裡加錯目標是英文門檻 1 沒過的唯一原因，「完全相同不收」在 224 題加題裡擋到 0 題。
  - 對象：框裡加到英文單字目標的那一項（目的地名稱結尾是 `英翻中` 或 `中翻英`）。文法、變化、比較與其他科不查。
  - 比什麼：英翻中比答案（`::` 後面）；中翻英比題幹最後一組全形括號裡的中文。新題和那個目標**每一題**的同一處比，只留中文字、再拿掉「的」「地」「得」（詞性標記、標點、空白、英文字母自然去掉）。新題和每一題都沒有共同的字，標「意思可能不同」。新題或舊題取不到中文的不標，照現在。
  - 標了的不進「全部加入」（和「沒轉成連結的不進全部加入」同一個機制），留在框裡：寫一行「這一題的意思和這個目標原有的不同，確認是同一個意思再加入」，旁邊照上一點列出原有題目。家長不處理就是不加；想加的照舊按那一項的「加入」。
  - 每次畫框時照目的地現在的題目算，不存進筆記，存下來的格式不變（不在[格式查核](rule-restructure-plugin-format-review.md)的範圍）。
  - 拿不準的代價：中文同義詞沒有共同的字會誤標，那一題改成逐項加。檢討的試算在比較測試的 12 份英文原稿標出 3 題，其中 2 題是已知的加錯。

### 4-3 驗收

D-195 第 1 類（寫進使用者筆記，做足才合併）：

- 同名的判斷，每一個都寫成測試：
  - `light 英翻中` 對 `light 英翻中`：同名；對 `light 中翻英`：不同名。
  - `light（輕的） 中翻英` 對 `light 中翻英`：同名（家長再選是不是不同意思）。
  - `**Light** 英翻中` 對 `light 英翻中`：同名。
  - `lie（躺） 過去式` 對 `lie（躺） 過去式`：同名；對 `lie（說謊） 過去式`：不同名。
  - 社會名稱只差全形、半形空白：同名；只差一個字：不同名。
  - 候選卡片、加進已有的那一項、最上層直接寫題目的：都不檢查。
  - 已有的兩個目標同名：兩個都列出來。
- 沒選完存不了；重貼之後選擇清空。
- 併進之後的卡組：那個目標從本文不見；框裡那一項讀回來的題目與補充，和原本那個目標的完全相同（用 `existing.ts` 讀框裡一項的同一套讀法比）；其他行逐字不變。按「加入」後，已有的卡組多出的正好是它還沒有的題目。
- 一篇搬空、全部搬空兩種情況照 §4-1。
- 同一份回覆、同樣的選擇，做兩次全文逐字相同；中斷後繼續不再問。
- 快照的本文與 `程式改動` 照格式查核定案後的寫法，預期值寫成字面值。
- 0.6.0 讀得懂存下來的草稿與快照（`git show v0.6.0:<路徑>` 的解析器跑一次）。
- §4-2：框裡每一項列出的題目和目的地現在的題目相同；一題完全相同的加題按「加入」後目的地不變。
- §4-2 意思核對，每一個都寫成測試（預期值是字面值）：
  - `light 英翻中` 原有答案「光」「燈」：新答案「輕的」標；「光線」不標；「n. 光」不標。
  - 原有答案「明亮的」：新答案「輕的」標（「的」不算共同的字）。
  - `light 中翻英` 原有 `Turn on the ＿＿.（燈） :: light`：新題 `This bag is ＿＿.（輕的） :: light` 標；`The ＿＿ is on.（燈） :: light` 不標。
  - 新題取不到中文（中翻英沒有全形括號）：不標。
  - 目的地是文法或其他科的目標：不查。
  - 「全部加入」略過標了的那一項、其他照加；按那一項的「加入」照加；框裡寫出那一行原因。
  - 在使用者電腦（經 Remote Control）：比較測試的 12 份英文原稿套這個檢查，標出的包含檢討記下的 2 筆加錯、總數不超過 5。只回報數字。
