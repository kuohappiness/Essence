## 使用者已經選的（決定卡，2026-11-28）

1. **紀錄要不要連那張卡當時的原文一起存**（改不回來：當時沒存的，事後補不回）。**使用者 2026-11-28 選「存原文」**（Claude 建議的）。理由：使用者兩批的意見多半在詳解，題目指紋（[syntax §2-8](../syntax.md#2-8-題目指紋)）與快照的比對（[syntax §6](../syntax.md#6-ai-輸出快照)「比對只看題目和答案」）都不看背面；只存 ID 與指紋，詳解之後被改過，就分不出使用者評的是 AI 原稿還是改過的版本，D-246 第 3 點「生成後被人改過的卡標出來」對背面做不到。寫在 §2 的 `card`。
2. **外掛版要不要加可以點的標籤**。D-246 第 3 點：開發階段不給，跑兩三批後把常見的做成標籤給外掛版用。兩批的意見歸類後（§6-2、§8-7 的表，一則可歸好幾類，共 47 筆），只有 1 筆（例句用的名字）不在這四類：**詳解**（沒講為什麼、背面看不懂、容易混的沒並排比、背面太多，共 18）、**版面**（16）、**考點**（考點不清楚、太多說法都對、題型該換，共 9）、**不值得考**（3）。**使用者 2026-11-28 選「加四個標籤」**（Claude 建議的）：點了「要改」或「不要這張」才出現，可以複選，一句話照樣可以寫；手機上點一下比打字快，AI 抓不到的問題仍然寫在一句話裡。代價是 D-246 擔心的「引導人只看那幾類」，靠一句話留著、品測模組讀到「只有標籤沒有一句話」時不推論原因來減輕。寫在 §2 的 `tags`、§3-2。
3. **格式查核由誰做**：Codex 的週額度 2026-11-30 才重置，**使用者 2026-11-28 選「現在請 Fable 5.2 high 查」**（[回報](<../Claude Codex Discussion/2026-11-28-card-feedback-format-review.md>)）。合併前的 L2 照舊用 Codex。
4. **從備份還原時回饋檔怎麼處理**（查核 F5：是 D-150 第 7、8 點與 D-155 第 6 點之外的新例外，回饋又是人寫的）。**使用者 2026-11-28 選「不列也不補回」**（Claude 建議的，和錯誤紀錄同一處例外）。寫在 §4-3、[syntax §11](../syntax.md#11-回饋紀錄)。

其餘是 Claude 的建議，2026-11-28 在串裡列給使用者、寫明照建議做（使用者還沒回；看過有意見再改，不算使用者同意）。回饋只在預覽、開關預設關、每台裝置各自打開、一台裝置一個月一個檔，是 D-246 與 D-163 第 6 點已定的；另外幾件：

## 和「不做」比較（D-153、D-177）

- **不做會怎樣**：每批卡由 Claude 另做一個手機回饋頁。兩批都碰到和外掛不一樣的地方（第 1 批比較題沒列選項、例句沒分行；第 2 批前 24 張的題目擠在一行，7 張受影響，§8-7〈限制〉），版面的意見要事後扣掉；卡號要對回 ID，回饋只在 Claude 準備一批時才收得到。家長自己做完一課 AI 卡、在預覽看的時候，想到的意見沒有地方留。
- **做了**：看到的就是複習畫面真正的樣子；ID、指紋、卡組、當時的原文由外掛帶入；做完一課、預覽時就能留，不用等 Claude 做頁。學習效果是推論：回饋只用來找問題的類別（D-246 第 6 點），規則有沒有因此變好要照比較測試量。
- **代價與解法**：
  - 一種新的紀錄檔：外掛只寫不讀，不進讀取閘門；格式查核與 L2 照上面。
  - 預覽畫面多一列：只在預覽、只在打開開關的裝置；孩子的複習畫面完全不變（學生回報照 [D-160](../../../../docs/decisions.md#d-160-學生在複習畫面回報問題點一個選項記進錯誤紀錄)）。
  - 一個設定：照 [D-161](../../../../docs/decisions.md#d-161-預覽卡片不記錄不動排程設定頁打開才有)、[D-163](../../../../docs/decisions.md#d-163-入口與目錄的四批開法全部卡的一輪與提醒一區) 第 6 點，只存在這台裝置，預設關。
  - iPhone 上的鍵盤、語音輸入與擠不擠：一次 iPhone 實機（§6）。
- **第 2 類**（[D-195](../../../../docs/decisions.md#d-195-測試分兩類改不回來的做足其餘延後但不漏)）：§1「晚一版」的功能與 iPhone 實機以外的少見情況，記進[技術債](../backlog.md#技術債)。寫不進去時這一列標「沒存到」，家長點「再存」就再寫一次（§2-3），不會悄悄丟掉。

## §2 紀錄的格式（格式查核的範圍）

格式定稿寫在 [syntax §11](../syntax.md#11-回饋紀錄)，這裡不重寫一份（[D-141](../../../../docs/decisions.md#d-141-文件架構入口只放狀態同一類資訊只維護一份)）。原本的提案（檔名、`t`、`build`、`path`、`cells`、`rate`、`tags`、`note`、`card`、`cut`，一行 16,000 bytes、一次預覽 1,000 行、不設每月上限、不先讀當月的檔）見這份說明在 `757f093c` 的版本；[格式查核](<../Claude Codex Discussion/2026-11-28-card-feedback-format-review.md>)（Fable 5.2 high，2026-11-28）之後改了這些，照 [D-207](../../../../docs/decisions.md#d-207-l2-的發現先分一定修可記限制交使用者選修法先收窄最後才加機制) 分：

| 發現 | 分類 | 怎麼處理 |
|---|---|---|
| F1 分不出哪一輪預覽：下一輪只補一句或取消，會把上一輪的評等讀成收回 | 一定修 | 多一欄 `run`（這一輪預覽打開的時間，排在 `build` 後面）；〈怎麼讀〉改成同一台、同一個 `run`、同一組 `cells` 取最後一行，收回只算那一輪 |
| F2「沒存到，再點一次」和「點已選的是取消」「內容沒變不寫」相衝 | 一定修 | 沒存到時多一個「點這裡再存」，點了寫現在的整份；上一次沒存到時，一句話沒改字按「存」也照寫（§3-2、§6 第 13 項） |
| F3 一句話照 UTF-16 截會切在半個表情符號上 | 直接修 | 照字算 500 個字 |
| F4 `card` 的換行、Tab 沒定死；比較卡剩下的句子那幾張少了整組 | 直接修 | 每一行原樣、一律用 `\n` 接、最後不加換行；比較卡與多音字一律帶同一組每個目標的原文 |
| F6 跨裝置照 `t` 比會讓一台蓋掉另一台；同一刻兩行 | 直接修 | 〈怎麼讀〉照檔裡行的先後、不同裝置與不同輪不互相蓋；同一輪的 `t` 嚴格遞增 |
| F10 漏列的文件與錯誤的出口 | 直接修 | §4-1 的 `failed`、`where: "feedback"`、§7 的文件清單；資料夾防呆不加 `紀錄/回饋`（上一層 `紀錄` 已在名單裡；搬走不影響複習，下一次寫在原位另建） |

| F8 備份讀兩次的中間多一行要重來 | 可記限制 | 和錯誤紀錄同一列技術債 |

## §3 畫面（`src/ui/Review.tsx`、新的 `src/ui/Feedback.tsx`、`Review.css`）

### 3-1 回饋列在哪裡、什麼時候有

- 只在預覽、開關打開、畫面上有卡、這張卡每一格都有 ID 的時候有。還沒補 ID 的手寫卡（預覽讀的是編輯器的文字，`lt` 是空字串）沒有回饋列，也不寫字說明（手寫卡不是回饋的主要對象；離開筆記補了 ID 再預覽就有）。
- 位置：卡片區（`.ec-stage`）和下方的按鈕（`.ec-actions`）之間，自己一條，不跟著卡片捲動。不在 `.ec-stage` 裡，所以點卡片翻面、左右滑都不會從這一條觸發（手勢只掛在 `.ec-stage`）。
- 和自評按鈕分得開：小一號、細框、開頭一個淡色的「回饋」兩個字；按下去的評等有底色（顏色照 U3 回饋頁：可以用綠、要改黃、不要這張紅）。
- 換卡、往回翻：回饋列顯示這一輪在這張卡留過的；關掉預覽就清掉（§1「晚一版」）。同一個目標裡同一題寫了兩次的兩張卡是同一份（查核 F7）。

### 3-2 評等與標籤

- 一列四顆：「可以用」「要改」「不要這張」「✎ 寫一句」（這一輪寫過一句時改成「✎ 改一句」）。375 px 寬的手機一行放得下（§6 的 iPhone 確認）。
- 點評等立刻存；點已經選的那一個是取消，也存一行。
- 選了「要改」或「不要這張」，下面多一行四顆標籤「詳解」「考點」「版面」「不值得考」，可以複選，點了立刻存；改成「可以用」或取消評等時收起並清掉。
- 存好了這一列開頭的「回饋」換成「已存」；沒存到換成「沒存到」，下面多一行「沒存到，點這裡再存」，點了把這張卡現在的整份再寫一次（查核 F2：再點一次評等是取消，不能拿來重存）。這一輪寫滿了寫「這次預覽的回饋滿了」。

### 3-3 一句話

- 按「✎ 寫一句」從**上方**滑下一個框（iPhone 的鍵盤在下面，不會蓋住），裡面一個多行的輸入框、「存」與「取消」；可以用 iPhone 的語音輸入。打開時背後不能操作（和回報選單一樣用 `inert`），Esc 是取消，點框外的暗處也是取消。
- Enter（不在中文組字中）等於「存」；不收換行。「存」寫一行（2-3），「取消」不寫、恢復成打開前的字。
- **按鍵**：現在的 `onKey` 只把 `input` 當輸入框（[Review.tsx](../../src/ui/Review.tsx) 的 `target.matches('input')`），多行輸入框裡的 Space、1～4、方向鍵會觸發翻面、自評與換卡。框打開時所有按鍵只交給框（同回報選單開著時的處理）。

### 3-4 設定頁（`src/obsidian/settings.ts`、`src/ui/prefs.ts`）

- 「複習」一區，接在「預覽時自動展開答案」後面：名稱「預覽時可以留回饋」；說明「預覽的每張卡下面多一列：可以用、要改、不要這張，也可以寫一句話。存在「紀錄/回饋/」，給改進製卡規則用，不影響複習與排程。只影響這台裝置。」名稱照 [D-156](../../../../docs/decisions.md#d-156-設定頁依功能分區不寫給家長) 依功能命名，不寫「給家長」。
- 存在這台裝置（`saveLocalStorage`，鍵 `essence-cards-preview-feedback`），存的是 `true` 才算開，缺值或壞值是關（同 `phoneCards`）。
- 「顯示預覽按鈕」關著時這個開關照樣可以開（從命令也能預覽）。
- 已經開著的預覽不跟著開關變（下一次打開預覽才算）。

### 3-5 完成畫面

「預覽完了」的說明：這一輪有留回饋時寫「共 N 張，留了 M 張的回饋」（M 是現在有評等、標籤或一句話的卡），沒有時照舊「共 N 張」。

## §4 接線

### 4-1 寫的一方（新的 `src/core/feedback/`）

- `createFeedbackLog({ files, device, build, now?, offset?, failed? })` 回一個 `write(entry): Promise<'saved' | 'full' | 'failed'>`；路徑、欄位的順序（照 syntax §11 的表）、`run`、嚴格遞增的 `t`、截短與一次預覽的上限都在這裡，純程式、不碰 Obsidian 與 React，用記憶體裡的 `Files` 測。`append` 丟錯時呼叫 `failed(error, 回饋檔的路徑)`，接線的地方記進錯誤紀錄（`where: "feedback"`，查核 F10 第 4 點）。
- `previewSink(log, path, text)` 是預覽的寫的一方（review 的 `FeedbackSink`）：從畫面上那張卡（`Card`）取 `cells`，從預覽打開時編輯器的文字切 `card`（第一次存時才 `parseDeck(text, { layout: true })`）。
- 一次預覽一個 `createFeedbackLog`（上限與 `run` 照一次預覽算）；在 `Files` 的 vault 版上寫，不經過資料夾防呆以外的包裝（錯誤紀錄怎麼接就怎麼接，[main.ts](../../src/main.ts) 的 `createErrorLog`）。
- `core/` 的邊界照 `eslint.config.js`：`core/feedback` 用 `core/files.ts`、`core/study` 的 `formatTime` 與型別、`core/deck` 的 `parseDeck`。

### 4-2 預覽（`src/review/preview.ts`、`src/obsidian/deck-actions.ts`、`src/ui/host.tsx`、`src/main.ts`）

- `deck-actions.ts` 打開預覽時讀開關；開著才向 `main.ts` 要一個寫的一方（`host.feedback(path, 編輯器的文字)`，`card` 要從這份文字切）。`createPreview` 多一個選填的 `feedback`（`FeedbackSink`），畫面不自己解析卡組。
- `Session` 介面多一個選填的 `feedback(change)`，只有開著回饋的預覽有；畫面看到它才畫回饋列，一般複習的 Session 沒有它，畫面也就沒有。由預覽記下這一輪每張卡的狀態（照每一格的 ID 與指紋，查核 F7）並呼叫 `save`；目前這張卡的回饋狀態放進 `View` 的 `feedback`，畫面只畫出來。
- `openPreview` 照舊不給 `onReport`；回饋和回報是兩件事。
- 預覽完全不寫複習紀錄、不動排程（D-161）照舊：預覽的 Session 本來就不接 state；`tests/feedback-log.test.ts` 確認留過幾行之後，記憶體裡的 vault 只多了回饋檔。

### 4-3 備份與還原（`src/core/backup/plan.ts`）

- 備份照 D-150 第 4 點包含整個 `Essence Cards/`，不用改。
- 還原的勾選清單不列 `紀錄/回饋/`、也不補回，和錯誤紀錄同一處例外（`listed`；使用者 2026-11-28 選，查核 F5）。理由同 D-155 第 6 點：只往後加的檔，現在的通常比備份多，照通用規則每次都會列成衝突，家長看不懂；舊的回饋仍在備份的 zip 裡，要用時從那裡讀。寫在 syntax §11 與 §6 最後一點。

## §5 品測模組怎麼讀（D-246 第 7 點，💡 照討論稿 §7-3，使用者看過再寫進決定）

- 先不寫程式：維護的 AI 在使用者電腦直接讀 `紀錄/回饋/`（同 D-160 第 5 點讀回報的做法），照 2-2〈怎麼讀〉取每張卡最後的回饋，用 `card` 對 AI 輸出快照（[syntax §6](../syntax.md#6-ai-輸出快照)）找規則版本、分出生成後被改過的卡。
- 什麼時候讀：比較測試開新的一輪之前，以及使用者問的時候（「這週的回饋有什麼」）。§7-3 原本的「新回饋滿約 20 則」沒有人會去數，先不用；第一次讀時一起看要不要外掛在入口的「提醒」寫「有 N 則新的回饋」。
- 幾則才提改法、怎麼分流、AI 評審先評再讀人的回饋：照 §7-3 與 D-246 第 6 點。

## §6 驗收與測試

測試照 code-quality〈測試〉：只透過公開介面，預期值手寫。必跑：在 `apps/Cards/` `npm run check`。

測試檔：畫面與狀態在 `tests/preview-feedback.test.ts`、`tests/preview-feedback-ui.test.ts`，寫的一方在 `tests/feedback-log.test.ts`，舊版在 `tests/feedback-old-version.test.ts`，還原在 `tests/backup-core.test.ts`，開關在 `tests/settings-tab.test.ts`、`tests/deck-actions.test.ts`。

1. 開關沒動過（預設）：預覽一整篇，畫面上沒有回饋列，`紀錄/回饋/` 沒有檔。
2. 開關打開、點「要改」：剛好多一行，`JSON.parse` 得出 syntax §11 的欄位與順序（和 §11 的範例一起比），`t`、`run` 帶時區，`cells` 對得上那張卡的 `lt` 與 `v`，`card` 等於手寫的那幾行原文。
3. 再點一次「要改」：多一行，沒有 `rate`、`tags`、`note`，`cells` 相同。
4. 標籤：選「要改」後點「詳解」「版面」，兩行，第二行 `tags` 是 `["explain","layout"]`（照畫面的順序，不照點的順序）；改點「可以用」，第三行沒有 `tags`。
5. 一句話：打開框打十個字不寫任何行；按「存」寫一行；不改字再存不寫；「取消」不寫且恢復原字；框開著時 Space、1～4、←、→ 都不翻面、不換卡，Enter 是存；換行變一個空白、只有空白等於沒寫；最多 500 個字，表情符號算一個字。
6. 比較卡：第一張的 `cells` 是組裡每一格；`card` 是組裡每個目標的原文、照筆記順序、中間空一行，組員中間隔了別的目標也只取組員；剩下的句子那一張 `cells` 只有那一格、`card` 照樣是整組（查核 F4）。全詩順序卡與句子排序：同一題好幾格只有一對 `cells`。CRLF 的卡組與 Tab 縮排：`card` 每一行原樣、用 `\n` 接、最後不加換行。
7. 還沒補 ID 的卡沒有回饋列；同一篇有 ID 的照樣有。
8. 預覽照舊不寫複習紀錄（4-2 最後一點）。
9. 舊版讀得到：`紀錄/回饋/` 裡放長得像作答與版本行的檔（含衝突副本），`0.6.0` 與現在的程式讀出的卡組、作答、變更、問題行、版本回報都和沒有這些檔時相同。
10. 還原的計畫不列 `紀錄/回饋/` 的檔：不見的、比備份多一行的、備份後才有的、衝突副本都不列；名稱像的旁邊資料夾照通用規則。拿掉這個例外時測試會失敗。
11. 一行超過 16,000 bytes：`card` 截短、`cut: true`、整行不超過上限且只差幾個 bytes；中文、表情符號、要跳脫的字不切在半個字上；截出來是原文的開頭；沒超過時沒有 `cut`。
12. 一次預覽第 1,001 次寫：不寫，回 `full`，畫面寫「這次預覽的回饋滿了」；換一次預覽重新算。
13. `append` 丟錯：回 `failed`，畫面寫「沒存到」與「沒存到，點這裡再存」，交給錯誤紀錄一次（錯誤紀錄同一個錯誤只在第 1、10、100 次記一行）；點「再存」成功後那一行的 `rate` 仍是剛才選的；沒存到之後一句話不改字按「存」也寫一行。交給錯誤紀錄的一方丟錯也照樣回 `failed`。
14. 設定頁：開關的名稱與說明照 3-4；缺值、壞值是關；換開關不影響已經開著的預覽。
15. 完成畫面：留了 M 張時寫「共 N 張，留了 M 張的回饋」，收回到 0 張時照舊。
16. 兩輪預覽（查核 F1）：同一張卡兩輪各留一次，兩行的 `run` 不同；同一輪的行 `run` 相同；同一刻的幾行 `t` 各加 1 毫秒；預覽開著跨月時照每一行的 `t` 換檔。
17. 同一個目標裡同一題寫了兩次（查核 F7）：兩張卡畫面上是同一份回饋，完成畫面算一張。
18. 先送的晚回來：狀態照最後一次的結果；關掉之後才回來的結果不通知畫面。
