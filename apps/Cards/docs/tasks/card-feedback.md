# 預覽畫面的單張卡回饋（D-246 第 4-3、5、7 點，給 Claude）

狀態：規劃中｜下一步：使用者在決定卡選加不加四個標籤（存原文已選），選完照選的改這份、寫格式查核請求，在使用者電腦請 Codex 查 §2｜等誰：使用者

來自：[D-246](../../../../docs/decisions.md#d-246-單張卡的回饋有空才留先給開發者拿來改製卡規則與評分說明)（第 4-3 點預覽畫面每張卡一列回饋、第 5 點存法、第 7 點還沒定的欄位與品測模組）、[驗證卡片評估機制](<../Claude Codex Discussion/2026-11-27-validate-evaluation.md>) §7 與 §8-7（兩批回饋頁的經驗）。使用者 2026-11-28：「開新討論串做家長回饋模組」。

遵守 repo 根目錄的 `AGENTS.md`。建議模型與推理等級：**Opus、高**（規劃與兩件選擇已在這份寫好，實作是照做）。新的寫進 vault 的紀錄檔與還原分類的例外屬於[高風險範圍](../../../../docs/agents/quality.md#高風險範圍要做-l2)：§2 開工前做[格式查核](../../../../docs/agents/quality.md#開工前的格式查核)，合併前做 L2，都在使用者電腦用 Codex（[D-212](../../../../docs/decisions.md#d-212-claude-直接呼叫本機-codex任務開始時分本機或雲端)）。

## 使用者要選的（決定卡，2026-11-28）

1. **紀錄要不要連那張卡當時的原文一起存**（改不回來：當時沒存的，事後補不回）。**使用者 2026-11-28 選「存原文」**（Claude 建議的）。理由：使用者兩批的意見多半在詳解，題目指紋（[syntax §2-8](../syntax.md#2-8-題目指紋)）與快照的比對（[syntax §6](../syntax.md#6-ai-輸出快照)「比對只看題目和答案」）都不看背面；只存 ID 與指紋，詳解之後被改過，就分不出使用者評的是 AI 原稿還是改過的版本，D-246 第 3 點「生成後被人改過的卡標出來」對背面做不到。寫在 §2 的 `card`。
2. **外掛版要不要加可以點的標籤**。D-246 第 3 點：開發階段不給，跑兩三批後把常見的做成標籤給外掛版用。兩批的意見歸類後（§6-2、§8-7 的表，一則可歸好幾類，共 47 筆），只有 1 筆（例句用的名字）不在這四類：**詳解**（沒講為什麼、背面看不懂、容易混的沒並排比、背面太多，共 18）、**版面**（16）、**考點**（考點不清楚、太多說法都對、題型該換，共 9）、**不值得考**（3）。Claude 建議加：點了「要改」或「不要這張」才出現，可以複選，一句話照樣可以寫；手機上點一下比打字快，AI 抓不到的問題仍然寫在一句話裡。代價是 D-246 擔心的「引導人只看那幾類」，靠一句話留著、品測模組讀到「只有標籤沒有一句話」時不推論原因來減輕。下面照「加」寫（§2 的 `tags`、§3-2）；選「先不加」就拿掉這兩處。

其餘是 Claude 的建議，2026-11-28 在串裡列給使用者、寫明照建議做（使用者還沒回；看過有意見再改，不算使用者同意）。回饋只在預覽、開關預設關、每台裝置各自打開、一台裝置一個月一個檔，是 D-246 與 D-163 第 6 點已定的；另外幾件：

- 外掛只寫回饋紀錄、不讀（同錯誤紀錄，[syntax §9](../syntax.md#9-錯誤紀錄)）：排程、複習、讀取閘門、加深都不看它，欄位可以隨版本增減，每一行的 `build` 說是哪一版寫的。
- 這一輪預覽留過的回饋，往回翻（‹）看得到；下一次打開預覽不顯示之前留過的（§1「晚一版」）。
- 還沒有 ID 的卡沒有回饋列（§3-1）。
- 還原的清單不列 `紀錄/回饋/`（同錯誤紀錄，§4-3）。
- 品測模組先不寫程式（§5）。

## 和「不做」比較（D-153、D-177）

- **不做會怎樣**：每批卡由 Claude 另做一個手機回饋頁。兩批都碰到和外掛不一樣的地方（第 1 批比較題沒列選項、例句沒分行；第 2 批前 24 張的題目擠在一行，7 張受影響，§8-7〈限制〉），版面的意見要事後扣掉；卡號要對回 ID，回饋只在 Claude 準備一批時才收得到。家長自己做完一課 AI 卡、在預覽看的時候，想到的意見沒有地方留。
- **做了**：看到的就是複習畫面真正的樣子；ID、指紋、卡組、當時的原文由外掛帶入；做完一課、預覽時就能留，不用等 Claude 做頁。學習效果是推論：回饋只用來找問題的類別（D-246 第 6 點），規則有沒有因此變好要照比較測試量。
- **代價與解法**：
  - 一種新的紀錄檔：外掛只寫不讀，不進讀取閘門；格式查核與 L2 照上面。
  - 預覽畫面多一列：只在預覽、只在打開開關的裝置；孩子的複習畫面完全不變（學生回報照 [D-160](../../../../docs/decisions.md#d-160-學生在複習畫面回報問題點一個選項記進錯誤紀錄)）。
  - 一個設定：照 [D-161](../../../../docs/decisions.md#d-161-預覽卡片不記錄不動排程設定頁打開才有)、[D-163](../../../../docs/decisions.md#d-163-入口與目錄的四批開法全部卡的一輪與提醒一區) 第 6 點，只存在這台裝置，預設關。
  - iPhone 上的鍵盤、語音輸入與擠不擠：一次 iPhone 實機（§6）。
- **第 2 類**（[D-195](../../../../docs/decisions.md#d-195-測試分兩類改不回來的做足其餘延後但不漏)）：§1「晚一版」的功能與 iPhone 實機以外的少見情況，記進[技術債](../backlog.md#技術債)。寫不進去時這一列標「沒存到」，家長再點一次就再寫一次（§2-3），不會悄悄丟掉。

## §2 紀錄的格式（格式查核的範圍）

### 2-1 檔案

`Essence Cards/紀錄/回饋/<年-月> <裝置碼> 回饋.jsonl`：一台裝置一個月一個檔，只往後加，一行一個 JSON（D-246 第 5 點，比照 [syntax §9](../syntax.md#9-錯誤紀錄)）。年月照當地時間；裝置碼和複習紀錄相同（[syntax §5](../syntax.md#5-複習紀錄)）；檔名多「回饋」兩個字，整個 vault 檔名不重複。

```
紀錄/回饋/2026-12 iPhone-7f3a 回饋.jsonl

{"t":"2026-12-03T21:15:03.250+08:00","build":"0.7.0+1a2b3c4","path":"Essence Cards/國二上/英文/國二上英文 L3 文法（卡片）.md","cells":[{"lt":"k3m9x2","v":"a1b2c3d4"}],"rate":"fix","tags":["explain"],"note":"沒講為什麼用過去進行式","card":"- 過去進行式的問句 ^k3m9x2\n  - ＿＿ your brothers eating when you left? :: Were\n    - 詳解：……"}
{"t":"2026-12-03T21:15:40.102+08:00","build":"0.7.0+1a2b3c4","path":"Essence Cards/國二上/英文/國二上英文 L3 文法（卡片）.md","cells":[{"lt":"k3m9x2","v":"a1b2c3d4"}],"rate":"fix","tags":["explain","layout"],"note":"沒講為什麼用過去進行式","card":"- 過去進行式的問句 ^k3m9x2\n  - ……"}
```

第二行是同一張卡又點了「版面」：每一行都是那張卡**那一刻的完整回饋**，不是差異。

### 2-2 欄位

| 欄位 | 內容 |
|---|---|
| `t` | 時間，寫法同 [§5](../syntax.md#5-複習紀錄) 的 `t` |
| `build` | 建置版本 `BUILD` 原樣（同 [§5-1](../syntax.md#5-1-版本行) 的 `val`）。版面的意見要看當時外掛怎麼排，所以一定寫 |
| `path` | 那張卡的卡組，vault 內的完整路徑 |
| `cells` | 這張卡的每一格（`Card.blanks`）的學習目標 ID 與題目指紋，照畫面的順序，同一對 `lt`、`v` 只留第一個。一般卡一格；比較卡是組裡每一格；全詩順序卡、句子排序的好幾格同一題只有一對 |
| `rate` | 評等：`ok` 可以用、`fix` 要改、`drop` 不要這張；沒選（或點了已選的那一個取消）不寫這一欄 |
| `tags` | 決定卡第 2 件選「加」才有。只在 `rate` 是 `fix`、`drop` 時，照畫面的順序：`explain` 詳解、`point` 考點、`layout` 版面、`worth` 不值得考；一個都沒點不寫。改回 `ok` 或取消評等時清掉。新的值可以隨版本增加 |
| `note` | 一句話，原樣，去掉頭尾空白；換行換成一個空白；最多 500 字（照 UTF-16 長度截）。沒寫不寫這一欄 |
| `card` | 這張卡用到的每個學習目標在卡組裡的原文：從目標那一行到它最後一個子項目（`parseDeck` 的 layout 給的 `end`），含題目、答案、背面、記憶錨點與資料欄位，照筆記順序，目標之間空一行，換行寫 `\n`。讀的是預覽打開時編輯器的文字（和畫面一致，[D-163](../../../../docs/decisions.md#d-163-入口與目錄的四批開法全部卡的一輪與提醒一區) 第 3 點的「這篇的每一題」） |
| `cut` | 只在 `card` 被截短時寫 `true`（2-3） |

- **怎麼讀**（給品測模組與維護的 AI；外掛不讀）：同一組 `cells`（每對 `lt`、`v` 照字串排序後相同）`t` 最晚的那一行是那張卡現在的回饋；沒有 `rate`、`tags`、`note` 的一行表示收回。跨裝置照 `t` 比；同一刻的照檔名、再照行的先後。
- **ID 或指紋變了**：卡改過題目或答案，指紋就不同，算另一張卡的回饋；背面改過指紋不變，靠 `card` 分得出評的是哪一版。
- **不記**：作答、排程、設定值、Obsidian 的版本。卡組的原文和錯誤紀錄的 `msg` 一樣只留在 vault 裡；寫進 repo 的只有數字與類別（[D-003](../../../../docs/decisions.md#d-003-公開範圍)；驗證卡片評估機制 §8-7 的做法）。

### 2-3 寫法與上限

- **什麼時候寫**：點評等或標籤，立刻寫一行；一句話在框關上（按「存」、Enter）時寫一行，內容沒變不寫；打字中不寫（§3-3）。
- **一行最多 16,000 bytes**（UTF-8，含 JSON 的跳脫）：太長時截短 `card` 並寫 `cut: true`；截到 `card` 沒有字還是太長（不會發生在 500 字的 `note`），就不寫、這一列標「沒存到」。
- **一次預覽最多寫 1,000 行**：防程式出錯時一直寫。到了這一列標「這次預覽的回饋滿了」，不再寫。不設每個月的上限，所以第一次寫之前不用讀當月的檔（iPhone 的雲端佔位檔讀不到時也照樣能寫，[D-154](../../../../docs/decisions.md#d-154-雲端佔位檔讀不到時預防當下說清楚先實測)）。
- **寫不進去**：`Files.append` 丟錯時這一列標「沒存到，再點一次」，不自動重試、不記進錯誤紀錄以外的地方；錯誤照 [D-155](../../../../docs/decisions.md#d-155-正式版的錯誤紀錄) 記一行，`where` 用新的 `feedback`（syntax §9 的表加一個值）。畫面上的狀態不退回：家長再點一次，就把那一刻的完整回饋再寫一次。
- 同一台裝置同一路徑的寫入照 `Files` 原本的隊伍排隊（[src/core/files.ts](../../src/core/files.ts) 的 `append`）；預覽關掉時還沒寫完的照寫完，不等它才關。

### 2-4 舊版與其他讀者

- 複習紀錄與版本回報只讀 `紀錄/` 直接底下的 `.jsonl`（[src/core/backup/logs.ts](../../src/core/backup/logs.ts)、[versions.ts](../../src/core/backup/versions.ts) 的註解），卡組不看 `紀錄/`，所以舊版外掛（`0.6.0`）讀到有 `紀錄/回饋/` 的 vault，排程與讀取閘門都一樣。要寫成測試（§6 第 9 項），格式查核也請 Codex 核對。
- 舊版的還原照 `紀錄/` 的通用規則：只補不見的、同名不同內容列成衝突，不蓋掉（[syntax §6](../syntax.md#6-ai-輸出快照) 最後一點）。家長會在舊版的還原畫面看到這些檔，不會壞資料；記成已知的限制。
- 不加 `需要版本`：沒有寫進卡組。

## §3 畫面（`src/ui/Review.tsx`、新的 `src/ui/Feedback.tsx`、`Review.css`）

### 3-1 回饋列在哪裡、什麼時候有

- 只在預覽、開關打開、畫面上有卡、這張卡每一格都有 ID 的時候有。還沒補 ID 的手寫卡（預覽讀的是編輯器的文字，`lt` 是空字串）沒有回饋列，也不寫字說明（手寫卡不是回饋的主要對象；離開筆記補了 ID 再預覽就有）。
- 位置：卡片區（`.ec-stage`）和下方的按鈕（`.ec-actions`）之間，自己一條，不跟著卡片捲動。不在 `.ec-stage` 裡，所以點卡片翻面、左右滑都不會從這一條觸發（手勢只掛在 `.ec-stage`）。
- 和自評按鈕分得開：小一號、細框、開頭一個淡色的「回饋」兩個字；按下去的評等有底色（顏色照 U3 回饋頁：可以用綠、要改黃、不要這張紅）。
- 換卡、往回翻：回饋列顯示這一輪在這張卡留過的；關掉預覽就清掉（§1「晚一版」）。

### 3-2 評等與標籤

- 一列四顆：「可以用」「要改」「不要這張」「✎ 寫一句」（這一輪寫過一句時改成「✎ 改一句」）。375 px 寬的手機一行放得下（§6 的 iPhone 確認）。
- 點評等立刻存；點已經選的那一個是取消，也存一行。
- 決定卡第 2 件選「加」：選了「要改」或「不要這張」，下面多一行四顆標籤「詳解」「考點」「版面」「不值得考」，可以複選，點了立刻存；改成「可以用」或取消評等時收起並清掉。
- 存好了這一列最後淡淡寫「已存」；沒存到寫紅字（2-3）。

### 3-3 一句話

- 按「✎ 寫一句」從**上方**滑下一個框（iPhone 的鍵盤在下面，不會蓋住），裡面一個多行的輸入框、「存」與「取消」；可以用 iPhone 的語音輸入。打開時背後不能操作（和回報選單一樣用 `inert`），Esc 是取消，點框外的暗處也是取消。
- Enter（不在中文組字中）等於「存」；不收換行。「存」寫一行（2-3），「取消」不寫、恢復成打開前的字。
- **按鍵**：現在的 `onKey` 只把 `input` 當輸入框（[Review.tsx](../../src/ui/Review.tsx) 的 `target.matches('input')`），多行輸入框裡的 Space、1～4、方向鍵會觸發翻面、自評與換卡。框打開時所有按鍵只交給框（同回報選單開著時的處理）。

### 3-4 設定頁（`src/obsidian/settings.ts`、`src/ui/prefs.ts`）

- 「複習」一區，接在「預覽時自動展開答案」後面：名稱「預覽時可以留回饋」；說明「預覽的每張卡下面多一列：可以用、要改、不要這張，也可以寫一句話。存在「紀錄/回饋/」，給改進製卡規則用，不影響複習與排程。只影響這台裝置。」名稱照 [D-156](../../../../docs/decisions.md#d-156-設定頁依功能分區不寫給家長) 依功能命名，不寫「給家長」。
- 存在這台裝置（`saveLocalStorage`，鍵 `essence-cards-preview-feedback`），存的是 `true` 才算開，缺值或壞值是關（同 `phoneCards`）。
- 「顯示預覽按鈕」關著時這個開關照樣可以開（從命令也能預覽）。
- 已經開著的預覽不跟著開關變（下一次打開預覽才算）。

### 3-5 完成畫面

「預覽完了」的說明：這一輪有留回饋時寫「共 N 張，留了 M 張的回饋」（M 是現在有評等、標籤或一句話的卡），沒有時照舊「共 N 張」。

## §4 接線

### 4-1 寫的一方（新的 `src/core/feedback/`）

- `createFeedbackLog({ files, device, build, now?, offset? })` 回一個 `write(entry): Promise<'saved' | 'full' | 'failed'>`；路徑、欄位的順序（照 2-2 的表）、截短與一次預覽的上限都在這裡，純程式、不碰 Obsidian 與 React，用假的 `Files` 測。
- 一次預覽一個 `createFeedbackLog`（上限照一次預覽算）；在 `Files` 的 vault 版上寫，不經過資料夾防呆以外的包裝（錯誤紀錄怎麼接就怎麼接，[main.ts](../../src/main.ts) 的 `createErrorLog`）。
- `core/` 的邊界照 `eslint.config.js`：`core/feedback` 只用 `core/files.ts` 與 `core/study` 的 `formatTime`。

### 4-2 預覽（`src/review/preview.ts`、`src/obsidian/deck-actions.ts`、`src/ui/host.tsx`、`src/main.ts`）

- `deck-actions.ts` 打開預覽時讀開關；開著才把編輯器的文字一起交出去（`card` 要從它切）。`createPreview` 多一個選填的 `feedback`：每張卡的 `cells` 與 `card` 由它算好放進 `View`，畫面不自己解析卡組。
- `Session` 介面多一個選填的 `feedback`，只有開著回饋的預覽有；畫面看到它才畫回饋列，一般複習的 Session 沒有它，畫面也就沒有。動作經過它（例如 `feedback.change(…)`），由預覽記下這一輪每張卡的狀態並呼叫 `write`；目前這張卡的回饋狀態放進 `View`，畫面只畫出來。
- `openPreview` 照舊不給 `onReport`；回饋和回報是兩件事。
- 預覽完全不寫複習紀錄、不動排程（D-161）照舊：既有的 `tests/preview.test.ts` 加一項，開著回饋留過幾張之後，複習紀錄與 state 的作答數不變。

### 4-3 備份與還原（`src/core/backup/plan.ts`）

- 備份照 D-150 第 4 點包含整個 `Essence Cards/`，不用改。
- 還原的勾選清單不列 `紀錄/回饋/`、也不補回，和錯誤紀錄同一處例外（`listed`）。理由同 D-155 第 6 點：只往後加的檔，現在的通常比備份多，照通用規則每次都會列成衝突，家長看不懂；舊的回饋仍在備份的 zip 裡，要用時從那裡讀。syntax §8 與新的 §11 各寫一句。

## §5 品測模組怎麼讀（D-246 第 7 點，💡 照討論稿 §7-3，使用者看過再寫進決定）

- 先不寫程式：維護的 AI 在使用者電腦直接讀 `紀錄/回饋/`（同 D-160 第 5 點讀回報的做法），照 2-2〈怎麼讀〉取每張卡最後的回饋，用 `card` 對 AI 輸出快照（[syntax §6](../syntax.md#6-ai-輸出快照)）找規則版本、分出生成後被改過的卡。
- 什麼時候讀：比較測試開新的一輪之前，以及使用者問的時候（「這週的回饋有什麼」）。§7-3 原本的「新回饋滿約 20 則」沒有人會去數，先不用；第一次讀時一起看要不要外掛在入口的「提醒」寫「有 N 則新的回饋」。
- 幾則才提改法、怎麼分流、AI 評審先評再讀人的回饋：照 §7-3 與 D-246 第 6 點。

## §6 驗收與測試

測試照 code-quality〈測試〉：只透過公開介面，預期值手寫。必跑：在 `apps/Cards/` `npm run check`。

1. 開關沒動過（預設）：預覽一整篇，畫面上沒有回饋列，`紀錄/回饋/` 沒有檔。
2. 開關打開、點「要改」：剛好多一行，`JSON.parse` 得出 2-2 的欄位與順序，`t` 帶時區，`cells` 對得上那張卡的 `lt` 與 `v`，`card` 等於手寫的那幾行原文。
3. 再點一次「要改」：多一行，沒有 `rate`、`tags`、`note`，`cells` 相同。
4. 標籤（決定卡第 2 件選「加」）：選「要改」後點「詳解」「版面」，兩行，第二行 `tags` 是 `["explain","layout"]`；改點「可以用」，第三行沒有 `tags`。
5. 一句話：打開框打十個字不寫任何行；按「存」寫一行；不改字再存不寫；「取消」不寫且恢復原字；框開著時 Space、1～4、←、→、Enter 都不翻面、不換卡（Enter 是存）。
6. 比較卡：`cells` 是組裡每一格，`card` 有組裡每個目標的原文、照筆記順序、中間空一行。全詩順序卡與句子排序：同一題好幾格只有一對 `cells`。
7. 還沒補 ID 的卡沒有回饋列；同一篇有 ID 的照樣有。
8. 預覽照舊不寫複習紀錄（4-2 最後一點）。
9. 舊版讀得到：`紀錄/回饋/` 裡放幾個檔，`0.6.0` 的讀取（照 [tests/single-old-version.test.ts](../../tests/single-old-version.test.ts) 的做法）與現在的 state 讀出的卡組、紀錄、版本回報都和沒有這些檔時相同。
10. 還原的計畫不列 `紀錄/回饋/` 的檔（備份裡有、現在不見也不列）；備份照舊包含。
11. 一行超過 16,000 bytes：`card` 截短、`cut: true`、整行剛好不超過上限；中文與表情符號不切在半個字上。
12. 一次預覽第 1,001 次寫：不寫，回 `full`，畫面寫「這次預覽的回饋滿了」。
13. `append` 丟錯：回 `failed`，畫面寫「沒存到，再點一次」，錯誤紀錄多一行 `where: "feedback"`；再點一次成功就寫完整的一行。
14. 設定頁：開關的名稱與說明照 3-4；缺值、壞值是關；換開關不影響已經開著的預覽。
15. 完成畫面：留了 M 張時寫「共 N 張，留了 M 張的回饋」，收回到 0 張時照舊。
