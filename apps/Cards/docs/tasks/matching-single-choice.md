## 和「不做」比較（D-153、D-177）

- **不做會怎樣**：「把例子歸到固定的幾類」的目標現在是翻面自評，孩子可以沒選就翻面，紀錄看不出他把西部和南部搞混；一組平行的事實（四個方位的海岸各是什麼地形）是四張翻面卡。做了之後一定要選、程式判對錯、留下選了哪一個（D-178 當初的理由），一組事實一張卡做完。學習上的效果是推論，待驗證。
- **代價與解法**：
  - 一個新卡型，接在題型模組第 A 步整理好的結構上，每一層補一處（§1-9 的接法，`tsc` 的漏接檢查就是清單）。
  - 一行新的寫法（P1）：舊版讀到的是一題完整的問答，不加 `需要版本`、不碰寫回筆記的三條路（§2）。
  - AI 可能把想得出來的事實也做成單選、自己編錯的選項：用在哪的規則要指得到教材的出處，錯的選項只准來自教材，錯誤級的檢查退回 AI（§6、§7）。
  - 0.7.0 已經很滿：排在第 A 步合併之後，不和第 B、C 步平行改同一批檔；2027-01-04 前沒合併就到 0.7.x（〈時程與切點〉）。
- **更小的做法**：只做一格的單選、不併成配對。使用者選了兩個一起做；這只當切點到了的退路。

## §0 第 0 段：試作一課（寫程式之前）

目的：寫程式前知道這兩種題型在真教材裡用得到多少，AI 寫得穩不穩。

- **在哪做**：使用者的電腦（Remote Control），用 Dean PKM 的國小社會筆記一課（建議康軒五上 2-1 海岸那一課；沒有就用最近做的一課）。repo 裡沒有課本，試作的輸入與 AI 的輸出留在那台電腦，**只把數字與結論寫進這份的〈結果〉**，不寫目標名稱以外的教材內容（`AGENTS.md` 底線）。
- **怎麼做**：在試作場開一個資料夾（`experiments/2026-11-matching-trial/`，只放步驟與規則草稿，不放教材），把 §7 的規則草稿接在國小社會預設後面，照平常的 AI 製卡流程出一次草稿，再由代審（另一個對話，只看題幹與選項、不看答案）照 §7 的清單看一次。
- **要回答的三件事**：
  1. 照收窄的規則，一課有幾個目標做得成單選、幾組做得成配對（每組幾對）。
  2. 同一組的選項行 AI 寫得一不一致（有沒有只差一項的兩組）。
  3. 教材的類別本來是不是就比題目多（配對時選項數比對數多）。
  - 另記：AI 有沒有寫出「下列何者」、編了教材沒有的錯選項、把想得出來的事實做成單選；代審找到「兩個都說得通」幾處。
- **停損**：一課做得成的少於 2 個目標，或代審找到「兩個都說得通」，先把數字給使用者看，問要不要照做（不自己決定開工）。

## §2 卡組的寫法（P1，格式查核的範圍）

```markdown
- 能從海岸景觀的描述判斷是臺灣哪一部的海岸
    - 出處：p.42
    - 選項：北部、東部、西部、南部
    - 海岸平直，有沙灘和潟湖，是臺灣哪一部的海岸？ :: 西部
    - 山緊靠著海，海岸陡直，是臺灣哪一部的海岸？ :: 東部

- 能說出臺灣北部海岸的地形
    - 選項：岩岸、沙岸、斷層海岸、珊瑚礁海岸
    - 臺灣北部的海岸主要是哪一種海岸？ :: 岩岸
- 能說出臺灣西部海岸的地形
    - 選項：岩岸、沙岸、斷層海岸、珊瑚礁海岸
    - 臺灣西部的海岸主要是哪一種海岸？ :: 沙岸
```

（內容只示範結構。第一個是單選；後兩個選項組相同，每天複習時併成配對。）

- **選項行**：目標底下一行，`選項：` 開頭（全形冒號，和 `記憶錨點：` 同一種標籤寫法），後面列**全部**選項，含答案。只認目標底下的；寫在題目底下的是那一題的補充，0.7.0 不認（每題自己的選項晚一版，往上加不會讀錯）。
- **切法與比對**：和比較卡的組同一套（`kinds/shared.ts` 的 `membersOf`、`pickKey`）：頓號或逗號隔開；全半形、大小寫、粗體不分；重複的只留第一個。
- **名稱照各科原本的寫法**（「能……」），沒有新的結尾、不用名稱的括號；卡片上不放標題（D-179）。
- **指紋**：選項行在目標底下，和其他補充一樣不算進題目的指紋（[syntax §2-8](../syntax.md)）。改選項、加減選項，出題歷史不斷。
- **舊版與沒勾**：`v0.6.0` 讀成一般的問答，選項行出現在背面的補充（討論稿 Fable 第一輪的探針 1）；所以不加 `需要版本`，舊裝置不擋（照多音字；使用者 2026-11-25「我一定會更新到最新版」）。
- **已有紀錄的翻面目標不改成有選項的**：只用在新做的卡組；AI 加題時由加題核對擋（§6）。家長手動加一行會讓那個目標從自評接成程式判，間隔照舊沿用，記成已知的行為（說明書寫一句）。
- **格式查核要回答**：
  - 現有的卡組裡有沒有已經是 `選項：` 開頭的補充，會被讀成單選（兩個正式 vault 用 `compare-versions` 看卡型摘要，§8）。
  - 選項行和現有的每一種卡型、欄位（`出處：` 等）、記憶錨點、隱式目標、填空題、方向（英翻中、中翻英）的先後。
  - 選項裡有 `＿`、`::`、`%%` 註解、連結、HTML 時怎麼讀（§3 的不能有的符號）。

## §3 認法（`src/core/deck/kinds/single.ts`、`question-types.ts`、`types.ts`、`parse.ts`）

- **卡型**：`Kind` 多 `{ id: 'single'; single: Single }`。`Single` 有選項（照寫的字，切好、去重）、每個選項的比對鍵、組的身分 `key`（比對鍵排序後的 JSON，和比較卡的 `group.key` 同一種算法）、每一題的答案是第幾個選項（對齊 `target.prompts`）。代號與名稱避開 `choice`、`Choice`、`readChoice`、`choiceStem`（多音字用的）。
- **先後**：照 `readKind` 現在的順序（比較卡 → 多音字 → 排序 → 接句），單選排最後；文法與變化在名稱階段認，照舊先。名稱已經是別的卡型時照那個卡型出，選項行當補充，存檔按鈕提示一次（`options-ignored`）。
- **認成單選的條件**（全部要成立）：
  1. 不是最上層直接寫的題目（`implicit`），名稱沒有方向（英翻中、中翻英照 D-050 是別的目標）。
  2. 目標底下剛好一行選項行。
  3. 選項至少 3 個；沒有不能有的符號：`` ` ``、`$`、`[`、`]`、`<`、`>`（同比較卡）、`＿`（會被讀成填空）。
  4. 每一題都是問答（`::`）、答案單行，答案的比對鍵在選項裡。
- **認不成**：有選項行、但上面任一條不成立，照翻面出，存檔按鈕提示（`options-invalid`，訊息寫是哪一條）；AI 的草稿算錯誤、退回（§6）。沒有選項行照原本，不提示。
- **需要版本**：`KIND_NEEDS.single = null`。
- **漏接**：`KindId` 多一個值之後，`tsc` 報錯的每一處（第 A 步 §1-4 表裡用 `switch`、`Record` 的地方）照下面補；補不到的照翻面出，寫進〈結果〉。

## §4 組卡（`src/core/study/compose.ts`、`session.ts`、`plan.ts`）

- **一個目標一格**：題目的輪替照比較卡（syntax §2-6：第一次出基本題，之後出最久沒出的）。選項 3 個也出 1 題（1/3，和 3 個字的比較卡相同；討論稿的決定 7），看紀錄再定。
- **字鍵**：這一組的全部選項，照寫的字顯示；順序照比較卡用卡上的內容打散（`seeded(seedOf(cells))`，同一張卡重來不變），3 個以上時一定和寫的順序不同。不淡掉、可以重複點（使用者選的）。
- **配對（併卡）**：照比較卡的 `pickCard`：同一篇、同一個 `single.key` 的目標，還沒答的併；答錯的到時間才併；答對的不併（`joins`）。比較卡的組和單選的組分開比（先比卡型，再比 `key`），選項剛好和某個比較卡的括號一樣也不併。
- **多放一題**：每個選項剛好是卡上一格的答案時，從還有別題的目標多放一題（D-191 第 2 點，`pickCardOf` 現在的做法）；沒有別題就不加。
- **只在每天複習併**：`nextCard`（今天的份、再複習一些）併。單篇練習與小考（`practice.ts`）、預覽（`pickPreviewCards`）一個目標一張：一格的單選本來就是合法的卡，也正好量得到「併著對、單獨錯」的比例。
- **新的排在一起**：`plan.ts` 的 `newGroupsTogether` 把同一組的新目標排在一起，單選的組照同一套（組鍵前面加卡型，不和比較卡的組撞）。
- **題型**：`questionType` 照舊回 `pick`（組卡與作答都是點選填空）；家長看得到的題型名稱是「配對」「單選」（§9）。

## §5 作答、紀錄與畫面（`src/review/pick.ts`、`src/ui/PickCard.tsx`）

- **作答與四級**：照點選填空，不改：第一次對是記住了，再選對是差一點，再選也錯或按沒印象是沒印象；全對可以按太簡單。要按「對答案」才判，對答案前可以改。
- **紀錄**：照比較卡，不加欄位、不用 `need`：`pick` 是對答案時那一格選的字鍵（照顯示的字），第一次按沒印象是 `null`；`retry` 是再選的結果；`also` 是同一個目標多放的那一題；`with` 是同一張卡第二個目標起指向第一行。舊版讀這些行照 `pick-old-version.test.ts` 的做法驗。
- **畫面**：
  - 每一格一列：題幹有 `＿＿` 就填在空格（現在的做法）；沒有空格時，題目下面一格。
  - 對答案後：填好的每一列就是對照；每個目標的記憶錨點接在自己那一列下面。不畫連線、不拖曳。
  - 長的選項字鍵（3～5 字）照現在的字鍵排；Windows 看一次，iPhone 併進 0.7.0 那一次。

## §6 AI 草稿的檢查與加題核對（`src/core/ai/check.ts`、`existing.ts`）

- **錯誤（擋住、退回 AI）**：有選項行但 §3 的條件不成立；選項有「以上皆是」「以上皆非」；有選項行的目標的題幹有「下列」「以下何者」。
- **提醒級不做**：外掛不列提醒級（`reply.ts` 的 `checkPiece`），只有代審看得到；「同一篇兩組選項只差一項」等試作的結果（§0 第 2 件）再決定。
- **加進已有的學習目標**：加題之後那個目標的卡型（`kind.id`）或 `single.key` 變了就留在框裡、寫原因（擋住「已有的翻面目標改成單選」，也擋住加了一題答案不在選項裡）；加題核對已有的七種加題照舊寫得進去。
- **搬候選**：候選裡的選項行跟著搬，搬完的卡型摘要和在框裡時相同（`move.ts` 現有的核對）。

## §7 規則（`apps/Cards/docs/card-rules/elementary-social.md`，國小社會預設跳下一版）

只寫在國小社會預設、勾「點選填空」時才送的那一段（沿用現有的勾選，不另開一格；社會預設不勾，0.7.0 會勾的只有使用者自己）。提示版號加一、嵌進外掛的內容與雜湊跟著改（D-151）。規則重整的比較測試（D-228）的快照已凍結，不受影響；測試結束後這一節跟著勾選的寫法搬進核心。

- **用在哪（兩句）**：要練的是把一個例子或描述歸到固定的幾類，或一組對應容易互相記混，而且題幹自己就能回答；出處要指得到教材的分類或對照表、習作用選或連的那一題、或架構段寫的邊界，指不到就不加選項行。
- **不用的**：「下列何者」「哪一個不是」、是非、只有兩項的配對、彼此不相干的一組、定義、原因、語詞解釋、計算。
- **選項從哪裡來**：只准來自教材：固定的類別、同一組其他目標的答案、架構段「邊界」寫的錯答；自己編的不收，湊不出兩個錯的選項就不加選項行。3～5 個；類別本來有 4、5 個就全列。
- **配對**：同一組的每個目標寫**完全相同**的選項行（同樣的字、同樣的順序），一組 3～5 對。
- **自我檢查**：試填每個選項，只有一個說得通。
- 例子用國小社會預設現有的海岸結構（只示範結構）。

## 驗收

- **行為不變**：沒有選項行的卡組，現有測試不改；`compare-versions` 對兩個正式 vault 零差異（§8）。
