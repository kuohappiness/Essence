## 和「不做」比較（D-153）

- **不做會怎樣**：多音字照現在的讀音卡，一張一句「『長』怎麼念？」，翻面自評：孩子在心裡念一個讀音就翻面，念錯了也可能以為自己對了；一次只看一句，沒有在句子之間比，段考的「選出讀音相同的」練不到（D-230 理由）。「相似詞」的名稱寫壞時，AI 的草稿照樣存進去，退回一般問答，家長看不出比較卡沒做成（查核 3-2）。
- **做的代價**：解析多認一種卡（選項是這個目標自己的，不是組裡別的目標）、組卡多一個分支（一張卡好幾句、每個讀音至少一句）、對照多一種來源（記憶錨點的子項目）、AI 草稿多幾條檢查、國語預設〈讀音〉改寫；紀錄沿用現有欄位，不加新的。都寫成測試。名稱的結尾「讀音」只在名稱有括號時才看，現在的 `長 讀音` 照舊翻面（§1-3），所以舊卡組與沒勾點選填空的家長不受影響。

## 範圍

### 1. 卡組的寫法與認法（`src/core/deck/question-types.ts`、`parse.ts`、`types.ts`）

1. **寫法**（名稱照預設的 `長 讀音`，多一個括號放這個字要比的讀音；句子把讀音的位置寫成緊接在字後面的 `（＿＿）`）：

   ```markdown
   - 長（ㄓㄤˇ、ㄔㄤˊ） 讀音
       - 出處：p.84、[AI 補充]
       - 他長（＿＿）得比哥哥高。 :: ㄓㄤˇ
       - 小樹苗慢慢長（＿＿）大了。 :: ㄓㄤˇ
       - 他是我們班的班長（＿＿）。 :: ㄓㄤˇ
       - 這條路很長（＿＿）。 :: ㄔㄤˊ
       - 夏天的白天比較長（＿＿）。 :: ㄔㄤˊ
       - 妹妹留著一頭長（＿＿）髮。 :: ㄔㄤˊ
       - 記憶錨點：
           - ㄓㄤˇ：長大、帶頭的人：成長、班長
           - ㄔㄤˊ：距離或時間久：長短、很長
   ```

   - 對答案後，空格填進讀音，讀起來是「他長（ㄓㄤˇ）得比哥哥高。」，和考卷的注音寫法一樣。
   - **沒勾點選填空時**（D-210）：名稱不寫括號（`長 讀音`），其他照寫，照翻面出；翻面時記憶錨點照樣出現。不用另外的結尾，因為現在的讀音卡本來就是這個名稱（和相似字要改寫「辨字」不同，§1-3）。
2. **認法**（格式查核 2-1、2-2）：**比較卡先認，照舊**（`readPick`）；它沒有讀出組、也沒有提示或錯誤時，才看多音字。名稱先照 `unbold` 去掉成對的 `**`、`==`（整行粗體 `**長（…） 讀音**` 也認），行尾的 ID 照現有解析先拿掉（ID 前用半形空白，D-134）：
   - `splitName` 讀得出字與括號，**最後一個括號之後剩下的字剛好是 `讀音`**（括號和讀音之間可以有半形或全形空白，也可以沒有）。
   - **選項是最後一個括號**，前面的括號留在名稱裡（`長（大）（ㄓㄤˇ、ㄔㄤˊ） 讀音`）。它不是有效的清單時不往前找，提示。切法照比較卡的組（`membersOf`）；照 `pickKey` 正規化後是空的項目丟掉（`**　**`）；正規化後至少兩個；不能有 `` ` ``、`$`、`[`、`]`、`<`、`>`（全形也算）；名稱的字不在選項裡。
   - **每一題都是多音字句**：問答題、答案單行；題幹照 `unbold` 之後剛好一個空格（`countBlanks`），而且這個空格是**緊接在名稱的字後面的 `（＿…）`**：左括號全形或半形、一個以上連續的全形底線、右括號全形或半形，括號裡沒有別的字（`（**＿＿**）`、`（＿　＿）`、`（&#65343;）`、沒有括號的 `長　＿＿` 都不算）。答案照 `pickKey` 是選項之一。聲調符號的相似字元（`´`、`‵`、`·`）不折成一樣：`ㄓㄤ´` 不等於 `ㄓㄤˊ`。
   - 符合的目標多一個 `choice`（型別見 §1-5）。程式不看選項是不是注音、字是不是一個字，也不分科目（手寫的 `read（/riːd/、/rɛd/） 讀音` 也認）；這兩件只在國語的 AI 草稿檢查（§5）。
3. **不是時照原題型出，不會壞**（和比較卡同一個原則，[syntax §2-3](../syntax.md#比較卡點選填空)；格式查核 2-3）：
   - 名稱沒有括號（`長 讀音`）：照翻面，不提示。這是現在的讀音卡，也是沒勾點選填空的寫法。
   - 名稱照 `unbold` 之後最後一段是 `讀音`（`endingOf`）、有括號，卻不符合第 2 點：照原題型，提示。**一題都不是多音字句**、選項讀不出（不是清單形狀、正規化後少於兩個、有不能有的字元）、括號之後不只 `讀音`（`長（…） 字義 讀音`）：`pick-not-recognized`，訊息寫是哪一條。**至少一題是、其他題不是**：`pick-mixed`，標不是的那幾題。一個目標只有一種提示。
   - 這兩種提示不算寫錯（不跳過目標），存檔按鈕提示；AI 的草稿算錯誤（§5）。原本就停出的照舊：題幹空的、沒有答案（`missing-answer`）、ID 衝突；名稱的字在括號裡的是比較卡，答案是組裡別的字時照舊 `pick-answer-invalid` 停出（`長（長、常） 讀音` 底下答案是常）。
   - **漏認、不提示**：結尾不是單獨的 `讀音`（`長（…）讀音（進階）`、`讀聲`）。標題要改字時，改名稱的結尾就不是多音字卡了。
4. **和其他結尾不互搶**：`choice` 只在最後一個括號之後剛好是 `讀音` 時認，所以全詩順序、句子排序、接句、英文的文法與變化（都看別的結尾）不受影響；有方向、最上層直接寫題目（implicit）、名稱有空格的照舊不看。
5. **型別**（`types.ts`）：`Target.choice?: { word: string; options: readonly string[]; optionKeys: readonly string[]; title: string; notes: readonly string[] }`。word 是括號前面的字、options 照括號裡的寫法（字鍵照它顯示）、optionKeys 是正規化後的寫法、title 是結尾（`讀音`）、notes 是記憶錨點的子項目（解析器已經為全詩順序卡分好的 `notes`，§4-2 用）。不放進 `group`：`group.key` 是「同一組的好幾個目標」的身分，組卡、今天的份與 `需要版本` 都照它併卡與判斷。

### 2. 「相似詞」的結尾（`question-types.ts` 的 `readPick`、`src/core/ai/check.ts`、`src/core/ai/prompt.ts`）

D-230 第 3 點：國語的詞寫相似詞（`反映（反應、反映） 相似詞`），沒勾點選填空時寫「辨詞」。正確的寫法現在已經認得（程式認括號，D-182 第 4 點）；要補的是寫壞時和相似字一樣提示、AI 的草稿一樣擋（查核 3-2）：

1. `readPick` 的 `hinted` 加 `相似詞`：結尾是相似詞、讀不出組或題目不對時提示 `pick-not-recognized`。
2. `check.ts` 的 `PICK_ENDING` 加 `相似詞`（名稱有 `==`、`＿` 的 `pick-name-cloze`、`pick-mixed` 升成錯誤、名稱不用寫成「能……」都跟著）；`pick-title` 的提醒接受 `相似詞`，訊息改成「相似字、相似詞或比較」。
3. `prompt.ts` 兩段都加「相似詞」：勾了點選填空的那段（現在只特列「國語的相似字結尾寫相似字」）加「國語的詞寫相似詞」；沒勾的那句改成名稱最後不要單獨寫「比較」「相似字」「相似詞」（格式查核 3）。任務段改字，版號加一（`提示 v5`、`加深 v3`，兩者共用 `pickRules`）。
4. 錯誤訊息裡的例子照舊用相似字，不另外分。
5. **獨立的「相似詞」是保留寫法**：名稱最後一段單獨是相似詞（前面有空白或右括號）就當成想做比較卡，和相似字、比較一樣；`反映和反應是不是 相似詞`、`反映和反應（近義）相似詞` 這種一般問答也會提示、AI 草稿會被擋。沒有分開的（`反映和反應是不是相似詞`）不算。syntax 寫明。

邊界例子（加進現有的比較卡測試）：`反映（反應、反映） 相似詞` 底下比較句 → 比較卡、沒有 `pick-title`；`反映 相似詞`（漏組）、`反映（反應、反映） 相似詞` 底下 `大家__意見。 :: 反映` → 解析提示 `pick-not-recognized`，AI 草稿是錯誤；`反映和反應是不是 相似詞`、`反映和反應（近義）相似詞` → 同上（保留寫法）；`反映和反應是不是相似詞`、`反映 辨詞`（整組寫在題目最後的括號裡）→ 一般問答，不提示；勾選與沒勾的提示文字各一個斷言。

### 3. 一張卡出幾句（`src/core/study/compose.ts`；待使用者選）

💡 Claude 建議：**比讀音多一句，每個讀音至少一句**。兩個讀音出三句，三個讀音出四句；池裡的句子不夠時全部出。

1. **選句**：照這個目標的出題順序（現有的 `rotation`：指紋相同的算一句，最久沒出的先、次數少的先、再照筆記順序），一張卡裡的指紋不重複（格式查核 5）。先為每個讀音挑順序最前面、答案是它的那一句（照括號的順序），再照順序補到讀音數加一。挑好的格用這張卡的種子打亂（現有的 `assembled`）。
2. **字鍵**：括號裡的讀音，每張卡打亂（現有的 `groupOf` 的打法）。
3. **第一次也一樣**：新的多音字第一次就出讀音數加一句；和比較卡「新卡整組一起出」同一個想法：第一次就看到不同讀音放在一起。
4. **預覽**（`pickPreviewCards` 的做法）：一張「第一次」的卡，其餘不同指紋的句子各一張（一格，字鍵照樣是全部讀音）。
5. **出卡的每個地方**都照這節組卡：今天的份（`session.ts`）、全部卡的一輪與單篇練習、小考（`practice.ts`）、預覽（`preview.ts`）。今天的份不用併卡：一個目標一張（`plan.ts` 的 `groupKey` 只看 `group`，不動）。

為什麼這樣建議：

- **猜對一半**：只有兩個讀音、一張一句時，亂猜有一半的機會對，排程會高估。三句取最差的一格，全猜對的機會是 1/8，比比較卡兩個選項出兩句（D-182 第 7 點，1/4）低。
- **刪去法**：一張卡固定「每個讀音各一句」時，知道一句就知道另一句（D-191 的理由）。多一句之後一定有一個讀音出兩次，刪去法不好用。
- **在句子之間比**：每個讀音至少一句，孩子每次都看到不同讀音放在一起，接近段考的「選出讀音相同的」（D-230 第 4 點的理由）。
- **代價**：一張卡多兩格，每格幾秒；只有到期的多音字才出，份量照每日的時間上限。

另外兩種做法：

- **固定兩句**（照 D-182 第 7 點）：每次少一格，但兩個讀音時常是各一句，知道一句就知道另一句，實際上接近一半一半。
- **一張一句**（照一般的輪替）：最快，但兩個讀音猜對一半，也沒有在句子之間比。

### 4. 作答、計分、對照與紀錄（`src/review/pick.ts`、`src/ui/PickCard.tsx`、紀錄）

1. **作答與計分**照點選填空，不改：點讀音填進空格、對答案、錯的格再選一次（兩個讀音時再選只剩一個能點，和兩個字的相似字組相同）、沒印象。一個目標好幾格取最差的一格（D-187 第 5 點）：每格第一次就對是記住了（全對可以改按太簡單）；有一格第一次錯、再選對是差一點；有一格再選也錯或按沒印象是沒印象。
2. **對照**（D-203 的上下排；格式查核 4-1、4-2）：對答案後每個讀音一行，讀音自己一行，底下是記憶錨點裡那個讀音的子項目；這次考到的照在畫面上第一次出現的順序排前面（`compareOrder`，同一個讀音考到兩次只列一次），沒考到的照括號的順序接在後面。
   - **怎麼對**：記憶錨點的每一行（子項目，和 `記憶錨點：` 同一行寫的字也算一行，照同一個方法）照**第一個**全形冒號切開，前面照 `pickKey` 對到選項；後面照 `anchorParts`（最後一個全形冒號）分成說明與常用詞。同一個讀音只用第一個對到的行。解析時就對好（`Choice.anchors`、`Choice.rest`），組卡不再讀字（study 從 deck 只 import 型別）。
   - **不丟字**：對不到選項的行（同一行寫的說明、同一讀音的第二行、半形冒號的、未知讀音的），照原本的順序一行一行接在對照後面。說明或常用詞是空的就只顯示有的那段；冒號後面整段是空的、沒有子項目的讀音只顯示讀音。
   - **沒勾點選填空、舊版翻面時**：記憶錨點照一般翻面的背面顯示（燈泡與清單），不另排版（格式查核 4-3）。
3. **標題**：卡片最上面淡色小字「讀音：長」（結尾加名稱的字）；不列讀音，字鍵已經列了。
4. **句子底下的詳解**不顯示，和相似字卡相同（點選填空的對照取代詳解）；寫了也不算錯。
5. **紀錄**（格式查核 5）照比較卡同一個目標有好幾格的寫法（[syntax §5](../syntax.md#5-複習紀錄)），**不加新欄位**：一行，最差的那格在最上層（`v` 是那一句的指紋、`pick`、`retry`），其他格放 `also`（各自的 `v`、`r`、`pick`、`retry`）；一個目標所以沒有 `with`；不寫 `cell`（每格是不同的題目）。排程只看最上層的 `r`；`also` 的句子算出過（出題順序用）。同一行裡的 `v` 不重複（§3-1）；同分時取畫面上前面那格（現有的做法）。
6. **舊版**（`0.6.0`；格式查核 1，**待使用者選**）：名稱的字不在括號裡，舊版讀不出組，照翻面出（題目「他長（＿＿）得比哥哥高。」、背面「ㄓㄤˇ」）。紀錄欄位舊版讀得懂（`also`、`pick`、`retry` 舊版已經有），但同一個目標會混進舊版的翻面自評（Codex 用 `v0.6.0` 重現，`reps` 兩筆都算）：這是 D-191 擋住相似字卡的理由。兩條路：
   - 💡 **照翻面、不擋**（同全詩順序卡 D-204 第 6 點、英文的句子排序）：卡組不加 `需要版本`（`move.ts` 的 `needsMark` 只看 `group`，不動）。前提寫進 0.7.0 的發版步驟：兩個 vault 都裝好、每台裝置的 Obsidian 重開之後，才用 AI 製卡做有多音字的國語卡組（AI 製卡的國語規則 v0.11 跟著 0.7.0 才有，所以多音字卡只會在更新後出現）；漏一台時混進的是幾筆自評，不丟資料。Claude 建議這條：擋要改寫進筆記的程式（比較卡的最低版本 `0.4.0` 擋不住 `0.6.0`，存檔、AI 草稿、移入三條路都要改），0.7.0 在 1/19 段考前。
   - **整篇擋住**（同相似字卡 D-191）：有多音字的卡組寫 `需要版本` 0.7.0（取卡組裡每種卡要的最高版本，比較卡的 `0.4.0` 照舊保留），舊裝置整篇不出、提示更新；三條寫入的路與 `pick-old-version` 一類的跨版本測試一起做。

### 5. AI 草稿的檢查（`src/core/ai/check.ts`、`src/core/ai/existing.ts`）

比解析嚴（[syntax §2-10](../syntax.md#2-10-寫錯時)）；本文、候選、加進已有的學習目標都檢查（格式查核 6-3）：

- **錯誤**（退回重做）：
  - 名稱照 `unbold` 之後最後一段是 `讀音`、有括號，卻是 `pick-not-recognized` 或 `pick-mixed`（`choice-invalid`，訊息照解析的原因）。
  - 同一個題幹（照 `pickKey`）出現兩次、答案不同（`choice-ambiguous`：孩子分不出該念哪一個，請換能唯一判讀的句子）。
  - **只在國語的草稿**（格式查核 2-4）：選項不是注音：每個讀音是一到三個注音符號（U+3105～U+3129），前面可以有輕聲的 `˙`，後面可以有 `ˊ`、`ˇ`、`ˋ`（`choice-reading`，訊息寫「讀音照課本寫注音，聲調用 ˊ ˇ ˋ，輕聲的 ˙ 寫在前面」）。
  - 選項沒有句子：括號裡的讀音，有一個不是任何一題的答案（`choice-unused`）。罕用的讀音不放進括號，括號裡也不能放錯的念法當選項（預設〈讀音〉）。
- **不符**（不擋）：
  - 不同指紋的句子，每個讀音少於兩句、只有兩個讀音的少於三句（`choice-few-sentences`，同 `pick-few-sentences`）。多音字不算通用的三題上限（`too-many-questions` 略過 `choice` 的目標），名稱不用寫成「能……」（`target-name` 照比較卡略過，`pickNames` 加多音字）。
  - 有讀音在記憶錨點沒有子項目（`choice-no-anchor`）。
- **提醒**：名稱括號前面不是一個漢字（`choice-word`，只在國語）；記憶錨點的子項目有三個以上全形冒號（`choice-anchor-colon`：常用詞裡不要再用全形冒號）。
- **加進已有的學習目標**（`existing.ts`，格式查核 6-2）：`verify` 比對加題前後的題型時把 `choice` 算進去：加題後原本是多音字的還是多音字、原本翻面的還是翻面，不然退回（「加過去會改到別的內容，請手動搬」）。已有的 `長 讀音`（翻面）照原池的寫法加題；已有的多音字目標只收括號裡的讀音、空格合規的句子。

### 6. 國小國語預設〈讀音〉（`apps/Cards/docs/card-rules/elementary-chinese.md`，跳到 v0.11）

§1～§5 定了、格式查核過才改；版本號一起改 `src/core/ai/rules.ts`。

- **多音字**：勾點選填空時名稱寫 `長（ㄓㄤˇ、ㄔㄤˊ） 讀音`，括號是池裡的讀音，用頓號隔開，照課本的注音；沒勾時寫 `長 讀音`。
- **題目**：一句話，字後面緊接 `（＿＿）`，答案是那一句的讀音（注音）；一句只挖一個字。不用「怎麼念？」的問句。
- **句數**：每個讀音至少兩句，只有兩個讀音的至少三句（同相似字，D-182 第 7 點），不算通用的三題上限；每一句只能有一種念法（只用教育部審訂音只有一種念法的詞，有又讀的不出），同一個題幹不配兩個讀音。
- **記憶錨點**：每個讀音一個子項目：讀音、全形冒號、這個讀音的意思（短）、全形冒號、一兩個常用詞（`ㄓㄤˇ：長大、帶頭的人：成長、班長`）；常用詞裡不再用全形冒號；取代現在每題的詳解。
- **[AI 補充]**（格式查核 6-1）：教材外的讀音照舊在出處加 `[AI 補充]`，那個讀音的錨點說明後面也標（`ㄔㄤˊ：距離或時間久 [AI 補充]：長短、很長`），取代 v0.10「那一題的詳解也標」；同一個教過的讀音換成自己寫的句子不標（v0.10 開頭的說明）。
- **容易念錯、只有一種讀音的字**：照舊 `酵 讀音`、問答翻面，不寫括號（括號不能放錯的念法）。
- **加深與加進已有的目標**：已有的多音字目標只加括號裡的讀音的句子、空格照寫法；要多一種讀音時名稱的括號要改，加題沿用原名，所以先畫在地圖。已有的 `長 讀音`（翻面）照原池的寫法加題，不改成點選。
- 〈相似詞〉、〈和學生已有的目標比對〉：`長（…） 讀音` 和 `長 讀音` 是同一種目標，用字找。
- 預設開頭的「多音字改成點選填空，寫法等程式的任務說明定了再加」改成已做的說法；狀態行與版本說明照改。

## 和題庫模組的關係

「建立題庫模組」討論串（2026-11-25 開，範圍等使用者選）建議把每種卡做成一個題型模組，第一段只搬不改。兩邊會改到同一批檔（`question-types.ts`、`parse.ts`、`compose.ts`、`session.ts`、`practice.ts`、`pick.ts`、`PickCard.tsx`、`check.ts`）：

- **技術債「讀手寫文字的去格式各處自己寫」**（[backlog〈技術債〉](../backlog.md#技術債)，觸發點是下一次改題型）：這次不新寫去格式的 regex，一律用現有的 `pickKey`、`unbold`、`countBlanks`；把各處合成一處的工作，💡 建議觸發點改成題庫模組的重構（同一批檔一次搬完），要使用者同意（D-195）。
