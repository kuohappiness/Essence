## 1. 要做什麼

把第一輪在使用者電腦用臨時腳本跑的比較測試，做成 repo 裡固定的工具：之後給**新的規則組合**和**新課**，照同一套步驟跑出可以比的結果。

- 規則組合不限英文與社會、不限三層：國語、自然、加深模組，以及「AI 提示詞架構」串在談的兩段式送法、照科目分段送出（使用者 2026-11-25 第 4、5 點），都要能放進來比（§4-2 多步）。
- 生成現在有兩種：Claude 由工具自動開新對話；ChatGPT 網頁由使用者手貼。外掛能直接呼叫 AI（D-126）之後加 API 轉接器，每組自動跑 3～5 份（§10）。
- 工具不替人下結論：門檻照開跑前凍結的設定算，要判斷的地方列出來等裁定。

**和不做比**（D-153）：

| | 不做（每次照第一輪手做） | 做成工具 |
|---|---|---|
| 主持的對話 | 第一輪 Remote Control 的對話長到要換串；22 支腳本每次重寫或改路徑 | 每一步一個指令、只印短結果，大檔留在測試資料夾；長的步驟在背景跑，中斷了照紀錄接著跑；裁定也交給另一個對話 |
| 時間 | 手貼與重跑占大半；ChatGPT 6 份全靠使用者 | Claude 的生成、兩位評審都自動；使用者只貼 ChatGPT 與裁定教學選擇 |
| 汙染 | Codex 在 repo 目錄裡讀了 `AGENTS.md`、載入 skill；Fable 自述有幾頁教材沒看 | 每個 AI 對話在只放那一份資料的暫存資料夾開、關掉自訂設定；從對話紀錄核對讀過哪些檔、每一頁都讀了 |
| 事後才定的事 | ChatGPT 算不算門檻、「明顯變差」多少、評分口徑，都在看到結果後才定，有三項在解開後補 | 門檻、份數、算門檻的生成器開跑前寫進設定並凍結；第一輪的口徑寫進評分說明 |
| 雜訊 | 同組兩份的差距常和兩組之間一樣大，每格只有 1～2 份 | 每組可以跑 3～5 份，兩兩比算「明顯」；差距小於組內差距的標「看不出差別」 |

接下來至少要再跑：英文第二輪（[任務說明](rule-restructure-test.md) §9 第 1 點）、國小社會換規則後的確認、國語與自然換三層前、加深模組，以及兩段式與分段送出的設計。

**不做的**：不替人寫結論、不在同一輪中途改規則、不改外掛的產品程式、不寫 vault（凍結時只讀）。

<測試資料夾>/

  生成/  事件.jsonl、原稿/<組>-<課>-<份>[-<步>].md、手貼/、紀錄/（對話紀錄）
  格式/  <組>-<課>-<份>.json

### 4-2 設定（`測試.yaml`，凍結後不改；補跑走 §5-10）

```yaml
名稱: 英文第二輪
課庫: D:\…\比較測試\課
課:
  - 代號: 英文U7
    表單: { 科目: english, 年級學期: 國二下, 單元: "U7 …", 目的: 準備段考, 補充: 否, 點選填空: 要, 家長調整: 無, 教材說明: 課本 p.… }
    已有目標: { vault: D:\…\<vault> }        # 凍結時讀一次
組:
  - 名稱: 現行
    規則: { 外掛: english }                    # 這個 commit 的外掛送什麼就送什麼
  - 名稱: 候選
    規則:
      commit: 288ba1ef                         # 規則檔從 commit 讀，不讀工作樹
      檔案: [apps/Cards/docs/card-rules/next/core.md, …/make.md, …/english.md]
      任務段: { 點選填空說明: 不送, 已有目標說明: 一行, 三段: 要, 已有目標清單: 原寫法 }
  - 名稱: 分段送出                              # 多步（使用者 2026-11-25 第 5 點這類設計）
    步驟:
      - { 對話: A, 規則: { 同: 候選, 檔案: [core.md, make.md, english-grammar.md] }, 卡組: 是 }
      - { 對話: B, 規則: { 同: 候選, 檔案: [core.md, make.md, english-words.md] }, 卡組: 是 }
生成:
  - { 生成器: claude, 模型: claude-opus-5-5, 推理: high, 份數: 3 }
  - { 生成器: 手貼, 服務: ChatGPT, 模型: GPT-6.2 Thinking, 推理: high, 份數: 1, 課: [英文U7] }
評審:
  - { 評審: codex, 模型: gpt-6.2-sol, 推理: high }
  - { 評審: claude, 模型: claude-fable-5-2, 推理: high }
評審重評: 1                                    # 每位評審挑幾個區組另開對話再評一次，量評審自己的雜訊（F20）
裁定: { 裁定者: claude, 模型: claude-opus-5-5, 推理: high }   # 只有一位記的重大錯誤、拿不準的分類（N9）
門檻: { … 見 §6-3 }
```

- **規則的四種來源**：
  1. `外掛`（科目代號，照 `RULE_SUBJECTS` 與 `buildPrompt`）；
  2. `檔案`（從指定 commit 讀，每份只取 `<!-- 以下送給 AI -->` 以下、到第一個 `<!-- 以下只在…送 -->` 為止，和候選規則 README 的組法一樣），加任務段選項；
  3. `同`（沿用另一組，可以只換檔案或任務段選項）；
  4. `自備`（每課每步指定測試資料夾 `提示/` 裡的一個檔；F1）：之後任何新送法都放得進來，不必再加選項。自備檔只認三種變數（N3）：`{{任務段}}`、`{{已有目標清單}}` 在凍結時展開、展開後的全文存進 `凍結/提示/`；`{{A.1}}`（前面某一步的回覆）在生成時代入，代入後的全文存進原稿旁邊。其他 `{{` 擋下。
- **任務段選項**只有第一輪用過的四個：點選填空說明（送／不送）、已有目標說明（外掛原文／一行）、三段（要／不要）、已有目標清單（原寫法／精簡，D-229 的寫法）。全部選外掛的預設時，結果要和 `taskSection` 一字不差（§8 第 2 條）。之後外掛自己改了任務段，就改用 `外掛` 來源，不在工具裡加選項。
- **多步**（F1）：一組的生成可以是好幾步，每一步可以覆寫 `規則`（沒寫就沿用組的）。同一個「對話」代號的步驟接在同一個對話裡說（多輪）；不同代號是分開的新對話（分段送出）。後面的步驟可以在自備提示檔裡寫 `{{A.1}}` 帶前面某一步的回覆（見上面第 4 種來源）。`卡組: 是` 的步驟，各自做格式檢查（產品裡分段送出就是分幾次貼回），卡組段照順序接起來才是評分的那一份。
- **有效原稿**開跑前定義（F6）：有 `<<<完>>>`、卡組段不是空的。無效的自動補一份、照記；不事後挑哪一份重跑。格式檢查有錯誤（存不了）的仍是有效原稿，照樣評內容。
- **設定的檢查**：算門檻的幾組，每課、每個算門檻的生成器份數要相同（F11）；規則檔、自備提示檔、課庫的檔都要在；門檻用到的組與生成器都有定義。

## 5. 步驟與指令

| 指令 | 做什麼 | 誰的時間 |
|---|---|---|
| `init [--from <另一個測試資料夾>]` | 建測試資料夾與 `測試.yaml` 範本；`--from` 沿用另一輪的組、生成器、評審與門檻，只換課（補跑另一課用，§5-10） | |
| `materials <課>` | 只有探針判定要轉頁時才有（§5-1）；探針都過，不做 | |
| `rubric <課>` | 評分表：寫、核對、回應三個新對話，交人看後凍結 | AI 三個對話 |
| `freeze` | 凍結已有目標、各組提示、評分表、範本與設定的雜湊；印每組規則與整份提示的字數；警告用過的課 | |
| `generate [--confirmed]` | 沒加 `--confirmed` 只印要開幾個對話與預估用量（F18）；加了在背景跑自動的生成，手貼的寫好說明 | AI；使用者同意用量 |
| `paste <工作> [<步>]` | 把剪貼簿（或指定檔）存成手貼的原稿 | 使用者貼 |
| `check` | 每份原稿、多步的每個 `卡組: 是` 的步驟，用外掛的 `inspectReply` 檢查格式，只記錄、不改原稿 | |
| `blind` | 匿名、打亂、分區組、建給評審的資料夾（一批一次） | |
| `judge [--confirmed]` | 同 `generate`：先印計畫，加了在背景跑兩位評審，驗 JSON、核對讀過的頁 | AI |
| `disputes [--confirmed]` | 合併兩位評審；只有一位記的重大錯誤交給新的隔離對話裁定，教學選擇列給使用者 | AI；使用者答教學選擇 |
| `unblind` | 檢查那一批鎖定與裁定都完成，解開、算指標與門檻，寫結果 | |
| `extend` | 補跑同一批課：把追加的份數寫成新的一批（§5-10） | |
| `status` | 每一步、每一批做到哪裡、缺什麼；背景工作的進度 | |

每個指令重跑都安全：做過的跳過，凍結過的檔不覆蓋（寫檔用 `wx`），和凍結的雜湊不同就停下並說是哪個檔。

### 5-1 教材

要不要轉頁看兩個探針（N6）：`claude` 能不能把整份 PDF 當附件送（P3a），和 Codex 讀不讀得了 PDF（P6）。兩個都行就不轉頁，生成與評審都讀同一份 PDF。任一個不行，就把第一輪的 `pdfpages.mjs` 搬進工具，在 §11 第 2 步（加 Codex 評審）之前做好，相依在第 0 步看原腳本決定，不加原生套件進外掛的 lockfile（F16）；兩位評審看到的教材形式不同時，記進結果。結論（2026-11-25，§9）：P3a、P6 都通過，不轉頁、不做 `materials`。

### 5-2 評分表

- 格式：Markdown 表 `| 列 | 類別 | 要考的知識或判準 | 頁碼 | 可以接受的等價做法 | 跨單元 |`；類別是必備、加分或重大錯誤；跨單元寫 `加題 <ID>`、`另立`、`疑似重複 <ID>` 或空白。工具檢查列號不重複、類別合法、ID 在已有目標快照裡。
- 流程照第一輪：寫的一方沒讀任何製卡規則（範本裡只給教材、已有目標快照與格式）；另一位逐列核對；寫的一方逐項回應接受、部分接受或不接受；操作的 Claude 看過、必要時問使用者，才凍結。三個對話的模型照設定（預設寫 Fable 5.2 high、核對 Codex）。
- 一課的評分表凍結後跨輪共用；改了存成新版，結果註明用哪一版，不同版的分數不直接比。

### 5-3 凍結

- **已有目標**：用外掛的 `readDecks` 讀 vault（照外掛同樣的篩選：同一科、年級學期不晚於這一課、啟用或暫停、讀得懂、有 ID；重複的 ID、需要新版的卡組與和它同 ID 的目標不送，和外掛 `state/index.ts` 的 `aiExisting` 用同樣的核心函式判斷），存兩份：送給 AI 的清單（`existingTargets`、英文另有 `learnedWords`），和給評審的完整題池（每個目標的每一題）。只讀，不寫 vault。篩選的組合寫在 `state/` 裡、工具不能整段沿用的部分，用 §8 第 16 條對第一輪的快照驗。
- **提示**：每組每課（多步的每一步）存一份，記字數與 SHA-256。
- **鎖**：`鎖.json` 記設定、評分表、範本、提示、已有目標的雜湊與凍結時 repo 的 commit；`外掛` 來源用到的檔在工作樹有沒 commit 的修改就停下。之後每一步開頭只核對這些凍結檔的雜湊，不要求 repo 停在同一個 commit（一輪會跨好幾天，N8）；`check`、`blind` 等步驟記下當時的 commit。
- **用過的課**（F15）：讀 `課庫/<課>/使用紀錄.md`，這一課解開過、而且候選規則的 commit 比那次解開晚時，印警告「這一課只能當回歸，不算新課」。

### 5-4 生成

- 工作＝組 × 課 × 生成器 × 第幾份；`事件.jsonl` **只追加事件**（開始、完成、失敗、逾時、額度用完、中斷），狀態由事件推出（F6）。
- `generate --confirmed` 在背景跑，進度寫檔，`status` 讀檔；主持的 Claude 不在前景等。測試資料夾放一個行程鎖檔：已經有一個 `generate`、`judge`、`disputes` 或 `rubric` 在跑時，再下一次就停下，不開重複的對話（N4）。開跑時把「跑中但行程已不在」的工作記成中斷、照規則重跑。
- 自動的生成器在暫存資料夾開新對話（§7）。送法照探針結果：PDF 當附件、不開工具（最接近家長用網頁與 D-126 的產品接法）；不行才給路徑讓它用 Read 讀，並從對話紀錄核對每一頁都讀了，記進每一份。附件說明各組相同，記進鎖。
- 手貼：`手貼/<工作>.md` 寫清楚用哪個服務、模型與推理設定、附哪一個 PDF、照順序貼哪幾段；使用者複製回覆後，操作的 Claude 執行 `paste`。
- **認得額度用完**：整個佇列停下、記下重置時間、不重試，`status` 印出來。另有斷路器：連續 3 個工作失敗就整個佇列停下（P8 實測不了，認不出額度用完時不會把剩下的全部記成失敗，N4）。
- **放棄與再試**：同一份試滿 3 次（失敗、逾時、中斷都算一次）就放棄，`status` 列出原因。操作的 Claude 看過原因、決定再試時加 `--retry`：記一筆「重開」事件，再給 3 次，嘗試的號碼接著算、前幾次的紀錄留著。評分（§5-7）一樣。
- 平台中斷、格式失敗都照記，不刪原稿；無效原稿照 §4-2 自動補一份。

### 5-5 格式

用 `inspectReply`（`三段` 依組設定），記錯誤與提示的數目和內容；多步的每個 `卡組: 是` 的步驟各檢查一次。有錯誤的原稿照樣評內容，結果另列「存不了」（第一輪口徑）。目標數、題數、候選、加題照 `inspectReply` 的 `pieces` 數（分篇、加題框、候選分開），不叫評審數（F5）。

### 5-6 匿名與區組

- **切法**（第一輪語意，F5）：三段的只留 `<<<卡組>>>` 到**最後一個** `<<<完>>>` 之間；不分段的整份留、切掉最後一個 `<<<完>>>` 之後；外層程式碼框只拿掉頭尾一行；換行統一、結尾一個換行；字一個不改。三段的找不到 `<<<卡組>>>` 就停下給人看。多步的把 `卡組: 是` 那幾步的卡組段照順序接起來。
- 掃洩漏字樣（組名、生成器與模型的名稱、`<<<` 標記），掃到就停下給人看。
- 代號每課各自打亂（`crypto.randomInt`）。**區組**：同一課、同一個生成器，每組各取一份成一個區組，順序打亂；一個區組最多 4 份、一定有基準組（組多時拆成幾個區組，各含基準組的一份，F11）。拆開時，每個候選組一定和基準組同一個區組，門檻用那個區組的評分；同一份基準稿在別的區組被評的那一次，只給同區組的其他組（例如精簡組）對照，報告註明（N7）。給評審的資料夾：評分說明、評分表、教材、已有目標的完整題池、這個區組的卡組（加行號）。
- 對照表寫進 `封存/對照表-批N.json`，欄位照第一輪（課、代號、原稿、原稿與匿名卡組的雜湊、字數）。

### 5-7 評分

- 每個區組、每位評審一個新對話（§7），只拿到那個區組的資料夾。
- **評分說明**（範本）包含第一輪的固定口徑：同義答案沒收、一個目標混兩個判準是題目品質，不是重大錯誤；只出現在題幹或詳解、沒被考到算部分；複習時看不到目標名稱，只在名稱裡的不算洩漏，同一個目標另一張卡的題幹露出答案照算；記憶錨點翻面後才顯示，裡面有答案字不算洩漏；加題加到判準不合的已有目標、教錯字義算重大錯誤；格式不評。科目特有的口徑（例如英文變化目標的括號）寫在 `templates/口徑/<科目>.md`，評那一科才放進去。
- **交的 JSON**（F9）：每份卡組逐列先寫證據（承接的目標名稱與行號），再寫「有／部分／沒有」；重大錯誤、題目品質（洩漏、多解、一題多事、池裡判準不同、其他）、近義重複（兩行）、跨單元去向、值得學但評分表沒有的，每一筆都寫行號（洩漏寫露出答案的那一張卡）；留一個「拿不準」的自由欄位。schema 只用兩家 CLI 都收的最小集合（陣列、enum、全部必填、不用動態鍵）；列數、行號、頁數由工具驗。
- **驗**：列號和評分表一樣、一列一筆；行號落在某個目標或某一題上；證據的行號真的是那個目標。格式不合就在**同一個對話**補正（`--resume`），其他判定不會跟著變；從對話紀錄看到有頁沒讀，才開新對話重評。再不合格算試了一次，試滿 3 次標失敗，由操作的 Claude 決定（再試用 `judge --retry`，§5-4）。探針證明不了讀過哪些頁時，退回第一輪後來的做法：逐頁交一行看到的重點（F7）。
- **評審重評**：設定的 `評審重評` 個區組，同一位評審另開對話再評一次，只報兩次的差，不進門檻（F20）。
- **鎖定**：一課、一批所有區組兩位都交了，算每個結果檔的雜湊寫進 `鎖定.md`。

### 5-8 合併與裁定

- 每格合併照 §6-2，一有一沒有、一有一部分都算部分，只在明細列歧見數（F10）。
- **要裁定的只有兩種**：只有一位記的重大錯誤；教學選擇（例如第一輪「認識字彙的中翻英算不算必備」）。重大錯誤交給一個新的隔離對話照定義重判、寫理由（看得到教材與那一份卡組，看不到組別）。教學選擇的來源是兩位評審的「拿不準」欄位：工具彙成一個檔，由同一個裁定對話分出哪些是教學選擇、哪些照口徑就能判（N9）；教學選擇列給使用者。裁定用的模型寫在設定。主持的 Claude 只看結論、不逐筆讀，寫進 `裁定.md`。
- 程式找到、兩位評審都沒記的洩漏候選（照第一輪 `cross.py`：同一個目標裡一張卡答案的粗體字出現在另一張卡的題幹）另列一個數，不進門檻。
- 裁定在**解開前**做；原評分不改，結果另算。

### 5-9 解開與結果

- 解開前檢查：那一批鎖定完成、`裁定.md` 每一列都有裁定。解開後寫 `課庫/<課>/使用紀錄.md` 一行。
- `結果/明細.md`、`明細.json`（私人）：逐課、逐組、逐生成器、逐份的指標，逐列的漏與部分，評審 × 生成器的分項（Codex 評 GPT 系列的生成器時另報，Fable 審查的問題 5），門檻的判讀。`明細.json` 留著給之後跨輪合併（§10）。
- `結果/摘要.md`：只有數字與結論，沒有教材內容與題目原文，可以直接貼進試用紀錄與任務〈結果〉。
- 解開後發現的事實錯誤（例如評審誤讀頁碼）照第一輪：另寫一節，寫明是事實不是口徑，原結果照留。

### 5-10 補跑（批）

D-228 規定結果相反時要補跑（第一輪補了三次）。補跑不改 `測試.yaml`（F2）：

- **同一課多跑幾份**：`extend` 把追加的工作寫進 `追加.jsonl`，記原因、時間、是不是在某一批解開之後才加；只能加已凍結的課、組與生成器的份數，規則與門檻不能改，加完照樣跑 §4-2 的設定檢查（算門檻的組份數相同）。
- **加一課**（例如 D-228 的「補跑另一課的 ChatGPT」，N2）：開新的測試資料夾，`init --from <這一輪>` 沿用同一份組、生成器、評審與門檻的設定；凍結時核對規則檔與範本的雜湊和原本那一輪相同，不同就停下。結果分開報，門檻本來就逐課判（§6-3），怎麼合由人寫。
- 新的一批有自己的對照表、鎖定與區組編號；`unblind` 只解已鎖定的那一批，結果標出哪幾份是後補、在哪一批解開後才加。
- 解開後才加的批，結果照記，但判讀時標「看過前一批結果才決定加跑」。

## 6. 指標與門檻

### 6-1 每一份的指標

| 指標 | 怎麼算 |
|---|---|
| 必備：有、部分、沒有；每份漏的列數 | 合併後的逐列（§6-2） |
| 加分：有、部分 | 同上 |
| 重大錯誤 | 合併、裁定後 |
| 題目品質 | 兩位聯集去重：行號用 `parseDeck` 歸到題，同一份、同一題、同一種算一筆；另報兩位都記與只有一位記的數 |
| 近義重複 | 同上，以對計 |
| 跨單元去向對錯 | 評分表有寫的列 |
| 會直接進孩子複習的錯 | 重大錯誤＋題目品質（每筆 1）；另報「不算多解」的版本與每題的平均 |
| 目標數、題數、候選、加題 | `inspectReply` 的 `pieces` |
| 存不了 | `inspectReply` 有錯誤 |
| 規則字數、整份提示字數 | 凍結的提示 |
| 生成時間、用量、讀了幾頁 | `事件.jsonl` 與對話紀錄 |

主要指標都是**每份的絕對數**；每題平均只當參考（第一輪 ChatGPT 題數多、錯也跟著多）。

### 6-2 合併兩位評審

| Codex＼Fable | 有 | 部分 | 沒有 |
|---|---|---|---|
| 有 | 有 | 部分 | 部分 |
| 部分 | 部分 | 部分 | 部分 |
| 沒有 | 部分 | 部分 | 沒有（＝漏） |

歧見（有對部分、有對沒有）只在明細列數，不裁定（第一輪口徑：一有一沒有算部分、不從嚴改判）。

### 6-3 門檻（設定裡寫，開跑前凍結）

- **基準組、候選組、哪幾個生成器算門檻**（第一輪「ChatGPT 算不算」沒寫，這次一定要寫）；其他生成器（例如 `codex`）只報告。
- **重大錯誤**：設定二選一（F12）：`不比基準多`（預設，[D-234](../../../../docs/decisions.md#d-234-比較測試的重大錯誤門檻改成每份平均不比現行多)：候選每份的平均不比基準多，另外列出只有候選才有的錯的種類給人看）；或 `零`（候選組每一份有效原稿都是 0，D-228 原文）。
- **不多漏必備**（F3c）：每課、每個算門檻的生成器，兩條都要過：
  1. 逐列：「漏的比例」＝漏的份數 ÷ 份數；候選比基準高出設定的差距以上（預設 0.5，意思是多過一半的份數漏了）就算多漏那一列。只有一份時等於第一輪的比法。
  2. 總數：候選每份漏的列數平均，比基準多出設定量以上（預設 1 列）就算多漏。抓「每份各漏不同的列」這種分散的漏。
  
  另外檢查近義重複沒有多出設定的量（不能靠重複題補覆蓋率）。
- **明顯**（F3b）：候選的每一份和基準的每一份兩兩比，數候選贏幾場（平手算半場）。贏的場數達到工具算的門檻（「隨便亂排也贏這麼多場的機會在 5% 以下」，照兩組實際的份數現算，份數不同也算得出：例如 3 對 3 要 9 場全贏、4 對 4 至少 15 場、5 對 5 至少 21 場），而且平均差達到設定的量，才算明顯。結果寫成「隨便各抽一份，候選比較好的機會有幾成」。
- **收益**：設定列出收益指標與最少的改善（例如規則字數少 20%、會直接進孩子複習的錯少 20%），至少一項達到（N1）：
  - 固定算的指標（規則字數、整份提示字數）達到設定量就算達到（第一輪社會靠這一項過）；
  - 會變的指標，兩組都有 3 份以上時要**明顯**達到；任一組不到 3 份時（算門檻的 ChatGPT 手貼預設 1 份），平均達標就算，結果標「份數不夠」。
- **不能變差**（F3a）分三態：平均在容許量內＝過；超過容許量而且明顯＝沒過；超過但不明顯＝**未定**，照 D-228 維持現行、加份數或加一課。任一組不到 3 份時，超過容許量一律算未定（N1）。資料吵不再讓候選比較容易過。
- 門檻**逐課、逐生成器**各判一次，工具不跨課、不跨生成器合併，怎麼合由人寫（N1）。
- 結果翻轉（補跑的方向和前一批相反）、或裁定解不開時，照 D-228：那一科維持現行、再加一課。工具只標出來，結論由人寫。

## 7. AI 對話怎麼開（轉接器）

| 轉接器 | 用在 | 做法（旗標以探針結果為準） |
|---|---|---|
| `claude` | 生成、評審、評分表、裁定 | `claude -p --safe-mode --strict-mcp-config --model <模型> --effort <等級> --output-format stream-json`，提示從 stdin 給；生成優先把 PDF 當附件送、`--tools ""`（不開工具），不行才 `--tools Read`；評審加 `--json-schema`；多輪用 session ID `--resume` |
| `codex` | 評審、評分表核對；也可以當生成器（標 `codex`，只報告、不算門檻） | `codex exec --skip-git-repo-check -C <暫存資料夾> --sandbox read-only -m <模型> -c model_reasoning_effort=<等級> -c approval_policy="never" --output-schema <檔> -o <檔> -`；多輪用 `codex exec resume` |
| `手貼` | ChatGPT 網頁（之後任何沒有 CLI 的服務） | §5-4 |
| `api` | 外掛能直接呼叫 AI 之後 | 延後（§10） |

- **隔離**（F13）：每個對話在系統暫存資料夾裡新建的資料夾開，裡面只放那一個工作要讀的檔；提示裡不給其他路徑。`--safe-mode` 關掉 `CLAUDE.md`、skill、外掛、hook，`--strict-mcp-config` 不載 MCP；每次從 stream-json 的開頭事件核對實際的工具、MCP 與模型。事後從對話紀錄查有沒有讀暫存資料夾以外的檔，有就把那一份標成汙染、重跑（Codex 的唯讀沙箱只擋寫入，不擋讀）。結束後把要留的輸出與對話紀錄搬回測試資料夾、刪掉暫存（逾時的也刪）。
- **系統提示**：做成設定並記雜湊（預設一段中性的說明：你是助理、附件是教材）。它去掉寫程式 agent 的指示，但網頁的系統提示、附件處理與記憶都複製不了，所以只說「同一套條件下比組別」，不說「等於網頁」。第一次使用時加一份 Claude 網頁手貼當校準，只報告。
- **ChatGPT**：`codex` 生成器不能代表 ChatGPT 網頁（模型變體、系統提示、讀檔方式都不同）；算門檻的課照舊每課至少一份手貼當錨。兩者並排一輪、題數、近義重複與候選減基準的方向都一致，才考慮取代手貼。
- **暫存資料夾的壽命**：多輪對話與 JSON 補正要靠 `--resume`，所以暫存資料夾等整個對話（含補正）結束才刪，也不能用 `--no-session-persistence`。
- **逾時**：每個對話有上限（設定，預設 40 分鐘）；到了就結束整個子行程樹（Windows 用 `taskkill /T /F`），記成逾時，不讀晚到的輸出；同一份最多自動重試一次，再失敗留給人決定。額度用完不算失敗、不重試（§5-4）。
- **同時跑**：每個轉接器同時幾個寫在設定（預設 2）。事件檔只追加、一行一筆，同時寫不互相蓋掉。
- **用量**：`claude` 讀 stream-json 的用量與時間；`codex` 讀 session 紀錄最後一筆 token 數（同 `tools/codex.ts` 的做法，在工具裡另寫一份，因為外掛的程式不 import 最上層，D-208 第 10 點）。額度是同一個帳號共用的，開跑前的計畫印出這一次預估占多少。
- **開跑前同意**：`generate`、`judge`、`disputes`、`rubric` 沒加 `--confirmed` 只印計畫與預估用量（D-212 第 2 點的精神）；操作的 Claude 拿去問使用者。

## 8. 驗收條件

程式能判斷的（雲端用自編的小 vault 與假的 CLI 測，預期值寫字面）：

1. `外掛` 來源的提示：規則部分等於 `tools/build.mjs` 的 `embedRules()` 產生的文字，任務段等於自編 vault 的字面預期值（F14：不拿 `buildPrompt` 自己比自己）。

3. 規則檔照起訖標記裁切：只有開始標記、有 `<!-- 以下只在加深時送 -->`、標記前後空行三種例子。
4. 凍結兩次產生的檔一字不差；凍結後改了設定、評分表、範本或自備提示檔，之後的指令停下並說是哪個檔。

6. 測試資料夾在 repo 裡時，`init` 與每個指令都停下。
7. 設定檢查：算門檻的組份數不同、規則檔不在、門檻用到沒定義的組，各自擋下並說原因。
8. 匿名：三段、不分段、外層有程式碼框、兩個 `<<<完>>>`、有格式錯誤（`inspectReply` 有錯誤）的原稿、多步接起來，各切得對；格式沒錯的原稿切出的範圍和 `inspectReply` 的 `pieces[].lines` 涵蓋的範圍相同（不新增產品程式的匯出，N5）；三段的找不到 `<<<卡組>>>` 時停下；匿名卡組裡掃不到組名、模型名與 `<<<`；給評審的資料夾裡沒有對照表、全貌、架構與其他區組的卡組。
9. 區組：三組各 3 份時每個區組剛好每組一份；五組時拆成每個最多 4 份、每個都有基準組；同一個種子打亂結果一樣。
10. 評審 JSON：少一列、多一列、判定不是有／部分／沒有、行號不在任何目標或題上、證據行號不是那個目標，各自不合格並說原因；格式補正走同一個對話（假 CLI 收到 `--resume`）。
11. 合併表 §6-2 的九格各有一例；題目品質指到同一題不同行（名稱行與題目行）的兩筆去重成一筆，不同題不去重。
12. 解開前那一批沒鎖定、`裁定.md` 有空格時停下；解開後才讀得到那一批的對照表；第二批還沒鎖定時解開第一批，讀不到第二批的對照表。

  → [D-234](../../../../docs/decisions.md#d-234-比較測試的重大錯誤門檻改成每份平均不比現行多)（2026-11-25）
