# 製卡規則的比較測試工具（給 Claude）

狀態：規劃中｜下一步：Fable 5.2 high 審這份規劃，同意後照 §11 實作｜等誰：Claude

來自：[比較測試第一輪](rule-restructure-test.md)（D-228）與 Cards backlog〈製卡規則的比較測試做成固定工具〉（使用者 2026-11-25：「開新的討論串 xhigh 去做這個測試工具，現在就開始，規劃做好先問一下 fable 5.2 high，同意後再實作」）

遵守 repo 根目錄的 `AGENTS.md`。建議模型與推理等級：規劃 **Opus、xhigh**；實作 **Opus、high**。第一輪的做法見[任務說明](rule-restructure-test.md) §10、§11 與〈結果〉；第一輪 22 支臨時腳本的技術摘要在專案檔案 `比較測試工具/第一輪腳本/摘要.md`（腳本本身在使用者電腦 repo 外，路徑寫死）。

## 1. 要做什麼

把第一輪在使用者電腦用臨時腳本跑的比較測試，做成 repo 裡固定的工具：之後給**新的規則組合**和**新課**，照同一套步驟跑出可以比的結果。

- 規則組合不限英文與社會、不限三層：國語、自然、加深模組，以及「AI 提示詞架構」串在談的兩段式送法、照科目分段送出（使用者 2026-11-25 第 4、5 點），都要能放進來比（§4-2 多步）。
- 生成現在有兩種：Claude 由工具自動開新對話；ChatGPT 網頁由使用者手貼。外掛能直接呼叫 AI（D-126）之後加 API 轉接器，每組自動跑 3～5 份（§10）。
- 工具不替人下結論：門檻照開跑前凍結的設定算，要判斷的地方列出來等裁定。

**和不做比**（D-153）：

| | 不做（每次照第一輪手做） | 做成工具 |
|---|---|---|
| 主持的對話 | 第一輪 Remote Control 的對話長到要換串；22 支腳本每次重寫或改路徑 | 每一步一個指令、只印短結果，大檔留在測試資料夾；中斷了照狀態接著跑 |
| 時間 | 手貼與重跑占大半；ChatGPT 6 份全靠使用者 | Claude 的生成、兩位評審都自動；使用者只貼 ChatGPT 與裁定教學選擇 |
| 汙染 | Codex 在 repo 目錄裡讀了 `AGENTS.md`、載入 skill；Fable 自述有幾頁教材沒看 | 每個 AI 對話在只放那一份資料的暫存資料夾開；評分逐頁交確認，缺頁就重評 |
| 事後才定的事 | ChatGPT 算不算門檻、「明顯變差」多少、評分口徑，都在看到結果後才定，有三項在解開後補 | 門檻、份數、適用的模型開跑前寫進設定並凍結；第一輪的口徑寫進評分說明 |
| 雜訊 | 同組兩份的差距常和兩組之間一樣大，每格只有 1～2 份 | 每組可以跑 3～5 份，報每份的值與範圍；差距小於組內差距的標「看不出差別」 |

接下來至少要再跑：英文第二輪（§9 第 1 點）、國小社會換規則後的確認、國語與自然換三層前、加深模組，以及兩段式與分段送出的設計。

**不做的**：不替人寫結論、不在同一輪中途改規則、不改外掛的產品程式、不讀寫正式 vault 以外的地方（凍結時只讀 vault）。

## 2. 第一輪學到、工具要改掉的

| # | 第一輪的情形（摘要的出處） | 工具的做法 |
|---|---|---|

| 2 | 評審一個對話評一課全部卡組（S1～S6，後補另開資料夾） | 份數變多後一個對話太長：改成**每個評分對話一個區組**＝同一課、同一個生成器，每組各一份、順序打亂（§5-7） |
| 3 | 評審交 Markdown 表，偶爾走樣，解析要寬鬆 | 改交 JSON，用 CLI 的 schema 驗（`claude -p --json-schema`、`codex exec --output-schema`，§9 先探）；不合格重評一次 |
| 4 | 合併：有＋沒有標 `??` 人工處理；有＋部分靠寫死在腳本的裁定 3、4 | 合併規則寫死在程式（§6-2）；要人判的列成清單，裁定寫進檔、工具讀檔重算 |

| 6 | 洩漏只在目標名稱裡的、在記憶錨點裡的，解開後才決定不算 | 寫進評分說明的固定口徑（§5-7）；另外照 `cross.py` 的做法列程式找到、評審都沒記的洩漏候選給裁定的人看 |

| 8 | 評分鎖定：兩位都交了才算雜湊、寫鎖定表，之後才打開對照表 | 照搬，由工具做：解開前檢查鎖定與裁定都完成 |

## 3. 放在哪裡、誰跑

- **程式**：`apps/Cards/tools/rule-test/`，`npm run rule-test -- <指令> <測試資料夾>`。直接 import 外掛的 `src/core`（`buildPrompt`、`existingTargets`、`learnedWords`、`RULE_SUBJECTS`、`ruleText`、`parseDeck`、`inspectReply`、`normalizeReply`），所以現行組的提示和外掛複製出來的一字不差；外掛的提示改了，工具跟著改，測試會抓到不一致。只加 devDependency，不進外掛的建置。
- **範本**：評分說明、評分表寫作與核對、追原因、第二道查核的提示，放 `apps/Cards/tools/rule-test/templates/`，改了要過 repo 的檢查；每次用的版本與雜湊記進測試資料夾。
- **說明**：怎麼跑寫在 `apps/Cards/tools/rule-test/README.md`（給操作的 Claude）；這份任務說明只寫規格。
- **測試資料夾在 repo 外**，私人資料（教材、vault 快照、原稿、評分表、評分）只在使用者電腦（D-003）。工具擋在 repo 裡建測試資料夾。repo 只收程式、範本、說明，和寫進[試用紀錄](../card-rules/trials.md)與任務〈結果〉的彙總。
- **誰跑**：使用者電腦上的 Claude（本機 session，或雲端串開 Remote Control；D-212 第 4 點：碰 vault 的在本機）。使用者只做三件事：同意開跑的用量、貼 ChatGPT、裁定教學選擇。

## 4. 測試資料夾與設定

### 4-1 資料夾

```
<課庫>/<課代號>/                    每課一份，跨好幾輪共用
  教材.pdf                         只含這一課的頁
  頁面/p001.png …、文字.md          materials 產生
  評分表.md                         凍結後不改；要改就存成評分表 v2.md
  使用紀錄.md                       解開時工具加一行（哪一輪用過、結果已經公開）
<測試資料夾>/
  測試.yaml                         設定（§4-2）
  凍結/  鎖.json、已有目標/<課>.json、提示/<組>-<課>[-<步>].md、範本/
  生成/  工作.jsonl、原稿/<組>-<課>-<份>[-<步>].md、手貼/
  格式/  <組>-<課>-<份>.json
  評分/  區組/<課>-B01/（給評審的資料夾）、結果/<評審>/<課>-B01.json、鎖定.md、裁定.md
  封存/  對照表.json                 解開前不讀
  結果/  明細.md（私人）、摘要.md（可以貼進 repo）
```

### 4-2 設定（`測試.yaml`，凍結後不改）

```yaml
名稱: 英文第二輪
課庫: D:\…\比較測試\課
課:
  - 代號: 英文U7
    表單: { 科目: english, 年級學期: 國二下, 單元: "U7 …", 目的: 準備段考, 補充: 否, 點選填空: 要, 家長調整: 無, 教材說明: 課本 p.… }
    已有目標: { vault: D:\…\Ferrie PKM }       # 凍結時讀一次
組:
  - 名稱: 現行
    規則: { 外掛: english }                    # 這個 commit 的外掛送什麼就送什麼
  - 名稱: 候選
    規則:
      commit: 288ba1ef                         # 規則檔從 commit 讀，不讀工作樹
      檔案: [apps/Cards/docs/card-rules/next/core.md, …/make.md, …/english.md]
      任務段: { 點選填空說明: 不送, 已有目標說明: 一行, 三段: 要, 已有目標清單: 原寫法 }
  - 名稱: 分段送出                              # 多步（使用者 2026-11-25 第 5 點這類設計）
    規則: { 同: 候選 }
    步驟:
      - { 對話: A, 送: 整份提示 }
      - { 對話: A, 送: 範本/第二段.md, 卡組: 是 }
生成:
  - { 生成器: claude, 模型: claude-opus-5-5, 推理: high, 份數: 3 }
  - { 生成器: 手貼, 服務: ChatGPT, 模型: GPT-6.2 Thinking, 推理: high, 份數: 1, 課: [英文U7] }
評審:
  - { 評審: codex, 模型: gpt-6.2-sol, 推理: high }
  - { 評審: claude, 模型: claude-fable-5-2, 推理: high }
門檻: { … 見 §6-3 }
```

- **規則的三種來源**：`外掛`（科目代號，照 `RULE_SUBJECTS` 與 `buildPrompt`）；`檔案`（從指定 commit 讀，每份只取 `<!-- 以下送給 AI -->` 以下、到第一個 `<!-- 以下只在…送 -->` 為止，和候選規則 README 的組法一樣），加任務段選項；`同`（沿用另一組）。
- **任務段選項**只有第一輪用過的四個：點選填空說明（送／不送）、已有目標說明（外掛原文／一行）、三段（要／不要）、已有目標清單（原寫法／精簡，D-229 的寫法）。全部選外掛的預設時，結果要和 `taskSection` 一字不差（§8 第 2 條）。之後外掛自己改了任務段，就改用 `外掛` 來源，不在工具裡加選項。
- **多步**：一組的生成可以是好幾步。同一個「對話」代號的步驟接在同一個對話裡說（多輪）；不同代號是分開的新對話（分段送出）。`送` 是 `整份提示` 或範本檔；範本可以用 `{{A.1}}` 帶前面某一步的回覆。`卡組: 是` 的步驟，卡組段照順序接起來才是評分的那一份。
- **課的表單**照外掛製卡畫面的欄位（`CardForm`），各組共用。

## 5. 步驟與指令

| 指令 | 做什麼 | 誰的時間 |
|---|---|---|
| `init` | 建測試資料夾與 `測試.yaml` 範本 | |
| `materials <課>` | 教材 PDF 轉成頁面圖與文字層（每課一次） | |
| `rubric <課>` | 評分表：寫、核對、回應三個新對話，交人看後凍結 | AI 三個對話 |
| `freeze` | 凍結已有目標、各組提示、評分表、範本與設定的雜湊；印每組規則與整份提示的字數 | |
| `plan` | 列出要開幾個對話、預估用量（照上一輪記錄的平均）；不跑 | |
| `generate [--confirmed]` | 跑自動的生成；手貼的寫好說明，列出還缺哪幾份 | AI；使用者同意用量 |
| `paste <工作> [<步>]` | 把剪貼簿（或指定檔）存成手貼的原稿 | 使用者貼 |
| `check` | 每份原稿用外掛的 `inspectReply` 檢查格式，只記錄、不改原稿 | |
| `blind` | 匿名、打亂、分區組、建給評審的資料夾 | |
| `judge [--confirmed]` | 跑兩位評審，驗 JSON、缺頁重評一次 | AI |
| `disputes` | 合併兩位評審，列出要裁定的寫進 `裁定.md` | 操作的 Claude；教學選擇問使用者 |
| `unblind` | 檢查鎖定與裁定都完成，解開、算指標與門檻，寫結果 | |
| `trace`、`review2` | 選用：追漏在哪一步、第二道查核 | AI |
| `status` | 每一步做到哪裡、缺什麼 | |

每個指令重跑都安全：做過的跳過，凍結過的檔不覆蓋（寫檔用 `wx`），和凍結的雜湊不同就停下並說是哪個檔。

### 5-1 教材

把第一輪的 `pdfpages.mjs` 搬進工具：讀 PDF 的頁數與文字層、每頁轉 PNG（解析度照第一輪）。相依實作時看原腳本決定，只能是 devDependency。

### 5-2 評分表

- 格式：Markdown 表 `| 列 | 類別 | 要考的知識或判準 | 頁碼 | 可以接受的等價做法 | 跨單元 |`；類別是必備、加分或重大錯誤；跨單元寫 `加題 <ID>`、`另立`、`疑似重複 <ID>` 或空白。工具檢查列號不重複、類別合法、ID 在已有目標快照裡。
- 流程照第一輪：寫的一方沒讀任何製卡規則（範本裡只給教材、已有目標快照與格式）；另一位逐列核對；寫的一方逐項回應接受、部分接受或不接受；操作的 Claude 看過、必要時問使用者，才凍結。三個對話的模型照設定（預設寫 Fable 5.2 high、核對 Codex）。
- 一課的評分表凍結後跨輪共用；改了存成新版，結果註明用哪一版，不同版的分數不直接比。

### 5-3 凍結

- **已有目標**：讀 vault 的卡組（照外掛同樣的篩選：`isDeckPath`、`parseDeck`；同一科、年級學期不晚於這一課、啟用或暫停、讀得懂、有 ID；重複的 ID、需要新版的卡組與和它同 ID 的目標不送，和外掛 `state/index.ts` 的 `aiExisting` 用同樣的核心函式判斷），存兩份：送給 AI 的清單（`existingTargets`、英文另有 `learnedWords`），和給評審的完整題池（每個目標的每一題）。只讀，不寫 vault。篩選的組合寫在 `state/` 裡、工具不能整段沿用的部分，用 §8 第 16 條對第一輪的數目驗。
- **提示**：每組每課（多步的每一步）存一份，記字數與 SHA-256；`外掛` 來源另外和 vault 裡那一科最新一份 AI 輸出快照的 `送出` 雜湊比對規則部分，不同就印出來（代表 vault 裝的版本和這個 commit 不同）。
- **鎖**：`鎖.json` 記設定、評分表、範本、提示、已有目標的雜湊、repo 的 commit；`外掛` 來源用到的檔在工作樹有沒 commit 的修改就停下。之後每一步開頭都核對。

### 5-4 生成

- 工作＝組 × 課 × 生成器 × 第幾份；`工作.jsonl` 每一行記狀態（等著、跑中、完成、失敗、逾時）、生成器、模型、推理、開始與結束時間、用量、對話 ID。
- 自動的生成器在只放教材的暫存資料夾開新對話（§7）。送出的整份提示前面加一段固定的附件說明（教材在 `教材/`，頁面圖與文字層），各組相同，記進鎖。
- 手貼：`手貼/<工作>.md` 寫清楚用哪個服務、模型與推理設定、附哪一個 PDF、照順序貼哪幾段；使用者複製回覆後，操作的 Claude 執行 `paste`。
- 平台中斷、格式失敗都照記，不刪原稿；要補跑時開新的一份，編號往下接。

### 5-5 格式

用 `inspectReply`（`三段` 依組設定），記錯誤與提示的數目和內容。有錯誤的原稿照樣評內容，結果另列「存不了」（第一輪口徑）。

### 5-6 匿名

- 切法照第一輪（摘要 ①）：三段的只留 `<<<卡組>>>` 到最後一個 `<<<完>>>` 之間；不分段的整份留、切掉 `<<<完>>>` 之後；外層程式碼框只拿掉頭尾一行；換行統一、結尾一個換行；字一個不改。多步的把 `卡組: 是` 那幾步的卡組段照順序接起來。
- 掃洩漏字樣（組名、生成器與模型的名稱、`<<<` 標記），掃到就停下給人看。
- 代號每課各自打亂（`crypto.randomInt`）。**區組**：同一課、同一個生成器，每組各取一份成一個區組，順序打亂；份數不一樣多時剩下的自己成區組。每個區組一個給評審的資料夾：評分說明、評分表、教材頁面與文字、已有目標的完整題池、這個區組的卡組（加行號）。
- 對照表寫進 `封存/`，欄位照第一輪（課、代號、原稿、原稿與匿名卡組的雜湊、字數）。

### 5-7 評分

- 每個區組、每位評審一個新對話（§7），只能讀那個區組的資料夾。
- **評分說明**（範本）包含第一輪的固定口徑：同義答案沒收、一個目標混兩個判準是題目品質，不是重大錯誤；只出現在題幹或詳解、沒被考到算部分；複習時看不到目標名稱，只在名稱裡的不算洩漏，同一個目標另一張卡的題幹露出答案照算；記憶錨點翻面後才顯示，裡面有答案字不算洩漏；加題加到判準不合的已有目標、教錯字義算重大錯誤；格式不評。科目特有的口徑（例如英文變化目標的括號）寫在 `templates/口徑/<科目>.md`，評那一科才放進去。
- **交的 JSON**：每份卡組逐列交「有／部分／沒有」與承接的目標名稱；重大錯誤、題目品質（洩漏、多解、一題多事、池裡判準不同、其他）、近義重複、跨單元去向、值得學但評分表沒有的，每一筆都寫行號；另外**逐頁**交一行看到的重點。目標數與題數由工具用 `parseDeck` 數，不叫評審數。
- **驗**：列號和評分表一樣、一列一筆；行號在範圍內；每一頁都有。不合格就把錯在哪裡附上重評一次；再不合格標失敗，由操作的 Claude 決定。
- **鎖定**：一課所有區組兩位都交了，算每個結果檔的雜湊寫進 `鎖定.md`。

### 5-8 合併與裁定

- 每格合併照 §6-2。要裁定的：有＋沒有；有＋部分而口徑決定不了的；只有一位記的重大錯誤；程式找到、評審都沒記的洩漏候選。工具把它們寫成 `裁定.md` 的表（課、代號、列或行、兩位原判、待填的裁定與理由）。
- 裁定在**解開前**做，由操作的 Claude 照口徑判、教學選擇問使用者（第一輪做法）；原評分不改，結果另算。

### 5-9 解開與結果

- 解開前檢查：鎖定完成、`裁定.md` 每一列都有裁定。解開後寫 `課庫/<課>/使用紀錄.md` 一行。
- `結果/明細.md`（私人）：逐課、逐組、逐生成器、逐份的指標，逐列的漏與部分，門檻的判讀。
- `結果/摘要.md`：只有數字與結論，沒有教材內容與題目原文，可以直接貼進試用紀錄與任務〈結果〉。
- 解開後發現的事實錯誤（例如評審誤讀頁碼）照第一輪：另寫一節，寫明是事實不是口徑，原結果照留。

### 5-10 選用的兩步

- `trace`：解開後，給漏掉的列和那一份的全貌、架構、卡組，請新對話判斷漏在哪一步（全貌沒看到、全貌看到架構沒排、卡組沒照架構）。
- `review2`：第二道查核，照任務說明 §11 的提示，量抓到評審找到的幾成、多抓了什麼、改壞幾處。

## 6. 指標與門檻

### 6-1 每一份的指標

| 指標 | 怎麼算 |
|---|---|
| 必備：有、部分、沒有 | 合併後的逐列（§6-2） |
| 加分：有、部分 | 同上 |
| 重大錯誤 | 合併、裁定後 |
| 題目品質 | 兩位聯集去重（同一份、同一行、同一種算一筆），分種類 |
| 近義重複 | 同上，以對計 |
| 跨單元去向對錯 | 評分表有寫的列 |
| 會直接進孩子複習的錯 | 重大錯誤＋題目品質（每筆 1）；另報「不算多解」的版本與每題的平均 |
| 目標數、題數 | `parseDeck` 數卡組段 |
| 存不了 | `inspectReply` 有錯誤 |
| 規則字數、整份提示字數 | 凍結的提示 |
| 生成時間、用量 | `工作.jsonl` |

### 6-2 合併兩位評審

| Codex＼Fable | 有 | 部分 | 沒有 |
|---|---|---|---|
| 有 | 有 | 部分，口徑決定不了的列出來裁定 | 列出來裁定 |
| 部分 | 同左 | 部分 | 部分 |
| 沒有 | 列出來裁定 | 部分 | 沒有（＝漏） |

### 6-3 門檻（設定裡寫，開跑前凍結）

- **基準組、候選組、哪幾個生成器算門檻**（第一輪「ChatGPT 算不算」沒寫，這次一定要寫）；其他生成器只報告。
- **重大錯誤為零**：候選組每一份有效原稿。
- **不多漏必備**：每課、每個算門檻的生成器，每一列算「漏的比例」＝漏的份數 ÷ 份數；候選比基準高出設定的差距以上（預設 0.5）就算多漏那一列。只有一份時等於第一輪的比法。另外檢查近義重複沒有多出設定的量（不能靠重複題補覆蓋率）。
- **收益與不變差**：設定列出收益指標與最少的改善（例如規則字數少 20%、會直接進孩子複習的錯少 20%），至少一項達到；另列不能明顯變差的指標與容許量。
- **雜訊**：兩組每組都有 3 份以上時，平均差達到設定的量、而且兩組的範圍不重疊，才算「明顯」；範圍重疊的寫「看不出差別」。不到 3 份的寫「份數不夠，只看平均」。固定算的（規則字數）不看範圍。
- 結果翻轉（重跑的方向和第一份相反）、或裁定解不開時，照 D-228：那一科維持現行、再加一課。工具只標出來，結論由人寫。

## 7. AI 對話怎麼開（轉接器）

| 轉接器 | 用在 | 做法 |
|---|---|---|
| `claude` | 生成、評審、評分表 | `claude -p --model <模型> --effort <等級> --output-format json`，提示從 stdin 給；只開 Read（讀教材頁面）；評審加 `--json-schema`；多輪用回傳的 session ID `--resume` |
| `codex` | 評審、評分表核對 | `codex exec --skip-git-repo-check -C <暫存資料夾> --sandbox read-only -m <模型> -c model_reasoning_effort=<等級> -c approval_policy="never" --output-schema <檔> -o <檔> -`；多輪用 `codex exec resume` |
| `手貼` | ChatGPT 網頁（之後任何沒有 CLI 的服務） | §5-4 |
| `api` | 外掛能直接呼叫 AI 之後 | 延後（§10） |

- **隔離**：每個對話在系統暫存資料夾裡新建的資料夾開，裡面只放那一個工作要讀的檔（生成：教材；評審：區組資料夾）；不在 repo、課庫或測試資料夾裡開，讀不到別的組、對照表、規則或 `AGENTS.md`。結束後把要留的輸出搬回測試資料夾、刪掉暫存。
- **系統提示**：`claude` 生成時用 `--system-prompt` 換成一段中性的說明（你是助理、附件在 `教材/`），比 Claude Code 預設的寫程式說明更接近家長用的網頁；可不可以用、會不會被使用者層的設定蓋過，§9 先探。
- **逾時**：每個對話有上限（設定，預設 40 分鐘）；到了就結束整個子行程樹（Windows 用 `taskkill /T /F`），記成逾時，不讀晚到的輸出；同一份最多自動重試一次，再失敗留給人決定。
- **同時跑**：每個轉接器同時幾個寫在設定（預設 2）。
- **用量**：`claude` 讀 JSON 裡的用量與時間；`codex` 讀 session 紀錄最後一筆 token 數（同 `tools/codex.ts` 的做法，在工具裡另寫一份，因為外掛的程式不 import 最上層，D-208 第 10 點）。
- **開跑前同意**：`generate`、`judge`、`rubric` 會開的對話數超過 4 個時，沒加 `--confirmed` 只印計畫與預估用量（D-212 第 2 點的精神）；操作的 Claude 拿去問使用者。

## 8. 驗收條件

程式能判斷的（雲端用自編的小 vault 與假的 CLI 測）：

1. `外掛` 來源的提示和直接呼叫外掛 `buildPrompt` 的結果一字不差（同一個表單與已有目標）。
2. `檔案` 來源的任務段選項全部選外掛預設時，和 `taskSection` 一字不差；四個選項各有一個字面預期值的例子（照候選規則 README 的三處改法與 D-229 精簡清單的範例）。
3. 規則檔照起訖標記裁切：只有開始標記、有 `<!-- 以下只在加深時送 -->`、標記前後空行三種例子。
4. 凍結兩次產生的檔一字不差；凍結後改了設定、評分表或範本，之後的指令停下並說是哪個檔。
5. `外掛` 來源用到的檔有沒 commit 的修改時，凍結停下。
6. 測試資料夾在 repo 裡時，`init` 與每個指令都停下。
7. 匿名：三段、不分段、外層有程式碼框、多步接起來四種例子切得對；匿名卡組裡掃不到組名、模型名與 `<<<`；給評審的資料夾裡沒有對照表、全貌、架構與其他區組的卡組。
8. 區組：三組各 3 份時每個區組剛好每組一份；份數不同時剩下的自己成區組；同一個種子打亂結果一樣。
9. 評審 JSON：少一列、多一列、判定不是有／部分／沒有、行號超出範圍、缺頁，各自不合格並說原因。
10. 合併表 §6-2 的九格各有一例；同一份、同一行、同一種的兩筆去重成一筆，不同行不去重。
11. 解開前沒鎖定、`裁定.md` 有空格時停下；解開後才讀得到對照表。
12. 門檻：給一組自編的逐份指標，算出的重大錯誤、多漏的列、收益、「看不出差別」都等於手算的字面值（含 1 份、2 份、3 份三種情形）。
13. 逾時：假 CLI 睡過上限時子行程被結束、工作記成逾時；重跑 `generate` 跳過完成的、只補沒完成的。
14. `摘要.md` 裡沒有評分表、卡組、教材的原文（用自編資料裡的特殊字串檢查）。

本機才驗得到的（§9 探完後在使用者電腦做，結果寫進〈結果〉）：

15. 用第一輪的設定重新凍結，四份現行組提示的字數與 SHA-256 和第一輪記錄的相同（74,473／74,496／30,812／30,812 字）；候選組四份和第一輪 `build.ts` 產生的相同。
16. 已有目標快照的數目和第一輪相同（英文 502 個、學過的單字 193 個；社會 138 個）。
17. 一課、一組、一份走完全部步驟：生成一份、兩位評審各評一個區組、解開出結果。

## 10. 不在這一份、延後的

- **API 轉接器**（D-126）：觸發點＝外掛直接呼叫 AI 的接法做好，或使用者有 API 金鑰。那時每組 3～5 份、ChatGPT 也自動。轉接器的介面這次就定好，加一個檔就接得上。
- **跨輪合併資料**（同一版規則在不同輪的結果合起來看）：每輪的 `結果/明細` 先存成工具讀得回來的格式（JSON 一份），合併等有兩輪同版規則時再做。
- **第一輪的資料匯入**：第一輪的評分是 Markdown 表，不匯入；第一輪的數字照〈結果〉留著。
- **實際使用時的品質統計**：backlog〈實際使用的審稿量照規則版本統計〉靠家長改題來量，使用者 2026-11-25 說家長基本上不會改題目，這個前提不成立。改寫成「要從孩子這一邊或自動查核來量」，留在 backlog 另外談，不屬於這個工具。

## 11. 實作順序

一個 commit 一件事，每一步先寫失敗的測試：

1. 設定讀取與驗證、測試資料夾的位置檢查、`init`、`status`。
2. 已有目標快照與提示組裝（三種來源、四個任務段選項、多步）、`freeze` 與鎖。
3. 轉接器（`claude`、`codex`、`手貼`）與工作佇列：隔離、逾時、重試、同時跑、用量；`plan`、`generate`、`paste`。
4. `check`、`blind`（切法、區組、對照表）。
5. 評分說明範本與 JSON schema、`judge`、驗證與鎖定。
6. 合併、裁定檔、`disputes`。
7. 指標、門檻、`unblind`、`明細`與`摘要`。
8. `materials`、`rubric`、`trace`、`review2` 的範本與指令。
9. README（操作步驟）、backlog 與 roadmap 同步。

合併前：`npm run check` 通過；照 quality.md 不是高風險範圍（不寫使用者的筆記、不動資料格式與排程），做 L1。§8 第 15～17 條與 §9 在使用者電腦做，排在合併之後的第一次使用之前；有程式的 PR 合併前問使用者。
