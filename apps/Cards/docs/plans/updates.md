使用者 2026-10-25 在專案討論串「規劃 Essence Cards 更新功能」開題，2026-10-26 確認範圍是三件事：

1. 新版程式怎麼送到電腦和 iPhone，出問題時怎麼退回。
2. 更新時卡組、複習紀錄、排程和設定不壞、進度不丟（資料相容）。
3. 內建製卡規則與科目預設改版時，家長改過的規則和已有的卡組怎麼辦。

不在範圍：課本改版或轉錄稿更新（[D-008](../../../../docs/decisions.md#d-008-學習紀錄與來源修改)，只提示不自動改卡）、AI 模型推薦的更新（[模型自動更新](../../../../docs/plans/ai-and-ecosystem.md#發音檢查與語音模型)）、學習地圖的調整（[D-136](../../../../docs/decisions.md#d-136-學習地圖課本是起點加深可以超出課本)）。Obsidian 自己的改版見 [D-138](../../../../docs/decisions.md#d-138-obsidian-出新的次版本時做一次相容性檢查)。

**北極星**：更新的價值是把更好的規則、修好的錯送到學生手上；最大的風險是更新本身打斷複習、讓排程亂掉或弄丟進度。**改進送得到，複習不中斷，進度不會丟。**

## 上架 Obsidian 官方目錄（D-220）

觸發點：第一個外部家庭要裝時。在那之前不上架；官方審查的程式檢查先放進 Cards 的 `npm run check`（[任務說明](../tasks/obsidian-review-check.md)）。到時候要做的事，開工前寫成任務說明，其中 D-149 怎麼套到別人家那一項先和 Codex 討論：

- **公開 repo 與發布**：照 [D-208](../../../../docs/decisions.md#d-208-三個外掛在同一個-repo-開發每個外掛有自己的資料夾) 第 10 點建 Cards 的公開 repo，匯出、Release 的順序與防呆照[三個外掛的討論稿〈對外發布〉](<../../../../docs/Claude Codex Discussion/2026-11-09-one-repo-three-plugins.md#對外發布>)與同一份 Codex 第一輪第 5 點。目錄讀預設分支根目錄的 `manifest.json`，Release 的 tag 等於版號，附 `main.js`、`manifest.json`、`styles.css`；根目錄要有 `README.md` 與 `LICENSE`。
- **授權**：選開源授權（D-126 第 5 點「發布前再選」）。
- **介紹**：中文的 README 與目錄上的介紹；寫明會用到網路（AI 製卡）與 vault 外的備份資料夾（照當時官方的規定寫）。
- **審查會算錯誤的項目**：改寫基準裡讀格式的正規表示式（`regex-lookbehind`，改寫要有測試與發布前比較）；開發版專用的 `dev-*.ts` 不放進公開 repo，或改到過得了檢查；檢查的 ESLint 外掛升到最新版再跑一次。
- **警告**：約 290 項只影響安全分數，多數是機械替換，上架前清掉。
- **D-149 怎麼套到別人家**：發布前比較改用測試 vault（上面第 6 點）；考前提醒移到設定頁；兩段發布在看不到別人家裝置時怎麼判斷可以開始寫新寫法。
- **說明書**：安裝與更新章只寫官方目錄（[D-048](../../../../docs/decisions.md#d-048-使用說明書) 2026-10-26 的補充），照實際走過一次的步驟寫。
- **iPhone 實測**：只在電腦裝、iCloud 帶到 iPhone 時，iPhone 要不要另外打開社群外掛；iOS 的「保持下載」照 [backlog 技術債](../backlog.md#技術債)那一列查清楚。
