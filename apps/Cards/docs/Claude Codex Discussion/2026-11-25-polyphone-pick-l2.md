### P1

1. **R1｜「加進已有的學習目標」能把相同題幹的矛盾答案寫回筆記**  
   **規格，已重現。** §5 要求同一題幹經 `pickKey` 正規化後配到不同讀音時擋下。已有 `他長（＿＿）得比哥哥高。 :: ㄓㄤˇ` 時，AI 回傳補題 `他**長**（＿＿）得比哥哥高。 :: ㄔㄤˊ`，`inspectReply` 回傳零錯誤，`planExisting` 回傳可寫入的全文。對全文再跑 `check`，兩題都報 `choice-ambiguous`，而且 `choiceCardOf` 把這兩句排在同一張卡上。若兩個矛盾答案都是同一批新增題，原文完全相同也能寫入。另測括號外的 `ㄓㄤ`，貼回時也是零錯誤，直到按加入才被 `verify` 留在框內。  
   **原因與影響。** 貼回時補題框走 `analyzeTarget`。寫入時的防呆只拿待新增題與目的地原有題目做較窄的文字比對，寫後核對只確認題型、選項和解析問題。正式寫入入口使用這個計畫，因此錯誤答案可以留在既有題池，之後影響同一個 ID 的評分。真實路徑可發生於跨課製卡或加深，尤其是 AI 重用舊句、換上粗體，或同批產生兩個答案時。機率低，但會持續影響後續複習。建議在合併前讓加題入口用 §5 的同一套判準核對合併後的題池。 [任務 §5](../tasks/polyphone-pick.md)、[check.ts](../../src/core/ai/check.ts#L483)、[existing.ts](../../src/core/ai/existing.ts#L175)、[state/index.ts](../../src/state/index.ts#L1065)

2. **R2｜底線數不同的同一句能通過草稿檢查，答對讀音仍被降評**  
   **規格漏洞，已重現。** §1 接受一個以上的底線，§5 用 `pickKey` 比對題幹。因此 `這條路很長（＿）。 :: ㄓㄤˇ` 和 `這條路很長（＿＿）。 :: ㄔㄤˊ` 通過錯誤檢查，只有句數與錨點的非阻擋訊息。用 `postProcess` 跑 DOM 後處理，兩句都成為 `這條路很長（[選項]）。`。兩格都選正確讀音 `ㄔㄤˊ`，流程要求其中一格再選成 `ㄓㄤˇ`，最後寫出最上層 `r: "near"`、`pick: "ㄔㄤˊ"`、`retry: "right"` 的紀錄。  
   **影響與機率。** 同一個可見題幹應有一個可判讀的答案。這裡會把答對記成「差一點」，排程用的就是這筆評分。AI 或家長改過挖空長度、重用句子且配到不同答案時可以發生，機率低。建議合併前把可接受的底線長度統一後再比對題幹，並涵蓋整份草稿和 R1 的合併後題池。 [任務 §1-2](../tasks/polyphone-pick.md)、[check.ts](../../src/core/ai/check.ts#L176)、[rendered.ts](../../src/ui/rendered.ts#L166)

3. **R3｜隱藏文字裡的 `長（＿＿）` 會讓別處的可見空格被當成讀音格**  
   **規格，解析、草稿檢查與 DOM 後處理已重現，Obsidian 實機待驗證。** 在一組合法多音字句中加 `他＿得比哥哥高。%% 長（＿＿） %% :: ㄓㄤˇ`，預期這一題觸發 `pick-mixed`，整個目標照翻面，AI 草稿報 `choice-invalid`。實際 `parseDeck` 仍給 `choice`，草稿零錯誤，這題進入組卡。把註解去除後的文字交給產品的 `postProcess`，空格插在 `他[選項]得比哥哥高。`。  
   **原因與影響。** `countBlanks` 數的是遮掉註解後的空格，位置 regex 卻只遮行內程式碼和公式，兩次檢查能命中不同的空格。手寫或編輯 Obsidian 筆記時可發生，需要註解裡保留另一個讀音格，機率低。這會讓不合語法的題目進入程式計分。建議合併前讓數格與定位檢查同一個可見空格。 [syntax §2-3](../syntax.md#比較卡點選填空)、[question-types.ts 遮罩](../../src/core/deck/question-types.ts#L43)、[question-types.ts 定位](../../src/core/deck/question-types.ts#L157)

### P2

4. **R4｜手寫題池缺一個讀音的句子，仍出成點選填空**  
   **規格漏洞，已重現。** 名稱為 `長（ㄓㄤˇ、ㄔㄤˊ） 讀音`，底下只有兩句 `ㄓㄤˇ` 的題目。`parseDeck` 回傳 `choice` 且沒有問題，`choiceCardOf` 出兩格，兩格正解都是 `ㄓㄤˇ`，字鍵仍列兩個讀音。§1 的認法允許這份筆記，§3 卻要求每個讀音至少出一句。AI 草稿會報 `choice-unused`，手寫筆記或手動刪掉某讀音最後一題時仍會走到，機率低。孩子可以一直選同一個鍵拿到全對。建議補定缺句時的行為，並保住該目標的題目，例如提示並照翻面出。 [任務 §3](../tasks/polyphone-pick.md)、[question-types.ts](../../src/core/deck/question-types.ts#L186)、[compose.ts](../../src/core/study/compose.ts#L133)

5. **R5｜題目集合相同，出題歷史一更新就可能換列序**  
   **規格，已重現。** 用三句固定題池及三筆歷史紀錄，讓「小孩長高了」先前出過兩次、「這條路很長」一次、「他是班長」零次。第一次組卡依序是「這條路很長／小孩長高了／他是班長」。再讀入一筆含 `also` 的三格紀錄後，三句指紋與字鍵完全相同，列序變為「小孩長高了／這條路很長／他是班長」。種子依指紋集合固定，但打亂前的輸入仍照 `rotation` 排序。  
   **影響與機率。** 舊版翻面歷史、手動增修題池都能造成各句出題次數不同。機率低，需要前後挑中同一批句子且輪替順序改變。評分規則仍取最差格，同分時代表該行的 `v` 可能跟著列序變動。建議選完句後先固定打亂前的順序，補一個「同一組指紋、不同歷史」的驗收例。 [L2 不可破壞的性質](../tasks/polyphone-pick-l2.md#行為與風險)、[compose.ts](../../src/core/study/compose.ts#L54)、[choiceAssembled](../../src/core/study/compose.ts#L150)

6. **R6｜有合法括號組時，結尾獨立的「相似詞」仍可能漏報**  
   **規格，已重現。** 用 `反映（反應、反映） 字義 相似詞` 加普通問答 `反映是什麼意思？ :: 把意見傳達出去`。依 §2-5，末段是獨立的 `相似詞`，讀不成比較卡應提示且擋草稿。實際 `parseDeck` 零問題、`check` 零錯誤。用完全相同的題目移除名稱中的 `字義`，兩個入口都報 `pick-not-recognized`。原因是有組時拿完整標題 `字義 相似詞` 做判斷。真實路徑可發生於家長或 AI 在結尾前插入分類字樣，機率低。結果是草稿可以把原本要做的比較卡存成一般問答。建議用同一條末段規則判斷提示，並加上這個有組、有額外標題文字的例子。 [任務 §2-5](../tasks/polyphone-pick.md)、[readPick](../../src/core/deck/question-types.ts#L125)

7. **R7｜國語 v0.11 給未勾點選填空的 AI 兩套互斥要求**  
   **規格衝突，建置內容已核對，生成結果待驗證。** 〈讀音〉要求未勾時用 `長 讀音`，全池最多三題、每個讀音至少一句。〈輸出前自我檢查〉仍一律要求名稱括號列讀音，每個讀音至少兩句，只有兩個讀音時至少三句。兩段都在實際嵌入的規則內。家長取消勾選時一定會送出這組衝突指令。AI 採哪一段的機率待驗證，若採自查段，便可能產出家長未選的點選題型，或超過翻面題數上限。建議先把自查條件依勾選狀態寫清楚。 [國語規則〈讀音〉](../card-rules/elementary-chinese.md#讀音)、[〈輸出前自我檢查〉](../card-rules/elementary-chinese.md)
