# 直接呼叫 AI 之後的多段審查：模糊的判斷交給窄的 AI 檢查

狀態：討論中｜下一步：使用者決定要不要用孩子的複習紀錄驗證（[卡片目標與規劃](2026-11-26-card-goals-and-plan.md) §6 第 1 步）｜等誰：使用者

## 1. 問題

使用者 2026-11-25：「我目前推論要解決上述的問題就是利用API多段的機制，把審核權交回給AI審查，因為太多錯誤存在模糊判斷空間，很難用程式完美的擋掉，你的看法呢? 如果你也同意，那方向可能要調整比較大」。

前提：家長不會改題目（使用者 2026-11-25），草稿幾乎直接進孩子的複習；畫面照樣呈現，想改的家長可以改，但那是彈性，不是防線。

## 2. 證據

**整份重審沒有用**（[比較測試〈結果〉](../tasks/rule-restructure-test.md#結果)「第二道查核」）：另開對話照同一套規則整份再看一次，必備漏掉的 3 項抓到 0 項，「部分」只抓到一成多；改壞 2 處，其中一處把題目移到判準不合的已有目標；每份 13～22 萬 token。多抓的有一半是真的問題（英文找到 9 處兩張卡互相洩漏，評審只記到 1 處）。

**窄的檢查有用一部分**（2026-11-25 在使用者電腦離線測，只用第一輪已評分的原稿；設計照[三層架構檢討](2026-11-25-three-layer-review.md) §5 測試 2，開跑前凍結；逐份結果只在使用者電腦）：

| 檢查 | 怎麼做 | 結果 | 門檻 |
|---|---|---|---|
| 盲解抓多解 | 抽出英文打字題的題幹（拿掉答案、詳解、錨點），另開對話寫最自然的兩個答案，不在答案欄的標「可能多解」 | 791 題標 174 題。兩位評審都記的 8 題抓到 5 題（63%）；只一位記的 186 題抓到 92 題（49%）；沒人記的旗標抽 20 筆，18 筆是真的多解（同義片語、冠詞或代名詞不同、縮寫） | 過（一半以上；沒人記的不超過抓到的一倍） |
| 加題核對 | 給那個目標的全部題目加新題，只問「同一個判準、同一個意思嗎」，只能降成候選 | 227 筆加題：已知加錯 5 筆抓到 2 筆，漏的 3 筆都是文法目標換了時態條件、答案形式相同；對的被降級 4 筆（1.8%），逐筆看都說得出理由 | 沒過（要全部抓到） |
| 程式意思核對（[外掛任務](../tasks/rule-restructure-plugin.md) §4-2） | 英文單字加題，新答案的中文和舊答案沒有共同的字就標 | 只查得到單字目標 163 筆：已知加錯抓到 1 筆（另 4 筆是文法目標），誤標 1 筆 | 對照 |

用量：盲解 12 次 84.6 萬 token、加題核對 15 次 106 萬 token，每次 11～34 秒；大部分是測試時 subagent 每次固定帶的約 6.5 萬字說明，改用 API 只送必要的會少很多，實際多少要接上 API 才量得到。

## 3. 提案

**分工**：

| 誰 | 管什麼 | 例子 |
|---|---|---|
| 規則 | 上游：核心邏輯、學習地圖、出口收窄、怎樣算考到 | 漏項大多在規則給的出口被送走（三層架構檢討 §1.2），後面的審查補不回來 |
| 程式 | 機械的：格式、ID、同名、數量、完全相同 | 快、準、不花 token |
| 窄的 AI 檢查 | 模糊的：一次只判一件事，另一個對話，看不到不需要的東西 | 盲解抓多解、單字加題的意思 |
| 家長 | 彈性 | 畫面照樣並排，想改可以改 |

**三個條件**：

1. 一次只判一件事，不整份重審（整份重審改壞 2 處、漏項 0/3）。
2. 只能降級或標記：加題降成候選、題目標成「要改」；不准自己另立目標或改寫題目。例外與處理見下一點。
3. 不取代規則：規則仍是品質的主要來源，檢查只補規則做不到的那一類（出題的 AI 知道答案，自己想不到別的答法）。

**盲解找到的另一個說法怎麼處理**（要 Codex 找洞）：抽查 20 筆有 2 筆不是真的對，直接收進答案欄會讓錯的答案也算對。候選做法：

- 甲：另一個獨立的檢查也寫出同一個說法才收進答案欄；只有一個寫出的，退回出題的 AI 改題（鎖住或換句子），改完再盲解一次。
- 乙：一律退回出題的 AI，由它決定收進答案或改題，再盲解一次。
- 丙：標記給家長。不採用：家長不會改。

💡 傾向甲。收進答案欄要等使用者選完「字數不同的兩個說法」那張決定卡（改不改 D-122）。

**順序**：

1. 手貼期間：規則照下一版修；程式的機械檢查與意思核對先用著；不加手貼的步驟。
2. 外掛直接呼叫 AI（分支 `claude/project-thread-q0jv5f` 的 `docs/tasks/ai-client.md`，審查中）接上 Cards 的優先順序往前拉：窄檢查、兩段送法、分科分段送都卡在它。
3. 接上後第一個放進流程的是盲解：英文審稿量七到八成是多解（[英文候選刪減對照](2026-11-25-english-candidate-diff.md) §3）。
4. 單字的加題改用 AI 核對，程式核對留著當沒有 API 時的備援。
5. 文法目標的加題核對另外設計再測（例如先讓檢查者寫出那個目標的判準，再拿新題比）。
6. 洩漏檢查（另一個對話只看題幹與同池其他卡，答不答得出）：整份重審找到 9 處、評審只記 1 處，值得做成窄檢查，要先測。

**和不做比**：不做就只能靠規則與程式。規則擋不了出題的 AI 自己想不到的答法（第一輪英文的多解，現行與候選都有），程式判斷不了意思；家長又不會改。孩子答對被判錯，排程跟著錯，正是北極星最在意的時間與正確。

**代價**：每課多幾次 AI 呼叫的費用與時間（接上 API 後實測再定上限）；流程多幾段，要處理某一段失敗或逾時（照 `code-quality` 寫規格時的逾時結局）；檢查本身會錯（盲解抽查 2/20、加題核對漏文法 3/5），所以只給降級與標記的權限，最壞是少收一題或少加一題。

## 4. 不用改的

三層架構（核心講原則、模組各自負責，比較容易配「一段一個窄任務」）；程式的機械檢查；手貼流程（沒有 API 時照舊能出正確的卡）；[D-236](../../../../docs/decisions.md#d-236-製卡規則比較測試的評估對齊北極星錯誤分輕重量孩子的時間評學習地圖) 的評估要量「整條流程最後交到孩子手上的卡」，不只第一次生成。

## 5. 還要確認的

- API 的費用（家長設定金鑰的摩擦不算代價：使用者 2026-11-26「既然決定要做API 在這一個點上家長的摩擦力就不考慮了 這沒有辦法改變 我們在其他地方努力讓家長使用體驗好一點就好」）。
- 每一種窄檢查用哪個模型、什麼推理等級最划算。
- 盲解的旗標在比較點選、文法翻面等非打字題要不要也做（這次不在範圍）。

## 6. 請 Codex 找漏洞

只讀本文、[三層架構檢討](2026-11-25-three-layer-review.md) §5、§8、§9、[英文候選刪減對照](2026-11-25-english-candidate-diff.md) §3、§4、比較測試〈結果〉的「第二道查核」、D-236、D-229。只回報，寫在 `2026-11-25-ai-review-layer-codex.md`，標題下第一行寫狀態。

1. 分工表有沒有該由程式做卻交給 AI、或反過來的。
2. 「只能降級或標記」夠不夠防止檢查改壞；甲、乙、丙之外有沒有更好的處理。
3. 離線測試的設計與結果有沒有讓結論站不住的地方（樣本、評審漏記、subagent 和 API 的差別）。
4. 順序：手貼期間有沒有該先做、卻排到 API 之後的。
5. 和不做比，代價有沒有漏算（費用、時間、失敗處理、手機）。

## 7. Claude 的回應

[Codex 查核](2026-11-25-ai-review-layer-codex.md)（2026-11-25，high）的 12 項全部採納，大方向不變。Codex 的總結是：盲解值得進下一輪，但還不足以自動收答案、直接放行，或用 AI 換掉單字加題的程式核對；修正後的提案照這三點收緊。

更正：Claude 2026-11-25 對使用者說「單字的加題，AI 比程式準」，數字撐不起來。單字目標的已知加錯只有 1 筆，程式和 AI 都抓到；AI 多抓到的 1 筆是文法目標。

| # | Codex 的發現 | 回應 |
|---|---|---|
| 1 | 盲解與比對要分工 | 採納。盲解只看孩子作答前看得到的（題幹、看得到的錨點、空格）；它寫出的說法交程式照複習時的比對規則判斷，複習時本來就算對的不算多解，算錯的才叫「替代說法」。空格怎麼畫照「字數不同的兩個說法」那張決定卡 |
| 2 | 同名照 D-229、加題核對要拿到完整題池 | 採納。同名的新目標仍由家長選併入或分開（[D-229](../../../../docs/decisions.md#d-229-已有目標改用精簡清單送貼回時擋同名與重複加題) 第 2 點），AI 的結果不代替；加題核對拿到原目標的全部題目才跑，沒有找到相關目標的標「沒有核對」，不當作通過 |
| 3 | 旗標與降級要有放行條件 | 採納。每題三種狀態：通過、有疑義、未完成。有疑義的不進複習（草稿看得到，家長想改可以改回）；用最後放行的題重算必備覆蓋，某個必備沒題了就限次補題，補不出來標成待補 |
| 4 | 提出替代說法和驗證分開 | 採納，取代甲、乙。每個替代說法交另一個窄檢查判兩件事：說法對不對、還考不考得到原判準。對又考得到 → 收進答案欄（等決定卡；決定前先改題）；對但繞開判準 → 退回出題的 AI 改題（鎖住或換句子，最多兩次），改完拿原來的替代說法再驗；不對 → 丟掉 |
| 5 | 門檻的公式、分母、抽樣 | 採納。開跑前凍結在執行說明的過關線：盲解「兩位都記的抓到一半以上，誤報不超過抓到的一倍」；加題核對「已知加錯全部抓到，對的被降級不超過一成」，後者沒寫進三層架構檢討 §5，是 Claude 漏寫。盲解兩種讀法都過：沒人記的 77 題全算誤報，77 小於抓到的 97；照抽查 2/20 推估約 8 題。下一輪照 Codex 的抽法：有旗標和沒旗標的都抽，評審不知道旗標從哪來，照孩子作答的畫面判，分課、分題型報 |
| 6 | 單字加題不能換掉程式 | 採納。§3〈順序〉第 4 點改成：單字照舊用程式核對，AI 核對在新稿上並排跑，量最後加錯幾筆、對的被擋幾筆再決定；文法另設計（第 5 點不變） |
| 7 | 偵測和整條流程分開驗收 | 採納，就是 [D-236](../../../../docs/decisions.md#d-236-製卡規則比較測試的評估對齊北極星錯誤分輕重量孩子的時間評學習地圖) 要量「最後交到孩子手上的卡」；比較測試工具多一組「有窄檢查／沒有」，用同一份新稿 |
| 8 | 手貼期間先做的要具體 | 採納。規則下一版照[英文候選刪減對照](2026-11-25-english-candidate-diff.md)〈5. 修正清單〉，前 3 項（另一個正確說法不能只寫詳解、加題拿不準留候選、拿回反例表防退步）加上「科目模組優先」；會話用語與句型框改題型是教學選擇，等使用者；D-229 貼回的同名與完全重複檢查已在[外掛任務](../tasks/rule-restructure-plugin.md) §4 |
| 9 | 費用與時間以整課算 | 採納。接上 API 後和「同一版規則與程式、沒有窄檢查」比：每課總費用、送出到可以複習的時間（中位數與最慢的 5%）、逾時比例、每課少掉幾個孩子會碰到的錯 |
| 10 | 失敗、重試、手機中斷 | 採納，寫進接上 API 的任務說明（逾時結局照 `code-quality`）：做完的進度留著、畫面標出哪些題還沒查、重試有上限、同一份結果只套用一次、草稿或已有目標改過就重查 |
| 11 | 洩漏怎麼證明 | 採納。同一題比「有其他卡／沒有」兩種輸入，要指出是哪張卡的哪一段；那 9 處只當開發例子，驗收用新課 |
| 12 | 記錄查核版本與完成狀態 | 採納方向。記在哪裡（草稿快照或卡組）和 D-236 第 6 點的規則版本一起談，不改複習紀錄的格式 |

**和使用者的「較高層級的專門審題」是同一層**：[Cards backlog〈訂閱製卡接法驗證（D-126）〉](../backlog.md#訂閱製卡接法驗證d-126)已記使用者 2026-11-25 在題型模組串說的「如果以後接API，應該要有一個較高層級的專門審題，確認出題的品質好壞」，配對與單選的「另一個 AI 不看答案重做一遍」也放那裡。第一輪的證據是整份重審沒有用，所以「較高層級」建議落在每一種窄檢查用比出題強的模型或推理等級，而不是一個對話整份審。配對與單選的盲解，就是第 1 項套到選擇題。使用者同意的話，這份討論稿當「接上 API 後的審查」的主文，backlog 的這一條和[〈AI 規劃〉](../backlog.md#ai-規劃2026-10-11-起的專題討論)裡盲解、加題核對（D1、D2）那一條連過來。

## 8. 修正後的提案

接上直接呼叫 AI 之後，一課的流程：

1. 生成（照規則，三層架構）。
2. 程式查機械的：格式、ID、同名、完全重複、數量；格式錯自動退回重生一次（三層架構檢討 C2）。同名照 D-229 由家長選。
3. 窄的 AI 檢查，每種另開一次呼叫、只看需要的東西、各自先過測試才放進流程：
   - 盲解（第一個做）→ 程式比對 → 替代說法逐項驗證 → 收進答案、退回改題或丟掉。
   - 加題核對：單字程式照舊、AI 並排量；文法另設計再測。拿不準就留候選。
   - 洩漏檢查：先照第 11 項證明有用。
4. 每題標通過、有疑義、未完成；有疑義的不進複習，重算必備覆蓋，缺了就限次補題。例外：某個必備只剩這一題、又補不出來時，這題照樣進複習並標記，因為拿掉是確定漏考、留著只是可能判錯（[Fable 查核](2026-11-26-card-goals-fable-review.md) 3-5）。
5. 未完成的（逾時、斷網、手機切走）畫面看得出來，可以續查；沒有 API 時照手貼流程，畫面寫明沒有查核。

權限：檢查只能降級、標記或退回出題的 AI 改題；不能自己改題、自己另立目標。規則仍是品質的主要來源。

模型：不能假設每個家長都有比出題強的模型（使用者 2026-11-26）。每種窄檢查都要在家長預設的模型（[D-085](../../../../docs/decisions.md#d-085-首選-openai-gpt-56-terra)）上量過；強模型審出的毛病，開發時寫成通用規則，讓出題時就不犯（[卡片目標與規劃](2026-11-26-card-goals-and-plan.md) §5、§6 第 5 步）。

費用：窄檢查只送需要的（題幹、同一目標的題目），不附教材 PDF；AI 模組不快取，附 PDF 的呼叫每次都重付教材的輸入費。AI 模組每次呼叫各自有逾時、重試上限與取消，也回報費用與用量；沒有並行上限，同時送幾個由 Cards 決定（「讓外掛直接呼叫 AI」那一串 2026-11-25 確認，依據分支 `claude/project-thread-q0jv5f` 的 `packages/ai-client/src/types.ts`、`client.ts`）。

手貼期間：規則下一版照第 8 項；程式檢查與單字意思核對先用；不加家長的步驟。

## 9. 請使用者決定

**問題**：要不要把「接上 API 後，模糊的判斷交給窄的 AI 檢查」（§8）定為方向，寫成 D-ID？

**兩邊的考量**：Claude 與 Codex 一致：整份重審停用；盲解值得做，但要先驗證替代說法、照孩子看到的畫面比對；單字加題先不換掉程式；接上 API 後要重測命中率與費用。Codex 比較謹慎的地方（不自動收答案、不直接放行、每題要有狀態）已全部寫進 §8。

**選項**：

- 甲：定為方向（寫成 D-ID）。Cards 接上直接呼叫 AI 排在 AI 模組合併後的下一個；每種窄檢查照 §8 先測再放進流程，第一個是盲解。
- 乙：先不定，接上 API 後用比較測試工具實測盲解，有數字再決定。
- 丙：不做，只靠規則與程式。
