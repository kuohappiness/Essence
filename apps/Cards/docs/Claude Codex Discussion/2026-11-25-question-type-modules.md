# 題型模組：每個學習目標掛上一種題型

狀態：討論中｜下一步：使用者用決定卡選這次的範圍；選定後交 Fable 5.2 xhigh 審這份規劃｜等誰：使用者

來自：使用者 2026-11-24～25 在專案討論串「製卡-國小國語」：「我們是否有把題型模組獨立抽出來管理，以後每一顆要用哪一種題型，例如還有排序等等，就可以直接掛上這個題型模組就好」「我要做題庫模組……規劃好也是先給 fable 5.2 xhigh 看過再動手」；[題型專區〈待決〉](../question-types.md#待決)

審查：使用者指定 Fable 5.2 xhigh 審這份規劃，不是 Codex。提案已成形、要找洞，照一輪一輪查（essence-discuss 第 7 點）。

## 0. 這份要決定什麼

使用者要三件事：

1. 每個學習目標可以掛上一種題型（點選、排序、選擇……）。
2. 新題型做成模組，接上就能用，不用每次改一大片。
3. 以後的題庫系統（[D-090](../../../../docs/decisions.md#d-090-題庫併入-cards變式題以題型排程)）也用得到（使用者選多音字點選時說「以後會有題庫系統，用得到」，[D-230](../../../../docs/decisions.md#d-230-國語字義卡和詞義卡錯開混淆點第一次就比多音字改點選填空) 第 4 點）。

「題庫模組」在專案裡可能指兩件事：題型（作答方式，[D-181](../../../../docs/decisions.md#d-181-題型是可以接上的模組開題型專區)）與題庫系統（D-090，閃卡以外的第二種練習，排在第二階段）。這份先照 Claude 的建議寫「題型模組」，題庫系統只寫之後怎麼接（§4）；範圍由使用者用決定卡選（2026-11-25 送出）。

## 1. 現況

### 1-1 題型與卡型

題型專區的「題型」是作答方式：翻面自評、打字比對、點選填空。孩子看到的每一種卡（這份叫**卡型**）由名稱的結尾或題目的形狀認出來，再交給其中一個題型：

| 卡型 | 怎麼認 | 題型 | 只在 |
|---|---|---|---|
| 問答、填空 | 其他全部 | 翻面自評 | |
| 英翻中 | 結尾 `英翻中` | 翻面自評 | |
| 接句 | 結尾 `接句`，一題一格的填空 | 翻面自評 | |
| 中翻英 | 結尾 `中翻英` | 打字比對 | |
| 文法、變化 | 結尾 `文法`、`過去式` 等 | 打字比對 | 英文卡組 |
| 比較卡 | 名稱的括號讀得出組，結尾只當標題（D-182 第 4 點） | 點選填空 | |
| 全詩順序 | 結尾 `排序`，一題兩格以上的填空 | 點選填空 | 英文要寫 `全詩` |
| 句子排序 | 結尾 `排序`、沒有 `全詩` | 點選填空 | 英文卡組 |
| 多音字、相似詞（D-230，還沒做） | 格式另一串在定 | 點選填空 | 國語 |

所以「掛上」已經有一半：卡型靠名稱的結尾掛（比較卡靠括號），家長與 AI 寫結尾就選了題型。缺的是程式這一半。

### 1-2 每多一種卡型要改哪裡

D-181 抽出了四個接點（認、組卡、作答、畫面，[題型專區〈程式現況〉](../question-types.md#程式現況)），作答與畫面已經是一張表。但卡型的知識還散在接點外面：每一種卡型在 `Target` 上有自己的欄位，用到它的檔案數（2026-11-25 的 `main`）：

| `Target` 的欄位 | 卡型 | 用到的檔 |
|---|---|---|
| `group` | 比較卡 | 14 |
| `order` | 全詩順序 | 10 |
| `typing` | 文法、變化 | 7 |
| `sentence` | 句子排序 | 4 |
| `couplet` | 接句 | 3 |

比較卡的 14 個檔除了四個接點，還有今天的份（`plan.ts`、`session.ts`）、練習（`practice.ts`）、需要版本（`need.ts`、`draft.ts`、`move.ts`）、AI 製卡的規則與草稿檢查（`prompt.ts`、`check.ts`）、預覽（`preview.ts`）。

已經碰到的問題：

- **認法互相排除**：每個認法要先排除別的卡型（`readTyping` 先看讀不讀得出組，`readSentence` 要排除組與全詩，`readCouplet` 要排除全詩順序），誰先誰後寫在 `parse.ts` 的呼叫順序裡。`排序` 已經有三種意思（全詩、英文句子、英文詩）。每加一種卡型，要逐一確認和舊的不會互搶。
- **去格式各處自己寫**：[Cards backlog〈技術債〉](../backlog.md#技術債)「讀手寫文字的去格式各處自己寫」，觸發點就是「下一次改題型或英文讀手寫文字的地方」；英文排序 L2 的後兩輪多是這一類。
- **AI 製卡**：每種卡型的規則文字與草稿檢查分寫在 `prompt.ts`、`check.ts` 與 card-rules 裡。

接下來要加的卡型：多音字、相似詞（D-230，排 0.7.0），題庫的選擇題（D-090），找錯題（v1 之後）。

## 2. 提案：一種卡型一個模組

### 2-1 兩層：題型與卡型

- **題型**（D-181 的定義不變）：孩子怎麼作答、誰判對錯、怎麼對到四級。只有幾種，各一個模組，放作答流程與畫面。現在三種；之後題庫的選擇題可能是第四種。
- **卡型**：孩子看到的那一種卡。一個卡型一個模組，放這一種卡從筆記到出題要的全部：怎麼認、需要版本、今天的份怎麼併成一張、組成一張卡、AI 製卡的規則文字與草稿檢查、規格的連結。每個卡型說它用哪一個題型。
- **卡型總表**：全部卡型照認的先後排成一張表，是「哪個結尾掛哪個卡型」的唯一來源；程式從上往下問，第一個認得的算。互搶只要看這張表的順序。題型專區的總表照這張表寫。

### 2-2 掛法不變：名稱的結尾

卡組的格式不改：卡型照舊靠名稱的結尾掛，比較卡照舊靠括號（D-182 第 4 點：結尾打錯也不會壞）。家長與 AI 寫的東西一樣，舊卡組不用動，舊版外掛讀得到的照舊讀得到（P1：寫進筆記的格式不能改壞）。

不另加一行 `題型: …` 的屬性：多一種寫法要家長與 AI 學，還要和結尾說好誰優先，舊版外掛也讀不懂（§6）。

換卡型不換學習目標 ID：例如讀音卡改成多音字點選，名稱照 D-126 改字、ID 不變，紀錄照樣算進同一個目標。所有題型都落在四級（題型專區〈共同規則〉），排程器不用知道換過。要注意的是從「想得出來」換成「認得出來」，排程可能高估一段時間（題型專區〈點選填空〉已寫的風險）。

### 2-3 程式的形狀（草稿，任務說明再定）

```ts
/** 一種卡型（tasks 再定名稱與欄位）。 */
interface CardKind<Data> {
  id: string;                                   // 'pick-group'、'poem-order'、'sentence-order'、'couplet'、'typing'、'zh-en'、'flip'…
  questionType: QuestionType;                   // 用哪個題型作答
  read(target: Target, deck: DeckContext): Read<Data>;   // 認得、不是我、或寫錯（附提示）
  needs?: string;                               // 卡組要帶的需要版本（D-191）
  bundle?(due: readonly Candidate[]): …;        // 今天的份：哪幾個目標併成一張（比較卡同組併）
  card(fields, data, history): Card;            // 組成一張卡
  ai?: { rules(form): string[]; check(deck): Issue[] };  // AI 製卡的規則文字與草稿檢查
}
const CARD_KINDS = [pickGroup, poemOrder, sentenceOrder, couplet, typing, zhEn, enZh, flip] as const;  // 認的先後
```

- `Target` 上的 `group`、`order`、`sentence`、`typing`、`couplet` 併成一欄 `kind: { id, data }`（照卡型分的聯集），TypeScript 照 id 收窄。散在 14 個檔的 `target.group` 改問卡型模組。
- 題型的表（`FLOWS`、`PREVIEWS`、`SCREENS`）照舊，`QuestionType` 多一個值時 TypeScript 指出缺哪一列（D-181 第 5 點的機械檢查留著）。卡型總表也加同樣的檢查：每個卡型要有範例（`tests/question-types.test.ts` 那張表），範例從筆記的文字跑到卡型。
- 檔案放 `src/question-types/`：題型一個資料夾（`flip/`、`typed/`、`pick/`），卡型放在它用的題型底下（`pick/group.ts`、`pick/poem-order.ts`）。

### 2-4 點選的選項從哪裡來

點選填空的各卡型差在選項從哪裡來，作答、判對錯、對到四級都一樣：

| 選項從哪裡來 | 卡型 | 一格對 |
|---|---|---|
| 組裡的其他目標 | 比較卡（相似字、比較、相似詞） | 一格一個目標 |
| 打散的每一格 | 全詩順序、句子排序 | 好幾格一個目標，取最差的一格 |
| 這個目標自己列的 | 多音字（讀音） | 好幾格一個目標 |
| 這一題自己列的 | 題庫的選擇題（之後） | 一題一格 |

多音字和之後的選擇題是同一類：選項不是別的目標。點選題型的模組照「選項從哪裡來」收參數，第四種來源接上時不用改作答流程。多音字的格式由「做多音字點選題」串照 D-230 第 4 點定，這份只提醒兩邊對齊（§5）。

### 2-5 AI 製卡

- 每個卡型的規則文字與草稿檢查放在它的模組裡，提示照家長的勾選與科目從模組組出來；card-rules 的科目預設只寫「這類內容用哪個卡型」（D-181 第 2 點），不重抄格式。
- 這和「AI 提示詞架構」串的核心＋任務模組＋科目模組（[D-228](../../../../docs/decisions.md#d-228-製卡規則重整成核心任務模組科目模組先用比較測試判斷)）要對齊：卡型的格式說明應該是其中一塊，誰先做、放哪一層等那邊的比較測試結果；這份第 1 段先不動提示的文字。
- 家長的勾選照舊只有點選填空（D-182、D-210），這次不加新的勾選（[D-179](../../../../docs/decisions.md#d-179-介面的每一項都要有必要性非必要不出現)）。

## 3. 和「不做」比較（D-153、D-177）

| | 不做（照現在的接點，再加多音字） | 只集中認法 | 一種卡型一個模組（建議） |
|---|---|---|---|
| 做什麼 | 多音字照比較卡的路，`Target` 再加一欄，約 10 個檔各加一段 | 認的先後排成一張表，其他不動 | §2 全部 |
| 加一種卡型 | 約 10 個檔，靠人記得每一處 | 互搶看得清楚，其他照舊約 10 個檔 | 一個模組加總表一列；漏了 TypeScript 與範例表擋 |
| 題庫接上 | 題庫筆記的選擇題再發明一套 | 同左 | 題庫筆記用同一張卡型總表、同一套題型 |
| 孩子感覺得到 | 沒有差別 | 沒有差別 | 沒有差別（第 1 段只搬不改） |
| 代價 | 每加一種多一欄、互搶越來越難查 | 小 | 約 20 個檔要搬；搬壞的風險；和同時在改 Cards 程式的串衝突 |

**優勢**：接下來至少有多音字、相似詞、題庫的選擇題要加，找錯題在 v1 之後。照現在的路，每一種都要找齊約 10 處。[英文打字與排序的 L2](2026-11-15-english-typed-order-review.md) 走了三輪，好幾項正是一條路漏了或兩處認法不同：R2 候選卡片繞過英文草稿的退件規則、R4 朗讀與第 2 步對同一個文法標籤的認法不同、R6 起排序詞塊的去格式和別處不一樣。

**代價與解法**：

- **搬壞**：第一段只搬不改，所有現有的測試不改內容、全部通過（`tests/` 148 個檔，D-181 第一步同樣的做法）；加卡型總表的範例檢查；L2 照 [quality.md](../../../../docs/agents/quality.md) 請 Codex 查。孩子看不到差別，不用另做 iPhone 實機，併進下一次發版本來就有的實機測試。
- **和其他串衝突**：同時在改 Cards 程式的還有多音字點選、考前抽測（0.7.0）、手機啟用第二步、API 製卡。第 1 段的分支開短、做完就合併；開工前問各串，避開正在改同一批檔的時候。
- **趕不上 0.7.0**：多音字不等這份。第 1 段先合併就直接寫成模組；沒合併就照現在的接點寫，第 1 段再一起搬（「做多音字點選題」串已知道）。
- **太大**：只集中認法是更小的做法，但它只解決互搶，加一種卡型照樣要找齊十處，題庫也接不上；差距明顯，不選它。

## 4. 題庫系統之後怎麼接

D-090 已定題庫做進 Cards、是獨立模組、題目寫在題庫筆記、和閃卡共用今天的份、排程、紀錄與學習目標 ID。這份要保證它之後接得上：

- **題庫筆記用同一張卡型總表**：題庫專用的卡型（選擇題、換數字的計算題）加在總表，只在題庫筆記認（卡型的 `read` 拿得到是哪一種筆記）。
- **作答流程不綁每天的複習**：`Flow` 已經同時給複習與預覽用（D-181 第 5 點），題庫的練習或模擬考是第三個用它的地方，判對錯與四級照舊、計分另算。
- **還沒決定、這次不碰的**：變式題從哪裡來（AI 換數字或家長從講義挑）、入口怎麼和閃卡放在一起、選擇題答對要不要算進排程（2026-10-14 的看法：選擇題練認出來，放進閃卡會讓排程高估，[題庫規畫](../plans/practice.md#題庫系統)）、考古題模擬考、自訂目標分數。題庫開工時再談。

## 5. 分段

| 段 | 做什麼 | 誰 | 驗收 |
|---|---|---|---|
| 1 | 卡型總表＋模組；`Target` 的卡型欄位併成一欄；接點外散落的卡型判斷改問模組。只搬不改，提示文字不動 | 這串 | 現有測試全過、不改內容；總表的範例檢查；L2 |
| 2 | 多音字、相似詞掛上 | 「做多音字點選題」串 | 照那串的任務說明 |
| 3 | 去格式統一成一處（技術債的觸發點） | 這串或另開 | 規格寫明接受哪些寫法、其餘怎麼處理；L2 |
| 之後 | 選擇題、其他新卡型 | 題庫開工時 | 照題型專區的七項定案 |

第 1 段的任務說明照 code-quality 寫，放 `apps/Cards/docs/tasks/`。

## 6. 這次不做

- **另加一行屬性指定題型**：§2-2。
- **家長在畫面上替一個目標換題型**：家長不改題目，防錯放在規則、程式與背景查核（使用者 2026-11-25）；要換就重新製卡或加深。
- **做成可以另外安裝的外掛式模組**：D-181 曾考慮、不做；卡型都由 Claude 寫，總表是 `const` 就夠。
- **新的作答方式**（選擇題、配對、是非）：等題庫；這次只保證接得上（§4）。

## 7. 要請使用者決定的

一次一題，前一題定了才問下一題：

1. **範圍**：先做題型模組，或現在就做題庫系統，或兩層一起規劃（2026-11-25 送出決定卡，💡 建議先做題型模組）。
2. （範圍定了才問）**第一批除了多音字、相似詞，還要掛哪些**：💡 建議社會的事件先後先用現有的全詩順序在試作場試一次，看要不要另做卡型；選擇題照 2026-10-14 留給題庫。
