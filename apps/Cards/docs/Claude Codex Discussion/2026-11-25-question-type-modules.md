# 題型模組：每個學習目標掛上一種題型

狀態：討論中｜下一步：使用者用決定卡選範圍（第一張選項寫錯，2026-11-25 收回重送）；範圍定了再問時程與掛法｜等誰：使用者

來自：使用者 2026-11-24～25 在專案討論串「製卡-國小國語」：「我們是否有把題型模組獨立抽出來管理，以後每一顆要用哪一種題型，例如還有排序等等，就可以直接掛上這個題型模組就好」「我要做題庫模組……規劃好也是先給 fable 5.2 xhigh 看過再動手」；[題型專區〈待決〉](../question-types.md#待決)

審查：使用者指定 Fable 5.2 xhigh 審這份規劃，不是 Codex（[quality.md](../../../../docs/agents/quality.md) 的角色表寫升級用 Fable 5.1 high，這次照使用者指定）。提案已成形、要找洞，照一輪一輪查（essence-discuss 第 7 點）。第一輪的原文與 Claude 的處理在文末；§0～§7 已照第一輪改寫（第 2 版）。

## 0. 這份要決定什麼

使用者要三件事：

1. 每個學習目標可以掛上一種題型（點選、排序、選擇……）。
2. 新題型做成模組，接上就能用，不用每次改一大片。
3. 以後的題庫系統（[D-090](../../../../docs/decisions.md#d-090-題庫併入-cards變式題以題型排程)）也用得到（使用者選多音字點選時說「以後會有題庫系統，用得到」，[D-230](../../../../docs/decisions.md#d-230-國語字義卡和詞義卡錯開混淆點第一次就比多音字改點選填空) 第 4 點）。

「題庫模組」在專案裡可能指兩件事：題型（作答方式，[D-181](../../../../docs/decisions.md#d-181-題型是可以接上的模組開題型專區)）與題庫系統（D-090，閃卡以外的第二種練習，排在第二階段；選擇題也放在那裡，[題庫規畫](../plans/practice.md#題庫系統) ③，使用者 2026-10-14 同意）。這份照 Claude 的建議寫「題型模組」：整理現有卡的程式結構，孩子看不到差別，選擇題照舊等題庫系統。題庫系統只寫之後怎麼接（§4）。範圍由使用者用決定卡選。

## 1. 現況

### 1-1 題型與卡型

題型專區的「題型」是作答方式：翻面自評、打字比對、點選填空。孩子看到的每一種卡（這份暫叫**卡型**，名稱要請使用者確認，§7）由名稱的結尾或題目的形狀認出來，再交給其中一個題型：

| 卡型 | 怎麼認 | 題型 | 只在 |
|---|---|---|---|
| 問答、填空 | 其他全部 | 翻面自評 | |
| 英翻中 | 結尾 `英翻中` | 翻面自評 | |
| 接句 | 結尾 `接句`，一題一格的填空 | 翻面自評 | |
| 中翻英 | 結尾 `中翻英` | 打字比對（配填空題時照翻面） | |
| 文法、變化 | 結尾 `文法`、`過去式` 等 | 打字比對（配填空題時照翻面） | 英文卡組 |
| 比較卡 | 名稱的括號讀得出組，結尾只當標題（D-182 第 4 點）；國語的 `相似詞` 也是 | 點選填空 | |
| 全詩順序 | 結尾 `排序`，一題兩格以上的填空 | 點選填空 | 英文要寫 `全詩` |
| 句子排序 | 結尾 `排序`、沒有 `全詩` | 點選填空 | 英文卡組 |
| 多音字（D-230，另一串在做） | 名稱的括號是讀音、字不在括號裡，結尾 `讀音`（那一串的提案） | 點選填空 | 國語 |

所以「掛上」已經有一半：卡型靠名稱的結尾掛（比較卡靠括號），家長與 AI 寫結尾就選了題型。題型要照每一題算，不是卡型的固定屬性：`go 中翻英` 底下的填空題照翻面出（`compose.ts:22`）。

### 1-2 每多一種卡型要改哪裡

D-181 抽出了四個接點（認、組卡、作答、畫面，[題型專區〈程式現況〉](../question-types.md#程式現況)），作答與畫面已經是一張表。但卡型的知識還散在接點外面：每一種卡型在 `Target` 上有自己的欄位，讀到它的檔（2026-11-25 的 `main`，Fable 逐檔核對，不算 `Card.group` 這類同名欄位）：

| `Target` 的欄位 | 卡型 | 讀到的檔 |
|---|---|---|
| `group` | 比較卡 | 12 |
| `order` | 全詩順序 | 7 |
| `typing` | 文法、變化 | 6 |
| `sentence` | 句子排序 | 5 |
| `couplet` | 接句 | 4 |

讀到任何一個卡型欄位的檔共 16 個：除了認與組卡，還有今天的份（`plan.ts`、`session.ts`）、練習（`practice.ts`）、預覽（`preview.ts`）、需要版本（`need.ts`、`move.ts`、`draft.ts`）、AI 製卡的草稿檢查與加題核對（`check.ts`、`existing.ts`）。

已經碰到的問題：

- **認法互相排除**：每個認法要先排除別的卡型（`readTyping` 先看讀不讀得出組，`readSentence` 要排除組與全詩，`readCouplet` 要排除全詩順序），每個認法也都先看方向；誰先誰後寫在 `parse.ts` 的呼叫順序裡。`排序` 已經有三種意思（全詩、英文句子、英文詩）。每加一種卡型，要逐一確認和舊的不會互搶，現在沒有測試把這件事釘住：`tests/question-types.test.ts` 只有三個題型各一例。
- **去格式各處自己寫**：[Cards backlog〈技術債〉](../backlog.md#技術債)「讀手寫文字的去格式各處自己寫」，觸發點是「下一次改題型或英文讀手寫文字的地方」，多音字就碰到了。
- **漏接一條路**：[英文打字與排序的 L2](2026-11-15-english-typed-order-review.md) R2 是 AI 製卡的候選框漏跑英文草稿的退件；現在 `check.ts` 仍是兩處各列一次檢查。

接下來確定要加的卡型只有多音字（相似詞現在就認成比較卡，只差結尾的提示）。題庫的選擇題、換數字的計算題在第二階段，找錯題在 v1 之後。

## 2. 提案：一種卡型在每一層各一列

### 2-1 兩層：題型與卡型

- **題型**（D-181 的定義不變）：孩子怎麼作答、誰判對錯、怎麼對到四級。現在三種，作答流程與畫面已經是 `FLOWS`、`PREVIEWS`、`SCREENS` 三張表。
- **卡型**：孩子看到的那一種卡。哪一題用哪個題型由卡型照每一題決定（§1-1）。
- 題型加卡型兩層和 D-187 第 8 點、D-192 的說法一致（全詩順序、句子排序是點選填空的一種）。

### 2-2 掛法不變：名稱的結尾

卡組的格式不改：卡型照舊靠名稱的結尾掛，比較卡照舊靠括號（D-182 第 4 點：結尾打錯也不會壞）。家長與 AI 寫的東西一樣，舊卡組不用動，舊版外掛讀得到的照舊讀得到（P1：寫進筆記的格式不能改壞）。這就是使用者「直接掛上」的答案，要請使用者確認（§7）。

不另加一行 `題型: …` 的屬性：多一種寫法要家長與 AI 學，還要和結尾說好誰優先，舊版外掛也讀不懂。

換卡型不換學習目標 ID：例如讀音卡改成多音字點選，名稱改字、ID 不變，紀錄照樣算進同一個目標；所有題型都落在四級，排程器不用知道換過。從「想得出來」換成「認得出來」，排程可能高估一段時間（題型專區〈點選填空〉已寫的風險）。舊裝置照 D-191 擋，由多音字那串處理。

### 2-3 程式的形狀（草稿，任務說明再定）

不開照卡型直切的資料夾：認法、組卡、AI 檢查分屬 `core/deck`、`core/study`、`core/ai`，D-110 的模組邊界（`eslint.config.js` 擋）不讓一個模組同時放這些。改成每一層各一張表，漏了編譯不過：

- **`Target.kind`**：`group`、`order`、`sentence`、`typing`、`couplet` 併成一欄帶標籤的聯集，`KindId` 型別放 `core/deck/types.ts`。`direction` 留在 `Target`（發布前比較的轉接器直接讀它，`tools/compare/adapter.ts`）。
- **每一層一張 `Record<KindId, …>`**（或 `switch` 加 `never`）：認（`core/deck`）、組卡與今天的份（`core/study`）、需要版本、AI 草稿檢查與加題核對（`core/ai`）。和 `FLOWS`、`SCREENS` 是同一種機械檢查，不動模組邊界。
- **`Card` 帶 `KindId`**：作答與畫面現在靠 `Card.group.order?.starts` 猜是哪一種（`review/pick.ts`、`ui/PickCard.tsx`、`ui/screens.tsx`），改成直接看。
- **認的先後原樣留著**：各認法的排除條件第一段不改，先後由分類表（§5 第 0 段）驗，不靠手排。
- **跨卡型的關係留在 `core/study`**，用 `KindId` 判斷：英翻中與中翻英配對、變化等英翻中記得、接句與全詩的先後。比較卡的併卡在四處各用不同的歷史，不硬併成一個通用函式。
- **需要版本不只看認得的目標**：`pick-answer-invalid` 也要標（`state/need.ts`、`core/ai/move.ts`），存檔提示的「比較卡」字樣也照卡型寫。

### 2-4 點選的選項從哪裡來

點選填空的各卡型差在選項從哪裡來，作答、判對錯、對到四級都一樣（`review/pick.ts` 只看每格的答案與字鍵）：

| 選項從哪裡來 | 卡型 | 一格對 |
|---|---|---|
| 組裡的其他目標 | 比較卡（相似字、比較、相似詞） | 一格一個目標 |
| 打散的每一格 | 全詩順序、句子排序 | 好幾格一個目標，取最差的一格 |
| 這個目標自己列的 | 多音字（讀音） | 好幾格一個目標 |

多音字那串提案把「選項屬於這個目標」做成 `Target.choice`，不塞進比較卡的組（組的身分是好幾個目標共用的，併卡、今天的份、需要版本都照它）；題庫的選擇題要「選項屬於題目」時，接到同一個 `choice`，紀錄的 `pick` 一樣寫選的那一項（兩串 2026-11-25 對齊）。選擇題是第四種題型還是點選的一種，等題庫開工再定。

### 2-5 AI 製卡

第 1 段不動送給 AI 的提示。卡型的格式說明放在提示的哪一層，等「AI 提示詞架構」串的比較測試（[D-228](../../../../docs/decisions.md#d-228-製卡規則重整成核心任務模組科目模組先用比較測試判斷)）有結果再說。家長的勾選照舊只有點選填空，不加新的勾選。

**優勢（照實寫）**：v1 內確定的新卡型只有多音字，所以好處主要在之後：題庫的選擇題與計算題、找錯題，以及每次加卡型時漏接的那幾處直接編譯不過。過去的 L2 證據裡，第 1 段只擋得到「漏接一條路」那一類（英文 R2）；朗讀與提示的認法不同（R4）、去格式（R6）不在這一段。

**代價與解法**：

- **搬壞**：照 D-181 第一步的做法驗收（§5 第 1 段）：行為測試逐檔列出、`git diff` 為空；讀卡型欄位的 11 個測試檔與 `boundaries.test.ts` 只准機械地改存取式；新舊版本的差分腳本，加新舊 `parseDeck` 的卡型對照；`npm run compare-versions` 對兩個正式 vault 的備份零差異。L2 照 quality.md 在本機請 Codex 查。
- **孩子正在用**：國二的孩子 12/2 起算數字、2027-01-19 段考，0.7.0 在 01-11 前裝（[提早試用計畫](../plans/early-trial.md)），小五的 vault 也在用。D-181 當時「正式 vault 還沒有卡組，現在搬最便宜」的前提不在了。第 1 段碰到排程的檔、孩子看不到好處，💡 建議等 0.7.0 定版後才開分支、進下一版（§7）。
- **和其他串衝突**：多音字點選、考前抽測（0.7.0，還沒有任務說明）、手機啟用第二步、API 製卡、製卡品質測試工具、AI 提示詞架構都在動 Cards。第 1 段在 0.7.0 之後做，開工前問各串。
- **多音字不等這份**：照現在的接點寫，第 1 段再一起搬（「做多音字點選題」串已知道）。

## 4. 題庫系統之後怎麼接

D-090 已定題庫做進 Cards、是獨立模組、題目寫在題庫筆記、和閃卡共用今天的份、排程、紀錄與學習目標 ID；題庫筆記的格式還沒定（[syntax §7](../syntax.md#7-之後才定的格式)）。第 1 段沒有擋住它：

- 💡 提案：題庫專用的卡型（選擇題、換數字的計算題）加成新的 `KindId`，只在題庫筆記認（認的時候拿得到是哪一種筆記）。
- `Flow` 已經同時給複習與預覽用，題庫的練習或模擬考是第三個用它的地方。
- 還沒決定、這次不碰：變式題從哪裡來、入口怎麼和閃卡放在一起、選擇題答對要不要算進排程、考古題模擬考、自訂目標分數。

## 6. 這次不做

- **另加一行屬性指定題型**：§2-2。
- **家長在畫面上替一個目標換題型**：家長不改題目，防錯放在規則、程式與背景查核（使用者 2026-11-25）；要換就重新製卡或加深。
- **照卡型直切的資料夾、可以另外安裝的模組**：§2-3；D-181 也不做可安裝的模組。
- **新的作答方式**（選擇題、配對、是非）：等題庫；這次只保證接得上（§4）。
- **社會的事件先後另做卡型**：社會卡組的 `排序` 配多格填空現在就認成全詩順序（Fable 實測），先記進 backlog、到試作場試。

## 7. 要請使用者決定的

一次一題，前一題定了才問下一題：

1. **範圍**：整理題型的程式結構，或現在就做題庫系統，或兩層一起規劃（💡 整理結構）。第一張決定卡的第一個選項寫成「選擇、排序等題型做成可掛上的模組，在每天複習裡出」，和這份不符（Fable F6），2026-11-25 收回重送。
2. **時程**：第 1 段在 0.7.0 之前或之後（💡 之後；現在只做第 0 段）。
3. **掛法與名稱**：掛法用名稱的結尾、不加屬性；孩子看到的那一種卡叫什麼（暫叫卡型；使用者的說法裡「排序」是一種題型，這份把它歸成點選填空的一種卡型）。
4. **去格式的觸發點**：多音字串不新寫去格式，只用現有的 `pickKey`、`unbold`、`countBlanks`，建議把觸發點改成第 1 段（同一批檔一次搬完）；這題由多音字串回報使用者時一起問（D-195），這串不重複問。
